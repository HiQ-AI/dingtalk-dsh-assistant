# 钉钉授权回复实时生效验收计划

## 症状

授权或人工处置申请已经发送到钉钉本人会话，用户引用申请消息回复后，Task 仍停留在 `waiting`；稍后从 Web 操作才会恢复。

## 根因

1. DWS bridge 只建立群消息实时订阅，个人审批回复仅靠历史消息轮询；当前 DWS 历史读取对最近本人会话消息不可见，因此回复没有进入 Runtime。
2. 非 `redline` 人工处置即使被历史轮询命中，bridge 也没有传递 `decision`，而 Runtime 要求所有人工阻塞恢复都携带决定，最终抛出 `authorization_decision_required`。

## 修复

- 为本人私聊增加独立的 `all-direct` 实时消息订阅。
- 仅按引用的申请 `messageId` 精确关联当前等待中的 Task；红线操作仍只接受明确的“批准/拒绝”，普通人工处置把具体回复作为处置结果并传递 `approved`。
- 个人订阅独立维护 ready、异常、指数退避重连和停止生命周期，并纳入 bridge 健康状态。
- 保留历史轮询作为离线窗口恢复路径，同时修正非红线决定缺失。

## 验证分层

- 单元层：命令编译、ready 门禁、精确引用、红线语义、普通处置、幂等和重连。
- 回归层：全量测试和关键竞态重复运行。
- 产物层：打包后检查修复文件存在并与源码绑定。
- 运行态：本地安装并重启后回读 `/health` 和 `/state/dws-bridge`。
- 业务 E2E：创建一条可控申请，在钉钉本人会话引用回复并确认原 Task 恢复。没有真实申请时保持未验证，不用 listener ready 代替。
