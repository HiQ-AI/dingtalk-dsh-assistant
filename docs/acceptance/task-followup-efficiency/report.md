## 交付行为

1. 等待实施确认时，相关事实追问可以直接引用回复并原生提及作者；内部证据不外发，原确认申请保持待答，旧执行不续办。通知与处理记录原子保存。积压多条时未答来源继续处理，已答来源不重发，无关来源不空转。
2. DSH 原生任务/执行会话跟踪成功 skill/read 的相关版本。入口变化、引用变化、同会话续办、旧会话无版本记录、同名替换、根目录改变、观察故障和结果未落盘前崩溃均有检查。普通二十个模型步骤不会重复加载技能正文；此断言是调用次数证明，不是线上耗时测量。
3. 实际 business-development 的三个既有文件补上阶段按需重读、低成本检查与夹具/页面初始化冒烟、失败分类及里程碑收尾。三文件 SHA 已独立回读；两个脚本未改，未新增 skill。四场景独立评估见 skill-update/independent-behavior-review.md。
4. 统筹指引要求跨关联任务区分已实施/仅方案/未实施，并在验收完成后按精确剩余动作收尾，不用重复总结代替交付。
