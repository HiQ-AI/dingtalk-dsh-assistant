# 资源、恢复与统筹效率改进

2026-10-28。三类改进已完成实现与定向验证，四个现有个人 skill 和公共脚本已在实际安装位置更新。插件源码通过隔离原生集成及打包运行核验；本轮没有合并、部署插件或安装正式资源目录。

## 结果

- 资源以受信目录中的标准键及别名统一识别。准备阶段不能取得已登记发布资源；沿原执行排空后再切换发布阶段并联合取得实际所需资源。旧锁、多个旧别名持有者、旧幂等摘要和未知效果保留，不用改账或抢锁升级。
- 恢复探针由 Host 重建并直接传递权威命令，模型不再复制长脚本；末尾 LF、精确摘要、原身份、原生权限与作业终态继续核验。原子执行结果和后置策略结论分别保存，后置拒绝不会被读成成功，也不会导致原证据丢失。
- Registry 公共脚本先核对原始字节摘要，再解析 manifest/index；现有 UAT helper 按严格版本语义比较整数和规范字符串。统筹对不必要资源占用和无缺口的材料空转主动纠偏，必要验证及未结效果仍保留；每轮判断通过原决定记录保存。
- 更新现有 `uat-pr`、`business-development`、`uat-deployment`、`baibu-uat-account-verify`，没有新建 skill。安装补丁、完整新脚本、摘要和回放配方见 `acceptance-helpers/verification.md`。

## 独立审查及修订

资源独立审查发现旧无阶段回执重试可能冲突，随后补旧请求原字段摘要校验；主会话发现已终态但未排空的旧别名冲突持有者可能误报 released，现保持 waiting/holder/blocking。对应反例均进入存储测试。

恢复独立审查先实跑 22 项，再额外复现 P2：正常 producer 被后置策略拦截时，最终内容与操作账摘要不同。修前失败保留在 `recovery-policy-block-before.log`。修复后同一审阅者独立重跑原反例，确认原账摘要不变、原身份可读回、最终策略仍失败、隔离证明拒绝；另独立运行 61 项通过。主会话随后对最终源码重跑六文件 106 项及包运行 2 项，全部通过。当前受支持路径未发现剩余阻断。

## 生效及边界

个人 skill/公共脚本已安装；通用插件仍待 PR 合并和另行部署，正式资源目录尚未写入。目录示例及安装/升级/降级限制见 `docs/ops/task-session-clean-start.md` 的资源章节。仅更新 skill 不会给旧 Host 增加目录或探针工具。

资源互斥只覆盖同一控制库内已声明的资源，不推断任意 shell 副作用，不代替跨实例平台控制。公共探针本轮验证直接原生调用，未扩展 PTC 模式；真实旧操作的正式人工审计及 noReplay 保持。隔离验证不代表历史任务已修复、真实 UAT 已部署或今后模型判断必然正确。
