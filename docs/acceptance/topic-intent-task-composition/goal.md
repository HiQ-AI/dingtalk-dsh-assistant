## 总目标

修复话题续办与通知恢复；在既有固定节点和效果账上接入 UAT 交付、生产发布、数据变更、UAT 同提交重建的受信平台适配器，并部署本地验证。四次撤回与两次补发的现场对账及既有任务事实必须保留。

## 完成条件

- 同话题后续消息读取关联任务、结果与通知，补充需求在原 Task 续办，授权与执行目标分别核验。
- 承接与结果是不同事件；重复恢复无重复发送；撤回/补发逐条预检、持久留痕、幂等回读。
- Run 成功与业务目标满足程度分别展示，不因结果有限误判任务没执行。
- 现场六条消息对账后无新增外部发送或任务执行，原任务与产物仍在。
- 测试、隔离重演、本地包哈希、启动与只读业务状态回查完成；验收矩阵如实记录未通过项。
- 四类流程在配置齐备时显示可发起；真实目标、审批、平台效果和独立回读均由 Host 守卫，缺条件时精确阻塞。

## 范围与约束

- 不重播 #51/#52 真实消息，不因验收而发信或撤回；现场修复只做已发生事实的对账。
- 先读源码与运行数据再改；破坏性脚本先 `--check`；按 `docs/ops/` 部署。
- 仓库非源码产物保留在现有 `docs/` 子目录；Draft PR #122 为当前交付分支。
