## 输入和执行边界

- 从原审计记录定位 91 条真实 `GROUP_TOPIC_ROUTE` 日志，逐条核对原内容指纹。按解析后 `envelope.messages` 确定批次；嵌套引用 ID 不算额外待路由消息。
- 当前真实存储哈希与原审计快照不同，且有 16 个批内消息实例的版本与历史日志不同；本次仅比较同一当前副本的新旧生成器，不能声称完整复现 21:44 的状态。
- 旧生成器使用固定基线 `fd8fa1537b42a261965439108baae5700bb4bb78`；加载时只重定位 import，依赖取同一工作区。最终新生成器 SHA-256 为 `b3cdf5cc572d51883202e3ecb7c2a853a1723a222f0b6417f7c1a3775ed10cb6`，结束时再次核对未在运行中改变。
- 使用既有 `group_topic_route_review`、目录分页和原文分页工具，不修改产品 API。Agent 为内存捕获器，模型不运行，业务动作/Outbox/取消执行入口均拒绝执行；结束时独立核对 Task 与 Group 业务状态哈希未变化。
- 原始存储与日志只读。产物仅含匿名计数、尺寸及哈希，不含消息正文、群/人员/任务身份或业务路径清单。

首次 6000 字符实验的完整 content P50 比 12,000 字节目标高 405 字节，保留于 [route-projection-budget-6000.json](route-projection-budget-6000.json)，未删除未达标样本。随后只把路由首包目录预算从 6000 调为 5000 字符；完整 content P50/P95 为 11,021/13,748 字节，低于 12,000/24,000 字节实验目标。两轮样本指纹、旧生成器尺寸及关系校验数量相同，各轮新旧生成器共享当轮捕获副本；两轮存储哈希不同，因此没有声称跨轮读取的是完全相同的历史状态。

这一调节把首包目录从 55 项降为 45 项；本固定样本中总目录仍为 79 项，均需首包后再读 1 页，91 批实际目录续页次数仍为 91。减少首包不代表免费减少必要阅读；若模型需要完整目录，仍需支付续页调用及读取成本。字节目标通过不能代替 token、费用或端到端响应验收。

## 结构断言

- 最终 91/91 批次均能从首包 45 项继续分页，完整恢复同序 79 项目录；共实际读取 91 个目录续页，无遗漏或重复。
- 66 批带消息引用；按当前消息、引用消息及关联 Task 的 Topic 关系检查，共验证 140 次关联 Topic、111 次关联 Task，无关联丢失。
- 101 个批内消息实例通过连续原文读取与当前副本逐字相等断言，覆盖全部 81 个唯一消息 ID。
- 本固定样本关联目录未超首包预算，没有触发关联目录续页；该分支仅由定向合成测试覆盖，不能冒称真实样本覆盖。
- 没有执行路由提交、任务操作或渠道发送，未生成新的人工语义真值。

完整脱敏数字与输入/代码哈希见 [route-projection-summary.json](route-projection-summary.json)。

## 复跑

从仓库根运行，显式传入三个本地只读数据入口。脚本不内置业务源目录；每次只捕获一次存储，再供新旧生成器共享。若传入持续变化的运行存储，跨次运行哈希可能变化；要精确复核某次结果，使用该次匹配哈希的私有快照。

```powershell
node docs/acceptance/performance-flow-optimization/scripts/route-projection-replay.mjs `
  --audit-metrics '<原审计 metrics.json 的绝对路径>' `
  --state '<只读存储快照的绝对路径>' `
  --session-root '<原生日志会话根目录的绝对路径>'
```

可用 `--output` 指定脱敏 JSON 产物路径；默认写入本目录。脚本失败只输出检查码，不打印业务内容或数据路径。
