# 统筹纠偏与决定留存

本轮用户进一步明确：每次决定和说明均须保留。运行时必须保留原人工等待语义，同时让统筹首次发现方向偏离即主动纠正。

## 决定留存方案

复用现有 dynamic_receipts：每次成功的 task.wait、task.complete、task.dialogue.reply 在同一事务追加 taskDecision，保留完整决定、原统筹会话/版本、时间和已认领唤醒的执行身份。收据主键提供幂等性，不能原地改写历史；不在 task 中堆历史数组，不另建存储表。查询使用任务 ID 部分索引和收据 rowid 游标，按新到旧有界分页，新增决定不改变下一页边界。

增加当前任务限定的 task_decisions_read 和只读 HTTP 入口；仅按需读取历史。旧记录仍保留原日志和收据，但没有新结构的历史不猜测重建。此次新增索引在取得唯一 Host 所有权后创建，失败回滚；部署前仍须原生排空。

## 用例

1. 首次偏离整体目标/受托范围，主动反馈原执行；正常必要验证不反馈。
2. 有限日志/无输出时保留盲点；已消费反馈后仍偏离时根据新证据纠正；待消费的同一反馈不重发。
3. 连续决定分别留存；同请求重试只一条，异内容同 ID 拒绝；完成、人工介入、对话回复均保留。
4. 重启后历史原字节语义不变；按任务隔离；分页期间新增决定不重复/漏掉旧页；非法游标/页长拒绝。
5. 原人工等待/暂停、反馈持久投递与安全步骤、原执行身份保持。

确定性原生测试证明机制；隔离真实模型场景核查判断内容，不能据少量样本保证真实业务中每次正确。未安装时不声称当前运行实例已生效。
