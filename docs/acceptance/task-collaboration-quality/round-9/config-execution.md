## 已核对的访问方式

- 控制 API 为 `http://127.0.0.1:18998`，配置只读入口为 `GET /state/agent-config`，任务为 `GET /state/tasks` 及现有任务详情。依据 Assistant `client.js:5,43`、`http.js:402`；验收仅记录 executionBackend、计数和检查结论，不打印全部配置或业务正文。
- 宿主 Web 为 `http://127.0.0.1:3080`。复用 `scripts/deployment-integrity.mjs:273–290` 的认证方式：从明确指定的本次启动日志在内存提取本机 token URL，通过正式 303 交换得到 cookie，再读正式页面。token、cookie、启动日志原文不打印、不写验收产物。
- 既有 `docs/acceptance/task-current-steps/scripts/verify-live-browser.mjs` 提供真实宿主浏览器与非 GET 拦截模式。新验收沿用只读边界，浏览器只做页面导航与读取；不点击保存、创建、取消、归档或会话激活入口。
- round-7 的 `scripts/execution-backend-browser.mjs` 使用隔离 API fixture 且包含保存/失败重试，不能直接运行到生产实例。本轮真实页面不注入配置、任务或 CLI 样本，不以 R7 夹具替代部署后证据。
- 现有设置入口为宿主插件配置中的“钉钉个人助理”，复用 Agent 配置表单；无需新设置页或自制终端。
