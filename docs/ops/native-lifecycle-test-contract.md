# 原生集成测试计时合同

真实 Host 生命周期测试使用 `test/fixtures/native-lifecycle.js`，分为准备、业务、清理。准备最多 30 秒，仅建立空 Host、临时目录和静态配置；显式 `await t.beginBusiness()` 后运行原任务推进与验收。业务保留各例各例原业务门限（包括长生命周期 240 秒及条件表达式），不把重启、恢复、重试、包构建或断言挪入准备。清理最多 10 秒。外层总上限为业务预算加 40 秒，三个阶段分别失败，不能互借预算。

覆盖映射见 `test/native-lifecycle-coverage.json`：44 文件内 250 个原静态注册，200 个迁移、6 个已有阶段化回调保持不变、44 个纯单元或 SQLite 回调保持不变。循环展开和一个真实嵌套注册另计；嵌套阶段仍受父业务总预算约束。6 个原无门限 Host 注册新增 30 秒业务上限，映射中明确标记 `newConstraint`，不是原门限。原有 3157 个断言保持；另增真实构造取消回归。

异步业务操作以 `await t.step(async () => operation())` 包裹，取消后不继续下一步。仅原有零参 Deferred 解锁可注册 `t.onCancel`；原 after FIFO 和关键业务 finally 保留。失败时先解锁、关闭已拥有资源、等待构造与底层操作排空，再运行原清理；无法证明排空时保留目录和错误，不能删除仍在使用的数据。只有适配器自己创建并验证归属的临时目录可自动移除；无生命周期上下文时 mkdtemp 严格委托原 API。

共享 Host 在构造早期注册幂等关闭，取消晚到的 service/store 也必须关闭一次。外层取消不跳过独立有界清理。准备、业务、清理超时、预先取消、并行隔离、嵌套取消、构造中取消以及清理错误均由 `test/native-maintenance-backup.test.js` 和真实 Host 构造回归验证；打包和嵌套身份代表用例继续使用原业务断言。

迁移审计：在含基准提交历史的完整仓库运行 `node scripts/check-native-lifecycle-migration.mjs`，比较原注册顺序、断言 AST、原有阶段化和排除回调、业务预算及唯一阶段边界。该审计固定于本次迁移基准，不替代运行时测试；后续有意修改被审计用例时应同步审查映射与基准。运行 `node scripts/test-suites.mjs check` 验证套件分组，再以正式 Windows CI/Release 运行全部分组。

本次是经批准的测试计时标准变更，不声称已证明或修复历史随机超时的产品根因。业务阶段自身超时仍是失败，不能进一步扩大业务预算放行。

## 清理诊断和迟到操作

手动 CI 的固定 `scope=native-1` 只运行原 native-1 组，沿用正式 Windows 环境；`all/history` 和 Release 六组门禁不变。该诊断入口输出共享 Host 的 service、可观测的 flush/store、resident store、fiber 和目录删除阶段；冻结/私有内部操作仍包含在父 close 阶段，不能据日志冒称内部阶段已单独验证。

清理 10 秒超时仍失败，输出当时未完成操作及耗时。不声称 JavaScript Promise 被强制中止：迟到关闭可继续排空并记录迟到结果，但超时或清理失败后，受管临时目录的后续 rm 会被拒绝，保留现场。已经在超时前合法开始的删除不能取消，日志会如实显示该在途操作；不会因此标记清理成功。未受管路径及业务阶段的 rm 保持原委托语义。测试覆盖迟到关闭完成后仍不误删、正常 FIFO/关闭/删除，以及方法装饰恢复。
