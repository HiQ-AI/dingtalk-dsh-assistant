# 运行看板设计约定

## 使用场景

中文本地运营工具，用户查看群消息为何被拆分、关联、执行或阻塞。重点是业务结论可直接阅读，不向页面传输或渲染完整技术数据。

## 视觉来源

采用运行时 token 为权威：DSH CSS 变量 → observer 的 colors/ui → 共享 Button、Pill、card/readout。surface #fff、surface2 #f7f7f8、border rgba(127,127,127,.25)、accent #4d6bfe、warning #a56500、danger #c33 均只是主题变量的原有回退值，不新增独立色板。继承宿主字体，标题 16px、正文 14px、辅助 12px；消息处理页面不展示技术 ID 与 JSON。

## 消息处理详情

原文与当前状态在前，实际步骤按时间顺序展示，每步先结论再依据。中文状态和文本同时表达结果，不仅依赖颜色。记录序号不是全局流程拓扑；多事项分别列出，关联话题和意图批次保留归属提示。模型建议、Host 接纳、业务执行及通知送达不得混称完成。

## 行为与组件所有权

收信箱沿用现有表格与宿主状态标签。材料等待分别显示“正在读取材料”“等待用户补充”“材料读取受阻”；范围等待显示“核对相关输入”。消息行末以原生 details/summary 展开“等待与通知”，可用键盘操作，显示责任人、恢复条件、实际相关来源及各条通知事实。ACK 仅表示发送已确认，送达必须独立回读；空通知列表写“尚无通知记录”。展开正文自然换行，不增加新的滚动容器或色板。

- 导航与操作使用宿主 Button，返回沿用原列表状态；读取错误在本区重试。
- 分页沿用接口游标，本页阶段计数不冒充完整历史。刷新保留当前页，旧请求不能覆盖新页。
- 消息处理过程只展示业务摘要，不创建技术详情或原始 JSON 节点；其他页面已有折叠沿用原生 details/summary。
- 滚动由宿主页面管理；JSON 自身限高滚动，详情正文自然换行；不改变全局滚动容器。
- 仅适用只读界面；无表单、选择器、删除或权限变更。本次不引入新的状态转换或授权规则。

连续消息以共享判断批次呈现来源与各事项，当前来源高亮、其他来源可切换查看。每步显示本次 startedAt/completedAt 对应耗时；缺失时间不显示零，重试注明轮次，共享判断不重复计时。

## 任务详情

卡片和详情共用最多32字符的简短标题，原文保留title提示，详情以原生details/summary展开完整任务目标。顶部显示中文状态、标题、更新时间与真实步骤完成数，通栏细进度条只表示步骤完成比例。主体采用 28px 编号圆点与连续细线组成的紧凑时间线；标题、文字状态在左，耗时在同一行最右，业务产出紧随其下。桌面产出按标签/正文对齐，窄屏自然换行，耗时始终靠右。步骤编号始终保留，当前步骤加重圆环；完成、等待、失败均以文字和状态色表达。步骤按真实工作流阶段分组，组标题显示中文名称与步骤数，保留全局编号；每步显示本次真实开始时间（浏览器本地时间、精确到秒）与耗时，未开始或缺失记录分别标注，不借用任务创建时间。卡片展开列表复用同一中文节点名称表与本次节点时间，Legacy阶段仍沿用已有检查点记录。目标置于步骤之前，当前结果置于步骤之后；不展示技术 ID 或原始 JSON，只展示当前计划的完整有效步骤，不提供历史执行切换；会话入口绑定当前有效步骤。

编号步骤显示当前执行轮次耗时：运行中每秒更新“已用时”，提交后固定显示“耗时”；等待步骤显示“本次执行耗时”，不累计后续等待。未开始显示“尚未开始”，缺失或倒置时间显示“耗时未记录”，重试显示轮次。使用辅助文字与等宽数字，复用步骤接口字段，不读取独立诊断接口。

任务详情顶部步骤摘要的右侧显示总耗时：从任务创建到当前时间，已结束任务截止到终态记录更新时间；包含排队、等待和重试，不累加并行步骤。未结束时每秒更新，结束后停止计时。缺失或倒置时间显示“总耗时未记录”；复用现有任务字段和步骤时长格式，无额外接口请求。

步骤产出进入任务详情才读取，默认展示首段，长文通过“继续阅读产出”分页。摘要、发现、限制分段，读取失败就地重试；不展示原始 JSON。按明确的产出字段补充材料正文、文件清单、文件变更及已持久化检查结果；不展开任意工具参数、读取文件的完整代码和日志；修改方案本身的代码属于业务产出，按页展示。校验节点若返回原结果，照实展示原结果，不捏造独立的校验报告。

新工程任务采用交付物契约 v9：确认项目与修改起点、创建独立 Git 工作目录、编写修改方案、检查修改方案、按方案修改文件、构建与检查修改结果。方案节点持久化可下载的 `修改方案.md` 文档工件和可应用补丁；应用前检查文档非空、长度和变更文件覆盖，这不等于证明方案技术正确。工作目录回执包含实际位置和来源仓库，当前使用独立 Git 仓库而非 git worktree。检查报告明确打包、构建、测试及跳过测试的范围，不把命令成功当成业务验收通过。历史节点保留原定义；未保存方案说明时仅提供由实际补丁整理的 `修改记录.md`，不补造理由或重跑任务。

节点产出统一核对当前分析/工程链：只读分页附带 overview，文件数量依据完整工件去重；默认显示读取、修改、索引或方案涉及数量，展开后才渲染正文与清单。提交/推送准备、执行回执、PR 草稿/创建/回读分别呈现，不相互冒充。未知结构标明“已保存节点产出，暂未提供可读展示”。

方案编写及方案检查节点只显示实际方案工件路径，不展示正文、文件数量、展开或下载入口。当前文档与补丁持久化在 JSON 工件中，因此显示真实 JSON 路径，不虚构独立 Markdown 文件路径；其余节点保持原展示。

新工程流程 v10 将“构建检查”和“业务验收”拆成两个节点。构建成功只允许进入业务验收；缺少受信验收用例、没有实际值或实际与预期不符时，业务验收保持等待，阻止后续提交，不自动循环重试。验收通过展示验收项、预期、实际和结论。既有 v1–v9 记录保持原定义，不补造历史业务验收节点；v10 用于新任务与受管重发。部署仍需双包更新、备份及独立回读，无 schema 迁移。

顶部并列显示总执行时长和总耗时。总执行时长来自服务端任务全阶段、历史代次及重试的节点执行区间并集，排除排队和等待，不含消息判断与任务负责会话；执行时更新、等待时冻结。缺失结束证据显示记录不完整，不把缺失部分当作零耗时。只传汇总字段，不加载历史明细。

任务及步骤时长满 60 分钟后统一显示小时、分钟和秒，例如 1 小时 2 分 3 秒；不足 60 分钟沿用原格式。

## 本地验收节点产出

工程 v11 沿用编号步骤及右侧耗时，不新增页面布局。核对条件节点显示本次任务验收条件；方案节点显示用例数量、操作步骤与预期，不展示执行参数。环境节点显示独立目录、明确的 UAT 环境、共享 UAT 数据库及任务数据标识，不显示连接凭据。

执行节点默认展示通过状态与验收项数量，展开后显示服务生命周期各阶段的状态、耗时，每项业务操作的预期、实际、结论，以及任务数据清理和进程停止结果；报告可下载为 `本地验收报告.md`。阶段耗时满 60 分钟换算小时。执行节点完成表示回执已保存，验收是否通过由报告及后续“核对验收与清理结果”节点共同体现。核对节点只有业务通过且清理确认后才允许提交。

缺少环境配置、验收条件、方案覆盖不完整、执行中断待核对、业务未通过、清理未确认、回执不匹配分别使用可理解的等待原因。不得将构建通过、执行节点完成或服务就绪表述为业务验收通过。


## 消息 Agent 查询与答复

消息处理详情在判断和接纳后显示独立“查询与答复”步骤，复用现有编号序列、主题 token 和宿主 Button，耗时在步骤标题右侧。执行状态分别显示处理中、待补充、查询受阻、待恢复、已取消；“答复已生成”不表示已经送达。普通问答仍不进入任务看板。

轨迹列表只返回 240 字答复摘要、依据数量、真实绑定会话及产出引用，不读取工件正文或工具日志。点击“查看答复与依据”后通过现有 evidence API 按页获取正文，依据逐条再次点击才读取。读取包含加载、错误重试、分页与过时请求丢弃；读取失败不影响其他步骤。会话跳转仅在 sessionBound 为真时出现。输出及依据只能从本消息已接纳引用读取，禁止以任意工件路径访问。

此文件继续作为本项目 DESIGN/UX 约定的维护入口；依据用户项目产物归档规范，不在仓库根重复建立设计文档。页面原有宿主全局滚动与导航保持其所属组件的约定。

### 调查补充输入

任务详情与消息处理步骤共用行内补充表单，显示 Host 提供的问题，仅 `canAnswer` 为真时允许提交。调用既有工作流补充入口，原生调查使用真实 execution runId。空输入就地提示，提交期间禁用，失败保留内容；相同内容重试保持 eventId，成功刷新处理状态。权限仍由服务端复核。


### 当前完整步骤与结果

任务卡片沿用现有显示，任务详情以当前完整计划为目录，按阶段顺序显示所有有效步骤。重执行原位更新，计划删除的步骤移除，新增步骤按当前顺序加入，有效前段保留；服务端负责结果有效性和归属，客户端不按标题合并。旧任务链接及归档入口读取当前详情别名，详情不提供执行次数或历史切换。

既有编号、状态、耗时、步骤正文、分页、工件及当前节点会话入口保持现有样式。相同名称的不同阶段步骤以稳定 stepKey 各自保留，阶段归属显示在步骤下方；结果中的 HTTP/HTTPS 地址提供可点击链接，已有 Markdown 描述链接保留描述，其他协议保持文字，新窗口链接使用 noopener/noreferrer。

尚未绑定工作流定义的阶段显示“该阶段步骤待确定”。即使计划尚无节点，也显示“步骤待确定”；未来已绑定的节点显示未开始。待确定阶段不计完成，也不能显示 100%。总执行时长注明累计业务步骤执行口径，包含重试；总耗时注明从任务创建至终态或当前时间，包含排队、等待与重试。步骤耗时仍表示该步当前执行。

正文及文档下载绑定 detailRevision，版本变化取消旧请求并以新版本读取未完成页，拒绝旧响应。不可变产物引用未变时保留已读正文、展开状态和分页位置；当前节点或产物引用改变时重置正文。详情刷新失败保留已有内容并明确提示尚未刷新，错误在本区重试；请求失败不能解释为步骤删除。底层执行记录继续支持恢复和排错，不参与任务详情展示。

当前正在阅读的步骤以键盘焦点优先、视口内步骤次之识别；步骤移除后用 aria-live 简短提示，并将焦点移到原位置相邻步骤。目录变空时聚焦执行步骤标题。未移除步骤保持阅读位置。群聊文件交付阶段依次显示“核对待交付文件”“发送群文件”“回读并核验文件”，卡片与详情使用相同名称。

Web重新执行的任务卡片从可读取关联任务的sourceGroupId解析原群名，悬浮注明Web重新执行；没有可用群来源显示Web任务。groupId仍表示本次实际执行来源，不用于代替通知或授权来源。

卡片话题引用包含groupId/topicId/revision/title，使用真实绑定及当前话题版本；Web重执行沿可读取关联链继承原话题。点击、Enter/Space导航及话题页关联任务查询均按话题群ID，禁止用Web执行来源代替。无绑定不猜测话题。

看板整体刷新采用单一进行中请求，自动与手动刷新共享，不重叠请求；失败保留既有数据且下一次可重试。群消息工具栏“打开群常驻会话”绑定Host当前协调会话ID，不使用旧常驻目录会话或任务叶子会话。按钮复用宿主Button，打开状态禁重复激活，打开后使用宿主会话页核验目录、权限和完整群名。
