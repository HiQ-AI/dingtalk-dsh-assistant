# 任务详情对话

任务详情“对话”复用原统筹会话及任务队列，不提供任务新建、目标修订或取消。普通进度询问由统筹根据现有记录回复；方向纠偏只有在既有 preserve 语义成立时定向投递原执行的 `task_delegate(..., feedback:true)`。不建立新的分类器，不按关键词分流；明确目标、授权或验收变化由统筹说明边界并澄清，不静默 replan。普通聊天不是人工介入答复。

## HTTP

- `POST /tasks/:taskId/dialogue`：可信本机 Web 请求，strict body `{ requestId, text }`；requestId 非空且不超过 200 字符，正文非空且不超过 10000 字符。作者来自 Host 的 webActorId，禁止客户端覆盖。返回 202 和持久消息 `{ id, text, actorId, receivedAt, reply, repliedAt? }`；不等待模型回复。
- `GET /state/tasks/:taskId/dialogue`：同一可信本机请求校验，返回 `{ taskId, sessionId, messages, writable, error }`。`reply:null` 表示已保存待处理，不代表进入模型步骤；error 是当前统筹技术错误码，不抹去消息。
- 同任务同 requestId 同正文不重复写入；同身份不同正文冲突。终态、暂停、归档不接受新消息；原请求已保存后的重试仍可回读。历史任务无写入口。不提供恢复或新建接口。

## 持久化与受管处理

消息和单条 `task.dialogue` wake 原子保存，复用既有任务 JSON 记录，无新表或 schema 迁移。原统筹正在运行时消息排队，不取消该轮、不启动第二运行者；排空后按原 sessionId 与新 lease 继续处理。每轮只领取一条对话 wake，普通执行唤醒仍留在原队列；本轮输入包含原任务、当前执行证据、本条消息及最近 20 条已回复历史，完整记录仍在原任务账本和模型内容目录。未处理对话阻止旧结论完成任务，但不自动反馈到所有执行。

对话轮仅允许读取任务证据、定向反馈原执行、用既有 `task_session_submit(wait, summary)` 回复。服务端拒绝新派/续办、取消和 complete/blocked；回复与该 wake 的确认原子提交，不改任务结果、需求版本或人工等待。崩溃后未回复消息沿原队列恢复，已回复不重新处理；原累计计时及执行 lease 不因询问进度而改变。

现有反馈仍在原执行下一安全模型步骤消费，不中断正在运行的工具；已产生的外部效果不会被聊天撤销。模型澄清/理解质量仍取决于实际模型，落账接收和消费证据不替代业务验证。

前端轮询仅在面板打开时运行，卸载/切任务取消旧读取；收起保留草稿和失败重试身份。GET 与 POST 竞争采用按消息 id 合并且不回退已有回复。Web 新建任务入口继续保持移除。
