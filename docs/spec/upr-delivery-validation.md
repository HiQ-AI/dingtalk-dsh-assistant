# UPR 交付复盘改进

## 目标与当前证据

复盘发现统筹在交付末期主动把审核分派性能治理作为阻塞项；导入导出的组合边界晚于单模块测试发现；部署观察器混淆 manifest/config 摘要并误拒正常空 CSS。现有业务 skill 已有范围约束，PR #283 已合入资源与恢复优化，不重复实现。

用户最新要求：不要增加细碎校验、固定证明链和新交付门槛，避免为了证明完成而无限追加工作。本轮只纠正会改变决策的规则和真实误判，用少量有区分力的回归验证。

## 最小实现

1. 复用统筹现有指引与模型评测入口，对可选优化与确定阻断分别验证。确有行为缺口才做短小的指引修正，不扩展 Host schema 或新增审批流程。
2. 修改既有 business-development、review-code-implementation 中相关段落：导入导出关注实际变换链的身份/空值语义，集成改动同步必要测试夹具；按涉及程度选择代表用例，不强制全场景矩阵。
3. 复用现有 Registry 脚本和 UAT 运行指引，消除认证类型和镜像展示字段误判；前端只检查入口及必要自有主资源，正常空 CSS、可选遥测不作为失败。没有复用价值不新增检查器。

## 验证和交付

只运行相关脚本测试、少量模型行为回归及独立复核；保留真实失败。个人工作区/skill 的修改留可回放补丁与摘要，直接回读实际安装内容。插件改动走新分支 PR，不合并或部署历史业务任务，不重放消息。
