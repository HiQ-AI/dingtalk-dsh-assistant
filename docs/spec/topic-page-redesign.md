# 话题页面重构方案

## 目标

话题页用于快速扫描当前群聊中的话题处理状态，并在固定版本下查看摘要、未决问题、关联任务与原始消息。此次重构只调整 Observer 展示与交互，不改变话题、消息或任务的数据契约。

## 现状问题

- 话题标题被放进内容宽度不确定的描边按钮，长标题会挤压列表层级。
- 列表和详情平均分栏，详情标题、版本与长正文争抢宽度，出现重叠。
- 摘要、待解决问题、关联任务和原始输入缺少稳定分区，阅读时难以判断信息性质。
- 消息只用分隔线平铺，发送人、时间、正文和引用缺少清晰的时间线关系。
- 窄屏虽然不会横向溢出，但列表和详情缺少明确的折行策略。

## 设计方向

采用面向运行排查的“话题索引 + 上下文工作区”布局，沿用 DSH 的主题变量、共享按钮、菜单和状态点。视觉重点来自选中行左侧强调线、处理进度和消息时间线，不引入新的固定色板或装饰性卡片体系。

```text
┌ 群聊筛选 ─────────────────────────── 处理口径 ┐
├───────────────┬───────────────────────────────┤
│ 话题 31        │ 状态 / 版本 / 标题              │
│ ┃ 当前话题     │ 摘要                           │
│   其他话题     │ 待解决问题 / 关联任务            │
│   …            │ 原始输入时间线                   │
│ 分页           │ 消息分页                        │
└───────────────┴───────────────────────────────┘
```

## 改动点

1. 列表项改为整行语义按钮，标题最多显示两行，摘要最多显示两行；选中状态使用主题强调色和浅色背景。
2. 列表展示独立的状态、版本进度与动作进度，处理进度使用可访问的 `progressbar`。
3. 详情头部允许标题完整换行，状态与版本放在独立元数据行，避免互相覆盖。
4. 摘要、待解决问题、关联任务使用稳定分区；无内容时保留明确空态。
5. 原始消息改为时间线，发送人、时间、正文和引用分别布局，并对超长连续文本启用断行。
6. 主区域使用可换行 flex：桌面端列表约 360–420px，详情占剩余空间；窄屏自动堆叠。
7. 延续既有请求取消保护、加载、错误、空态、分页及键盘按钮语义。

## 令牌与组件归属

- 色彩、边框与背景：现有 `--dsw-alias-*` 主题变量。
- 群聊筛选：现有 authored `SelectMenu`。
- 操作按钮：`@deepseek-ai/dsh-client-ui-primitives` 的 `Button`。
- 状态表达：现有 `StateDot` 与语义色映射。
- 页面局部排版：Observer 当前内联样式范式，不新增并行样式系统。

## 验证

- Observer 源码测试和全量 Node 测试。
- 浏览器覆盖正常、长标题长正文、列表/详情加载、空态、错误重试、分页、陈旧响应抑制、键盘选择。
- 1280px 桌面与 390px 窄屏截图；检查话题区域无横向溢出、标题和元数据不重叠。
- 严格静态 UI 审计与改动范围反模式搜索。
