# 执行资源读取与审查闭环

日期：2026-10-21。用户要求落实流分类任务复盘前三项；部署失败归因于共享部署平台，本轮不改上传、健康或构建流程，不修改 dataset 业务代码。

## 当前缺口

1. 实现审查已要求解释循环数据库访问的必要性、上界和次数，但可以只把未解决风险列在交付限制中。需要由原实现职责补证或修订，并保留未解决发现；不能以注释、顺序依赖或 mock 功能通过代替成本依据。
2. 首次测试前的实现审查漏掉新增测试的 import，导致通过后修改候选并重跑。应覆盖本轮生产代码、测试、夹具与辅助代码，先处理已知规范问题再固定候选；新发现仍正常修正复验。
3. Host 已原子持有整段 execution 的资源，但只有统筹的 task_execution_read 能读实时资源；执行者不得访问统筹工具，只能等待额外 feedback。这产生额外查找及工具准入拦截。

## 实施范围

- 复用 dynamic-task-store 的执行绑定校验和 executionViews 资源投影，新增 execution.resources 只读查询。在同一次账本读取中验证当前 task/session/inputVersion/leaseEpoch 和运行资格，仅返回当前执行身份与实时 resources，不接收模型指定的 executionId，不读其他任务正文，不变更租约。
- task-session-service 为每次执行绑定 readResources 回调；execution-session 注册无参数 execution_resources_read。保持现有 current、feedback 与取消门禁，拒绝同名工具覆盖；该内部只读工具不记为外部 operation。
- 返回值是当前观察，不替代授权或后续写入门禁。无资源时明确 none；旧租约、续办前绑定、已提交/排空、任务暂停均不能用旧身份取得有效持锁证明。
- 更新 README 与运行指引中的工具合同；现有 uat-pr 的共享资源章节说明统筹和执行者各自入口。除此之外不修改部署流程。
- 精确更新实际 DSH skills 的实现审查、方案审查与业务开发步骤，不新建 skill；不要求所有项目额外压测、全量扫描或人工批准，不允许用无界全表加载及任意深度截断替代合理方案。

## 验证与交付

- 真实隔离 SQLite：自身 held/none、参数篡改、旧租约/版本/会话、暂停/终态拒绝、续办换绑、读取无新 receipt/operation 或锁变更。
- 原生 Agent/Tools/Session 集成：执行者直接读自身资源，模拟正常续办无需统筹 feedback；错误参数可纠正，同名覆盖拒绝，旧身份拒绝，读取不产生外部操作。保留已有资源生命周期与阶段报告回归。
- skills 做格式/本地引用检查及独立情景评估；格式成功不等于真实长期执行行为已证明。
- 原复盘保留历史证据，将部署故障更正为平台问题。代码实跑后按仓库流程提交 PR；不主动触发 CI，不将 PR 或隔离 Host 测试当成本地运行实例已升级。
