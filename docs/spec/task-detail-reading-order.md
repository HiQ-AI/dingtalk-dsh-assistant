# 任务详情阅读顺序调整

目标：首屏说明当前状态、待处理原因、目标与最新产出，随后显示阶段和执行步骤；隐藏工作流编号等技术标识，历史执行按需请求。保留真实会话入口、分页、失败重试和旧请求隔离。复用现有 UI token 和组件，不请求任务耗时诊断接口。

改动仅在 observer 客户端：历史区域独立折叠组件控制挂载；产出提前且注明最新产出不等于交付；空步骤显示明确状态。用已有隔离浏览器检查宽窄屏、键盘和请求时机，相关单测检查原有行为。
## 第二轮视觉方向（用户反馈后）

保留真实步骤编号。详情采用上方任务总览、下方左侧编号进度轴与右侧产出的双栏布局，窄屏自然叠放。顶部状态、任务标题、更新时间分三级；当前/受阻步骤有明确视觉焦点，完成步骤降低强调，尚未执行使用空心编号。进度条仅表达已完成步骤数，不声称工作量完成百分比。阶段仍保留编号与中文状态，结果和目标不用相同大小的卡片堆叠。沿用宿主品牌色、成功/警告/错误状态色，字体继承宿主，数字使用等宽数字。不增加图像、动画或重型依赖。
