# 共享资源、恢复验证与统筹收口

## 现状与目标

2026-10-27 草稿 UPR 物料名称任务中，同一 UAT 对象存在多个自由字符串资源键；本地准备期间提前占发布资源，后来又等待无关 development。固定恢复探针经模型复制丢失末尾 LF；临时验收脚本误解 JSON 字节与版本类型。统筹已有纠偏文字，但重复核验和文档收口仍需外部提醒。

本轮基于 main 63f7f74a（已包含 PR282）修复三类问题，复用当前 task/execution 生命周期及正式审计，不改历史效果、不重放原命令。使用已附着工作树的新分支 worktree-resource-stage-recovery。原有未跟踪产物保留。

## 方案约束

1. 资源身份由工作区受信目录登记 canonical key、已知 aliases 及用途，插件不能内置 HiQ 仓库、环境或私人配置。Host 统一解析新声明，并在排队/持有/操作约束中识别旧别名占用；不原地改旧回执或把冲突持有者强行合并。提供可读目录，错误或歧义配置关闭该路径并明确报错。
2. 本地准备和共享发布记录为明确阶段。准备阶段不得申请已登记发布资源；进入发布阶段须在原执行真实排空后按本轮必需集合原子获取；不得持部分锁等剩余键，未知效果/在途作业仍阻止释放。保留通用文件互斥等既有用途，不凭自然语言猜资源身份。
3. 恢复复用 native-restart-scope-probe 的权威计划；新增必要的公共执行入口避免模型手抄长命令，确保真实执行参数、末尾 LF、摘要及原生回执来自同一原文。不能放松精确绑定、人工审计和 noReplay，也不启动旧 Maven/PG。
4. 验收沿现有公共脚本归属补齐 Registry 原始字节/JSON解析及版本语义核对，业务误配与解析错误明确区分；脚本实跑隔离 HTTP 夹具，默认不读凭据、不访问生产，不用真发消息或部署证明本地测试。
5. 统筹在既有巡检/决策/feedback 机制内判断当前动作是否必要、发布资源是否被本地准备拖住、收口剩余动作是否减少；明确纠偏或等待的事实依据，保留每次结论。证据足够后沿原成员集中收口，不新增固定审查人数或审批。
6. 现有技能按职责同步，保留输入样本/目标版本/候选验证及未知效果边界；不给每项小任务添加新文档门槛。代码、运行说明、技能要分别验证。

## 验证与交付

按相关风险运行定向测试，包含别名互斥、原子多资源、阶段切换、重启/旧持有者/未知效果、探针原文往返和篡改拒绝、HTTP原始字节与字段类型、巡检主动反馈与不重复反馈、可收口与仍缺证据对照。保留首轮失败及新轮复验。技能做结构与独立场景评估。

本轮交付代码/公共脚本/本地技能及独立 PR；未授权合并、部署、手动 CI 或真实钉钉外发。运行数据和原任务只用于只读取证。
