# 有序列表回读与原通知对账

目标：原通知已发送成功，仅因分段列表 `1./2.` 回读成 `1./1.` 而无法结清。本次修复现有正文比较，不引入发送、补发、消息编辑或直接写账。既有通知回读方案为历史快照，此处单独记录当前场景及边界。

范围：只从期望正文识别围栏外的顶层、从 1 开始、编号连续的列表；允许条目之间有空行。构造条目编号各自为 1 的回读候选，保持正文、顺序和行结构，再复用原有 inline-code 与无序列表格式处理。不把全文数字或所有列表编号统一抹除，不修改真实消息或原始通知正文。

验证：基线复现两条失败用例，修复后定向验证格式与身份反例、unknown 仅执行 notification.reconcile 的合同。读取精确原消息完成离线校验；待活动执行自然排空，按原生双包部署规程 Check、SIGINT、安装、启动和独立回读。运行时沿既有原通知回读正式对账，验 delivered、相同 messageId、sendAttemptCount=1、告警消失，不调用重试发送接口。
