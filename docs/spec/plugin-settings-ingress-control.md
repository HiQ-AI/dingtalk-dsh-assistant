# 配置页加载与消息接入控制

## 目标和现状

配置页核心数据与 DWS 鉴权子进程、完整任务和告警列表共同等待，慢探测/单接口失败导致配置整体延迟。现有桥具备断线恢复下界、完整历史范围校验和消息 ID 去重，但没有操作者暂停入口。

## 决策

- 核心配置与辅助探测分开：配置、群和健康先显示，环境、统计、版本独立加载和报错；使用既有分页 total，避免拉完整任务正文。
- 暂停范围是订阅群的新消息接入（事件与定时补拉），不是停止已接纳任务、发件箱或操作者私聊审批。停监听并等待已开始的可靠接收排空；进行中的历史读取返回后不再接纳消息。
- 接入状态持久化，重启仍暂停。恢复先建监听再沿暂停前下界补拉；沿既有去重与 ingressEpoch，不修改旧任务/消息身份。仅完整补拉成功后清理持久恢复下界；失败保留并定时重试。
- 本地受信 PUT 接口严格接收 paused 布尔值；UI 显示暂停、恢复补拉中、失败而非把接纳等同于补拉完成。

## 比较与排除

1. 缓存环境结果：只能改善重复访问，不能解决首次慢调用和故障耦合，故不选。
2. 缩短命令超时：会把慢检查变成失败，仍阻塞配置，故不选。
3. 核心/辅助分离并使用分页统计：保持检查真实结果且减少数据传输，采用。

暂停不采用只屏蔽前端（后台继续接收），也不采用取消订阅（会改变群配置和丢失恢复边界），采用桥级持久开关。

## 验证边界

定向测试验证慢探测不阻塞配置、辅助失败隔离、迟到刷新不回写、暂停/重启/恢复补拉/补拉失败保留下界、接口权限与非法参数。实跑构建核对生成 bundle；不声称已部署或真实钉钉验收。
