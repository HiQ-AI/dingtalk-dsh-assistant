# 内置任务进展查询流程

任务进展询问属于一次性平台操作。消息仍依次经过 S（事项）、R（话题／目标）和 I（意图）；`status`、`result` 意图进入内置查询流程，不创建 execution run，也不进入任务看板。

流程固定为 `task-progress-query@1`：

1. **范围校验**：记录本群、当前提问、已关联的单任务或群内集合范围。只允许同群任务；集合查询只读有限候选。缺少可核身份时返回未定位，不猜测。
2. **候选检索**：读取新工作流的任务来源和旧任务快照。标题、目标和后续澄清只是召回线索；排除提问发生后创建的任务、明确只做排查的前置任务。返回候选身份和匹配依据。
3. **进展回读**：逐个回读任务状态、结果和结构化交付标记。已取消、完成、已部署分别表述；缺交付回执写“未见部署回执”，不推出未部署的事实结论。
4. **答复生成**：只依据回读节点输出生成引用来源消息的回复，保留候选归属的不确定性；数量补充仅写话题事实，后续引用问题清单重新执行只读查询。

每步输出经过结构校验，流程版本与节点摘要存于 `message.command.complete` 的结果中；同一命令在失败／恢复时按原命令身份重试，不产生业务 Task。通知仍走独立 Outbox，ACK 与渠道送达分开。查询的最大候选数为 8，超出时说明结果有限而不宣称查全。权限使用消息入口已认证的发送人与同群边界；对非所有者只暴露任务标题、状态及结构化交付标记，不返回私有执行记录。

本次不迁移旧 `status-query.js` 的历史事件；旧 Resident 未切换群保留其原有处理路径，已切换群只使用消息工作流和此内置查询流程。
