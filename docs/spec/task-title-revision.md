# 目标修订时同步任务名称

## 问题

Task 的 `objective` 可以在 `task-context` 或 `task-reopen` 中修订，但名称仍停留在首次创建时的语义。排查任务升级为修复、部署后，看板会继续显示旧名称，影响当前状态识别。

## 方案

- `task-context` 与 `task-reopen` 增加可选 `title`。
- `objective` 实质变化时必须同时提供概括当前完整目标的新 `title`；只提供 `title` 或目标变化却缺少名称均拒绝。
- Runtime 在同一次 Task 原子更新中写入新目标和新名称，并通过 `objectiveHistory`、`titleHistory` 保留旧值与版本信息。
- 重开时的 `runHistory` 保存该轮名称；普通信息补充、等待恢复和异常唤醒不改名。
- Task ID、叶子 Session 和执行历史保持稳定。

## 验证

- 协议接受续接动作中的合法名称，并拒绝超过 120 字的名称。
- 运行中任务目标升级时同步改名并保留名称、目标历史。
- 仅提供名称或只修改目标不提供名称时不产生 Task 副作用。
- 已完成任务按新目标重开时同步改名，旧名称保留在名称历史和轮次历史中。
