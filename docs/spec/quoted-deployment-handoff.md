# 引用部署指令的协调承接与状态修复

## 目标与现场证据

2026-10-27 消息 #313 的原文为“部署到UAT2”，引用包含 dataset #417、dataset-web #389。首轮路由已识别两个 PR，独立协调的原生日志 seq=5 输入却只有 source.original/unitText，没有 quotedMessage；最终 seq=32 提交重复询问部署对象。来源预约快照未保存引用，协调 context 也未投影引用，构成两处信息断点。不是原消息没给对象，也不是初次路由没有理解。

看板将 source.processingCompleted 当作 processed，但该标记只证明本轮语义决策已提交；协调仍 needs_clarification/unsettled。结论仅取 Topic decisions/ignoredRanges，遗漏独立协调问题和接纳结论。

## 方案与边界

- 复用来源预约、原消息版本与动态来源 quote，保留引用身份/作者/内容与附件上下文；协调初始输入及按需分页可读取同一份真实引用，不把候选摘要当授权原文。旧预约从同版本来源核验引用，不能用更新版本或跨群任意消息补足。
- 原有 Task 关联仍由模型读取完整目录/目标判断；引用用于解释目标，当前作者/原文约束决定授权。无引用仍允许真正必要的澄清。
- 消息投影增加真实协调决定，区分待澄清与语义已处理；语义耗时独立于来源收束、通知和业务部署。前端沿用既有表格和折叠明细。
- 现场恢复保留原消息/来源/预约及已送达澄清，不重新入站、不重复发送旧问题；仅在有受控、可审计恢复路径时重判原预约。验证承接不等同于宣称 UAT2 部署完成。

## 验证与交付

定向测试覆盖引用的预约/初始输入/分页/旧预约恢复/版本隔离、无引用与有冲突反例；原生 Host 回放“部署到UAT2”关联原任务。HTTP 与浏览器覆盖等待澄清、已接纳、混合单元、结论和时间。现场只读证据落忽略目录，脱敏断言与结果进验收轮记录。代码通过定向验证后提交 feature PR；本地部署按 ops runbook 自检后执行并独立回读包、PID、健康及 #313。
