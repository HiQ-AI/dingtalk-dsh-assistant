# 工程任务仓库校验与原任务重发方案

## 现状与目标

归一化计算任务的消息动作把 `repositoryId` 冻结为 `dataset-web`。该仓库只有前端代码；后端 `dataset` 的 `origin/main` 存在 `DatasetMergeCommonServiceImpl` 等合并实现。工程节点在前端检索后提交空 `changes`，`apply-changes` 以 `ENGINEERING_EDIT_SCOPE_MISMATCH` 等待。空变更没有写入效果，自动恢复扫描又刻意跳过该确定性错误，因此任务不会前进。

目标：工程仓库目录向意图节点提供具体职责，任务接纳前拒绝已知错选；空变更给出准确可恢复诊断；对这条无编辑效果的旧运行，在明确目标仓库后保留任务与节点历史，以新代次重新执行。不得把前端文件写入后端仓库、复用旧验证、重发不确定通知或绕过权限。

## 流程

1. 每个准入仓库配置稳定的 `purpose` 与必要的目标关键词。意图节点只选目录中的仓库；Host 在创建前检查目标关键词的唯一匹配，如果动作选择不同仓库则拒绝接纳并要求重新选择。关键词只处理明确领域，不把未匹配误判为正确。
2. 直接检索节点的空变更在应用前标为 `ENGINEERING_NO_CHANGES_PROPOSED`，避免误称范围越权。节点不自动重试同一产出。
3. 大文件不要求模型复制全部正文。v8 允许提交精确 `from/to` 局部替换和原文件 SHA256；Host 在冻结候选中核对文件身份、目标原文唯一命中并还原完整文件，再交给既有受管编辑效果。未命中或多处命中明确等待，不执行模糊编辑。历史 v6/v7 定义保持不变。
4. Web 本人可对等待在空变更、且全部节点已排空、没有编辑/提交/推送/PR效果的工程运行，指定已准入仓库重发；同仓库仅允许从 v6/v7 空方案升级一次到 v8，防止无限重发。Host 读取原任务目标，冻结新仓库配置与当前基线，持久登记新定义；Store 原子切换到新代次，旧节点标记 `superseded`，再从准备节点执行。任务 ID 与来源不变，领取次数向前推进；重复请求按 requestId 幂等。
5. 本地验证使用隔离 Store 和 fake adapters 覆盖错选拒绝、正确选择、空变更、局部替换、重发成功及有编辑效果/未排空/越权反例。部署后回读本机 profile 的两仓库目录、包哈希、原任务的新代次和实际节点。业务代码只由插件任务流执行；本次修复者仅检查和修复插件。真实业务修复、构建、PR 与渠道通知分别独立回读。

## 风险边界

后端 `dataset` 来源须用独立干净 Git checkout 和固定检查命令；不能直接用用户当前脏工作目录。旧任务的完成通知不能因重发而重复发送。新仓库的完整业务结果由任务流产出，重发操作本身不算修复完成。
