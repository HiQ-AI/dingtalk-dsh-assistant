# 公共话题事实与环境确认接续

## 已验证问题

2026-10-08 四条测试环境讨论先正确匹配原开发任务，却因其中第三人仅补充公共 UAT1 占用事实而触发 WORKFLOW_TASK_FORBIDDEN，协调器最终把整段讨论另建为无 Task 的事实话题。原 Task 已读到文档正文，仍缺 UAT。原生会话 lease 60 中可回读候选及拒绝顺序。

另一个独立阻塞是 engineeringTarget 仅从当前消息匹配完整 UAT 名称，不能接纳合法需求方结合问答给出的“那就2吧”。不能靠给短句添加正则解决通用上下文语义。

## 方案与边界

1. 同群已有话题中的纯公共事实，仅获取公共话题上下文，剥离 Task 身份；全动作必须 fact、conversation scope、replyPolicy none。Host 再次核验，消息账不为此产生 Task 输入围栏或 Owner 事件。混合动作及 revise/control 仍按原 Task 权限核验。
2. 合法需求方选择环境使用 revise。显式 UAT 保留原来源核验；短答语义须携带真实同话题问答来源引用。模型理解含义，Host 核验来源版本、原文、群及话题和当前确认人的权限，保存原文证据。上下文作者不升级为任务授权人。
3. 权限拒绝反馈要求纠正动作，不得靠新建话题避开权限。
4. 历史恢复仅开放已 settled、全 applied 纯会话事实且无 Task、通知、执行和外部效果的原消息。沿现有 reprocess 递增来源版本，失效旧事实，保留原作者、正文和审计。原 create 不重放，禁止直接写控制库。

## 候选与排除

- 去掉 Task 权限：会放行第三人修改任务，排除。
- 所有事实都拒绝关联 Task 话题：继续拆散同话题上下文，排除。
- 公共事实与任务修改按动作区分：复用现有话题及权限，采用。
- 直接相信模型填写 UAT：无法排除缺来源的猜测，排除；采用可核验的真实问答引用。

## 验证

本地覆盖第三人公共事实与合法 revise 同批、越权 revise 拒绝、Owner 不被公共事实唤醒、问答 UAT 来源与跨话题/旧版本反例、仅纯事实可重处理。部署沿现有 Check、排空、封存、包回读和 Resume；Resume 后沿既有入口恢复四条真实来源，随后核验原 Task 的 UAT2、唯一任务和 Owner 继续，不伪造用户答复。
