# 消息上下文与混合事项修复方案

## 目标与现状

任务执行会话承担业务执行责任，群协调负责完整承接和准确分派。审计在真实 SQLite、协调器和 Service 上复现：引用已解决澄清的新交办被入口提前消费；已执行事项与待澄清事项共处一消息时，补答后整条来源被已有命令过滤；新会话旧历史仅30条且没有省略标记或补读入口；历史旧版本、同时间戳前文和引用身份投影存在缺口；重复全文单元可产生重复动作。

基础反证：87项既有相关测试通过；独立事项能够分别建Task，两个动作与闲聊可以分别执行和忽略。因此保留当前持久群会话、消息控制账及任务后端，修复入口和数据合同。

## 实施设计

1. 新消息先经统一接收持久化，引用通知作为当前事实进入协调输入。模型可在同条消息输出clarification与其他事项；已解决澄清只作为历史引用，不直接消费当前消息。澄清动作仅使用本单元原文，保留原请求身份、权限和幂等。
2. 协调澄清补答记录待续办unit身份；调度只重新接纳这些单元，已执行/运行/效果未知及无关等待单元原样保留。续办使用稳定unit身份和原话题，提交事务重新校验来源、单元、请求和任务版本。不能仅放宽整条消息过滤后重建所有单元。
3. 当前上下文按有效source版本去重，使用来源序列处理相同时间戳；最近窗口明确返回省略与游标。增加同群、来源水位内的历史分页读取，读取结果登记为本轮可用材料，引用及历史保留发送者、时间和附件身份。保留原生会话连续历史，不增加全量历史堆叠。
4. 拒绝相同来源跨度和相同动作的重复单元；支持同一句表达不同目标及共享约束，不能通过禁止所有跨度重叠误伤合法拆分。模型指令区分事实、闲聊、多独立事项和同一任务多阶段，新增脚本化语义合同用例；脚本化Provider不冒充真实模型准确率。

## 范围和交付

不改执行会话权限或任务工作流定义；不部署、不向钉钉发测试消息、不重放真实历史。复用隔离worktree，在最新origin/main上新建worktree-message-intent-context；主仓未提交资料保持不变。

## 验证

按子目标独立验证，再组合真实Service/SQLite链路：两个任务加闲聊、局部澄清与完成项保留、引用已解决/未解决通知加新任务、同请求重复回复、重启/并发/过期来源；40条及超过200条历史补读、编辑去重、同时间戳、跨群/未来来源拒绝、附件与引用身份；重复单元拒绝、合法共享跨度通过。测试和失败过程进入docs/acceptance/message-intent-context，matrix为用例最终状态源。通过后提交PR并回读远端状态，不合并或部署。
