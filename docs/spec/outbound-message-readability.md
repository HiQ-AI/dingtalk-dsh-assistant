# 提醒提及与对外消息可读性

## 现状与目标

2026-10-23 第 7 轮真实提醒已送达，但用户指出没有原生 @，旧失败提醒的协调摘要也暴露了协调、计划、执行及收件人内部标识。普通群发送分支丢弃 `atOpenDingTalkIds`，协调摘要直接展示审计快照；私聊人工申请及话题回复还存在同类输出入口。

目标：到期提醒使用可信来源中的人员身份发送钉钉原生 @；所有当前对外正文只展示事项、时间、结果和必要行动，不展示平台运行 ID、修订号及无意义技术统计。内部关联、幂等和历史证据不变。

## 实施边界

1. 普通与引用群发送统一透传并校验原生提及列表。使用当前 DWS `--at-open-dingtalk-ids`，不把 userId 或显示名冒充 openDingTalkId，不通过正文拼接假 @。
2. 协调查询、接纳、订正、取消、暂停、到期及失败摘要按业务语义生成，时间统一使用当前工作时区；不凭失败状态推断未发送、已修复或应重发。
3. 复用现有对外正文守卫，以实际运行标识格式与已知内部身份拦截泄漏。保留业务编号和链接，不做静默文本删改。人工申请和话题决策在持久接纳前校验，避免无效正文落账后永久堵住发送。
4. 人工申请正文不再显示内部申请号，但原生引用和 payload 关联保留。仅约束实际对外字段，内部 evidence 仍可保存诊断身份。
5. 不修改已准备通知的不可变正文，不重发历史提醒，不改活动数据库，不扩展到已停用工作流。新版本继续使用既有受控双包部署流程。

## 验证

- 普通/引用/Outbox 的真实命令编译包含合法原生提及参数；空列表无参数、非法列表发送前拒绝。
- 协调所有外发分支没有运行 ID、重复时区和无意义计数；具体业务事项与必要失败边界仍准确。
- 人工申请及话题含内部 ID 时在入账前拒绝，修正后能正常提交；业务编号和 URL 不误伤。
- 送达证据与 @ 证据分开：DWS SUCCESS 及消息回读证明送达，只有明确 openDingTalkId 元数据或用户客户端观察证明实际 @；缺元数据标未验证。
- 部署后继续真实群订正与到期提醒验收，独立回读通知数量和实际耗时，保留已知约 45 秒模型处理延迟边界。
