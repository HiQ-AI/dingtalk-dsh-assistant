# 会话列表正式进程资源争用修复

## 目标与现状

正式会话列表超过60秒，隔离相同列表读取约513毫秒。正式进程短时CPU样本显示垃圾回收、UTF8解码、文件读取及旧发件箱替换图遍历占据主要时间；只读调试调用栈确认入站会执行readWorkflowSeal。当前追加群封存快照约34MB，每次入站重复读取、摘要计算和JSON解析；初始群已有文件身份缓存，追加群没有。发件箱替换图对每条发件重新扫描全部发件，形成平方级工作量。上述属于已证实的重复工作；列表响应改善须部署后实测，不能提前把全部延迟归于它们。

## 修改

- 初始群与追加群复用同一不可变快照验证路径，按路径、摘要、验证范围及文件身份缓存成功结果；并发同一验证共享Promise。每次仍stat核对文件身份，读取前后身份不一致或摘要/业务校验失败立即拒绝并清缓存。
- 替换图构建反向邻接表，后继查询只访问相邻记录；环、未知目标、分叉及已有后继检查保留。
- 不改原生会话列表合同、不删除历史、不绕过入站切换门禁。

## 验收

定向切换/发件箱/桥接回归，规模化快照复验和替换图访问计数，标准安装及同一正式列表请求读回。原失败证据保留；真实项目/代码问答证据另行核对。
