# 原生会话目录校验开销分析

## 目标及当前证据

PR #243扩展测试5项超时。32轮续办隔离复跑（同profile、原120秒门槛）91.5秒通过，外部fs测量lstat=39322次/25901ms、realpath=39252次/32446ms、readdir=3167次/2506ms、open=3149次/12016ms。不是已证明的死锁；相同逻辑能结束，但同步链路目录检查占主要耗时，机器/磁盘负载可使其越过既有门槛。

## 根因及修复

checkedTaskDirectory对每级祖先都做完整realpath，后代验证重复解析已核对的整条父链。backendFor对缓存命中仍前后两次全树检查。先保留每一级lstat及符号链接拒绝，仅在现存目标末端核对realpath；创建缺目录前再次核对实际父目录，再沿既有mkdir/lstat继续。backendFor仅新装配前做创建检查，缓存及装配完成后统一核验一次，仍在每次原生调用前检查。不得跨公共调用缓存目录安全结论，不放宽任务/会话身份或原生写者授权。

## 验证与反证

保持原超时与断言；先运行原生persistence全组（含祖先/root/project/session/log/index替换链接、取消、重启），再同32轮fs测量对照。完整扩展组合、release smoke及测试映射门禁全绿后才合并部署。任何门禁失败保留新round并分析。现场四文件差异已核对为本地安装落后于main中0885fcb阶段边界修复，部署应基于最终合并main，不能照旧以为是未知私改。
