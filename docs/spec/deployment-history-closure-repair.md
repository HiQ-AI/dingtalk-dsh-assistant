# 部署备份对明确历史清理的工件引用处理

## 原因

正式控制账中4个不存在的工件属于两个已删除历史任务，execution_events的task.delete明确记录reason=explicit-user-terminal-history-cleanup。备份验证遍历所有历史引用，但未识别已完成文件清理的生命周期。原生普通task.delete明确retained包含artifact-files，仍必须保留并验证文件。

## 处理

从只读控制账建立明确历史清理任务集合，要求当前business_tasks/execution_runs中均没有该任务。仅此集合的任务工件在文件已不存在时记录为已清理引用；其余缺失、破损或链接仍失败。保留整个数据库和审计事件，不删引用、不伪造工件。在线自检、离线备份验证、备份复核使用同一规则，结果记录具体已清理引用。

## 验证

覆盖明确清理记录通过、普通删除保留工件仍失败、无删除记录失败、仍存在当前任务失败、存在但损坏的工件失败及备份复核。通过后按现有维护部署流程安装已核验包，恢复原任务只读调查，并按真实消息ID更正或撤回过时受阻通知。

历史引用根还包括execution_receipts中的节点领取绑定与message_items中的旧Task候选快照。已清理Task对象不再作为闭包根；只有Run的对象须由historyRemoved阶段启动回执和原生plannedStageRunId证明，或由旧dispatch命令摘要同时匹配Task32位/Run40位证明。数据库行摘要和现存文件清单不变，未知Run不豁免。此逻辑仅部署备份使用，不改变在线任务运行规则。
