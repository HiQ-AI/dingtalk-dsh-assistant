# 本地包部署与原运行恢复

用户要求将新包替换、校验、服务重启固化为脚本，减少重复工具调用、人工轮询和部署耗时。现有部署核心已包含维护、停机锁、原生安装、进程和健康检查，但入口位于历史验收目录，调用者仍反复拼接参数和读取中间状态；配置预检没有核对活动工程定义的冻结摘要。

## 目标与范围

复用现有核心，提供一个常用PowerShell入口；一条命令执行输入/包核验、零写预检、原生维护排空、停机、替换安装、计划任务启动、真实健康及包/profile/PID回读、恢复派发。阶段和汇总打印到终端，详细JSON和日志存放docs子目录。继续已发起部署时只回读/恢复，不重复安装或迁移。

普通无迁移部署不复制或扫描历史Task树。必要依赖索引迁移只保留控制库一致性恢复副本及固定profile，独立核验逻辑摘要；其他既有迁移保持各自必要范围。Check必须零写，不凭回执声称已安装或已恢复。

## 当前真实故障

包6deedf50安装101文件核验通过，控制库已为schema9。第二次配置同时更新全局checks、增加单Task验收map，改变repositoryDigest，三个活动工程Run在新配置下全部恢复失败，启动报ENGINEERING_DEFINITION_CONFIG_DRIFT。其旧配置摘要全部匹配，已有Run的checkpointChecks仍保存正确前端2/后端3。

此次恢复只将两个仓库的全局checks还原为核验过的旧值并移除新增taskmap，保留当前双向dependencyRepositories、首轮Host回执读取能力和其他全部配置。不得整份还原旧profile、修改控制表、取消/重建Task或放宽漂移检查。检查和验收修订通过原Run正式checkpoint接入；全局默认配置待旧活动定义结束后切换。

## 实施约束

- 现有原生YAML编辑器增加窄受控恢复合同：当前/旧源摘要、原部署链、活动定义、精确字段及其他字段不变都核验；原子CAS写入，输出真实恢复证明。
- 统一入口复用已安装包及原维护封存许可，对真实退出的失败启动执行受控配置恢复并重新启动；保留原launch，不伪造历史成功，后续回读验证新的恢复链。
- 预检在停机前验证计划配置与活动定义摘要，冲突时明确拒绝，不能等到新实例启动才发现。
- 启动失败输出具体阶段、代码和证据路径，不盲目反复重装/重启；真正业务审批和未知外部效果保持原边界。

## 验证

定向测试覆盖Check零写、一调用完整流程、错误时不误恢复、失败启动只修当前配置、重复回读/恢复不重复部署、输入/配置漂移和外来证据拒绝、汇总不泄露秘密。最后使用同一入口实际恢复当前安装，独立回读101文件、新PID双端口、health、maintenance inactive和自启；另核原Task/Run/代次/成功节点没有被重建或重放。

## 普通包替换不隐式修改配置

无工程或查询提案时，直接走维护、包安装、原profile摘要核验、启动、Readback、Resume。configArgs为空，不执行配置check/apply或计划工程配置编辑；安装前后profile必须逐字摘要一致。若提供任何工程字段，Bundle/MergePolicy/ChecksProposal必须齐全，RepositoryPatches不能单独生效。无需新增mode开关；既有查询/完整工程/失败恢复分支不变。
