# 任务卡片信息层级修订

## 用户判断

任务看板是四列状态概览。卡片用于快速判断任务结果、异常和下一步操作；目录、分支、文档路径属于归档操作的核对资料，不适合作为每张卡片的常驻内容。此前仅把清单折叠，仍让无操作意义的“待归档清理”和通知成功信息占据卡片，并未解决信息选择问题。

## 展示决策

| 信息 | 卡片默认态 | 按需位置 | 理由 |
| --- | --- | --- | --- |
| 已完成任务的业务结果 | 显示，如“已成功/已取消/已失败” | — | 完成桶包含不同结果，必须区分。 |
| 完成通知已送达 | 不显示 | 群聊发信箱 | 正常终态，不需要重复占卡片；发信箱保留送达证据。 |
| 通知待生成、待送达、受阻 | 显示简短状态；多条按状态计数 | 群聊发信箱 | 尚未闭环，影响用户下一步判断。 |
| `topic_request_retry_exhausted:<id>` | 显示“系统协调受阻 · 待恢复” | 原因原文保留在 Task 数据与悬停提示 | 长请求 ID 不帮助扫描；此类等待不是让用户重新发起任务。 |
| 其他等待原因与信息等待通知 | 显示原因摘要；信息等待通知单独保留 | Task 会话 | 等待原因或所需补充可能需要用户采取行动。 |
| 待归档状态、目录数、文档数 | 不显示 | 点击“检查并归档”后的预览 | 已完成任务的归档入口已在卡片底部，正常待归档状态无新增信息。 |
| 归档清理失败 | 显示“归档失败 · 查看原因后重试” | “查看并重试”预览中显示原始错误 | 属于需要处理的异常。 |
| worktree 路径、分支、文档来源及归档位置 | 不显示 | 归档前核对/归档记录 | 只有执行清理或追查记录时才需要。 |

## 归档交互

无登记目录且无失败记录的完成任务维持直接归档。存在登记目录或失败记录时，先显示操作预览，再由用户确认归档。预览明确区分任务自建目录与借用目录：Runtime 仅迁出并清理已登记的任务自建目录；借用目录及其登记文档保留原处。归档后的卡片仅在有目录记录时提供“归档记录”入口。预览只是解释即将执行的范围，不代替 Runtime 的只读预检和身份核验。

## 视觉与组件

沿用 Observer 主题变量、卡片密度与警示色。默认态减少内容，异常信息优先；预览采用卡片内次级表面，长路径可折行，文档列表限高滚动。归档按钮与打开会话按钮分离为两个真实按钮，键盘焦点和操作目标独立。桌面维持四列，窄屏一列。

## 验证范围

真实浏览器隔离渲染覆盖正常通知隐藏、异常通知可见、技术等待摘要、默认不出现路径、借用目录预览、任务自建目录清理预览、失败原因、取消无写请求、窄屏与键盘。后端归档行为以现有 Runtime 代码和测试为准，本次不修改。
