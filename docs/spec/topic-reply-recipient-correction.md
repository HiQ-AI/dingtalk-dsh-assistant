# Topic 语义回复对象修复前置方案

日期：2026-10-29（Asia/Shanghai）；基线：63ab508b502c8d2576a654e9be2f15225031d7ff。
本文件是实施前快照，进展及最终决策记录于唯一goal：`../acceptance/topic-reply-recipient-correction/goal.md`。

## 目标与问题

Topic 结合本轮固定原文、引用、人员身份及已有回复，决定沟通内容和对象；Host 只验证并执行，不以最后依据消息作者覆盖对象。明确纠正助手回复对象与新增/取消业务任务是两件事，不应因任务保持不变而仅记事实。

现场交接线索采用脱敏A/B/C表示：A提出需求、B补充解释；决定同时依据A/B，Host实际回复并@B。C随后引用助手回复纠正对象为A，模型仅提交actions=[]与reason。交接不等于本地已复现，需测试独立验证。禁止读取正式库或现场补发/撤回。

## 已读调用链与根因边界

- `decision.js:39-49`：reply分支允许actions=[]、reply和replyReview，但没有replyToMessageId/atOpenDingTalkIds；reason是独立不回复分支。因此无需任务动作也可以沟通，不能归因于schema禁止空actions回复。
- `topic-runtime.js:1001-1046`：在固定request上校验来源、任务版本、群、回复归属及历史回复审阅，随后持久接受decision。应在外部接纳边界校验显式回复路由，不允许先执行任务再发现新请求路由非法。
- `topic-runtime.js:801-812`：执行阶段从record.revision对应消息中findLast(basisMessageIds)，然后将其作者同时作为回复对象和@对象。这是确定的Host覆盖点；是否完全解释现场需另有现场验证，本任务不做。
- `topic-runtime.js:315-322`已有replyRouting：目标来自本Topic真人消息，显式收件人必须是这些参与者且不可重复，未提供@时按已显式选择目标推导。完成/审阅通知在:1220/:1306已经复用。默认infer目标与依据last是不同语义。
- `task-topic-coordinator.js:139`包含“明确他人负责且未要求助手参与时仅记事实”指令。应澄清“纠正本助手沟通对象”不等于转派业务给其他人，保留正常他人负责业务的静默，不取消上游非干预边界。
- 既有outbox、replyReview和operationId幂等必须保留；回复接纳/持久/送达不能混称。完成/阻塞通知路径的已有显式选人合同不应顺带重构。

## 三种候选与取舍

| 方案 | 优点 | 不采用/采用原因 |
|---|---|---|
| Host根据最后basis、姓名或纠正关键词推断对象 | 变更小、兼容表面简单 | 不采用：没有稳定语义，A/B反例仍错，别名歧义及引用他人可能扩大授权 |
| Topic显式选择routing，Host复用固定版本replyRouting与原outbox | 已有成熟验证及通知能力，任务与沟通解耦 | 推荐：在现有decision上增加必要字段，不引入独立收件人服务或调度器 |
| 全套跨Topic主回复/纠正事件架构 | 可以统一更广泛沟通 | 不采用：超出本次范围，增加迁移和恢复复杂度，非本问题必要条件 |

## 实施范围与接纳合同

1. reply分支暴露显式replyToMessageId及atOpenDingTalkIds，使用已有消息/人员ID，不把姓名文本交给Host猜测。reason分支仍不回复，不混入路由字段。
2. 本次新接纳的真人群回复必须选定合法目标；校验基于固定request.messages和既有replyOwnership过滤，不能扩大到别群、任意历史消息或新版本人员。
3. 与既有replyRouting保持最小一致：明确目标后未指定@的默认是该目标作者，不再用last basis；显式@仍验证参与者集合。具体字段必填策略、无真人来源及显式空@语义由实施前机制核对收敛，不为猜测未来增加开关。
4. 校验后的路由保存在原decision账本中，恢复执行读取同一固定版本验证，不因新消息改变目标；沿用原outboundId/sourceMessageId及回复审阅替换协议。
5. 历史已接受记录必须单独识别：已持久outbox及成功送达不重发/重选；无显式routing的旧pending记录不能默默按最后作者解释成新语义。实现前按既有恢复能力决定最小fail-closed或复用已冻结路由，并用实际测试证明，不凭空承诺全部旧数据库兼容。
6. 语义指令说明普通沟通纠正可使用actions=[]+reply；确认被纠正对象确属助手及同事项，别名歧义先澄清，不把引用他人消息当助手错误，不把收件人纠正扩成任务取消/重建/转派。不强制每条纠正另发一条，既有审阅/幂等可合并或维持已正确沟通。

## 验证计划与证据

- SG1/S3：脱敏双依据基线，证明B最后发言但A才是目标；修复后实际outbox的replyTo、@、source和decision持久字段准确。
- 明确纠正、任务保持：本地重现引用助手错回复，使用原任务/版本，检查任务无新建/取消/唤醒且适当沟通成功。
- fail-closed：别名歧义不猜；非法跨群/不在固定版本/伪造收件人拒绝；引用非本助手回复不得替换无关outbound。
- 幂等：同一decision重复提交、发送故障恢复、重启后已持久outbox不重复；新消息不漂移原路由，异值冲突拒绝。
- 回归：普通确认、完成/阻塞通知、replyReview和来源/授权；按影响选择现成相关文件，不自动全量或CI。
- 结构测试不能证明真实LLM一定理解所有昵称或任意自然语言；如只使用受控模型输出须在报告说明提示词覆盖边界，不冒充真实现场E2E。
- 各轮结果由docs记matrix/round，历史FAIL保留；全绿后report。独立review审实现/测试和边界，Lead核关键原始结果后提交新PR。
