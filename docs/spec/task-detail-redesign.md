# 任务详情阅读工作台

## 现状与目标

现有 `web-client.js` 将每个步骤的元数据、产出和会话入口全部纵向展开，当前结果位于末尾；长流程难以定位当前步骤。仅改 observer 展示，不改变任务状态、接口、授权、控制操作或部署。

验收目标：首屏识别任务状态、步骤处理数、总时长与当前结果；以稳定 stepKey 选择步骤；能查看全部当前有效步骤、完整目标、产出分页和真实会话；刷新、删除步骤、失败、空状态、390px 窄屏均可使用。

## 设计选择

比较三种结构：全量时间线仍需长距离滚动；全部折叠的手风琴难以同时定位流程与阅读产出；采用步骤目录和阅读面板，当前结果置于概览之后。桌面目录约 320px，正文占余下空间；窄屏目录在上、阅读面板在下，提供查看所选步骤与返回步骤目录的键盘入口。

视觉沿宿主 `colors/ui`：底色 #fff、次级底色 #f7f7f8、正文继承宿主、辅助 #737373、强调 #4d6bfe、等待 #a56500、失败 #c33 为既有回退值。标题 24px，章节 16px，正文 14px，辅助 12px，数字 tabular-nums。标志性元素是实际顺序的编号步骤目录与选中指示；避免相同卡片反复堆叠，不加装饰图、动画或依赖。

## 交互与所有权

继续以 `docs/manual/observer-design.md` 为 DESIGN/UX 唯一维护入口。复用宿主 Button、TaskStepOutput、TaskStepElapsed、TaskTotalElapsed、groupTaskSteps 和当前 detail API。步骤选择使用原生按钮，不伪装成需要方向键模型的 tabs。首次选择当前运行/等待/失败/受阻步骤，其次未执行步骤，最后已完成的末步；用户选中后自动刷新不抢走阅读位置。

已访问面板保持挂载但隐藏，以保留展开和分页；未访问产出不请求。产物身份变化沿原 key 清空旧正文，detailRevision 继续约束分页。删除正在阅读的步骤时选择相邻步骤并宣告变化；无剩余步骤时聚焦章节标题。请求失败保留原内容和选择。

## 验证与交付

复用已有 React 隔离宿主方案，新增本特性的可重复场景脚本，因为现有脚本绑定历史私有任务快照、旧布局和固定临时路径。先用相同夹具运行基线，再验证改版的明暗主题、桌面/窄屏、键盘、加载/失败/空状态、跳过/复用、分页保持和计划更新。用例状态进入 matrix.csv，各轮保留证据；截图仅在 docs/tmp，不提交二进制。相关 Node 测试、语法检查与 UI 静态审计后提交 feature PR，不自行部署或合并。
