# M2 受管代际目录实施快照

2026-09-23。继续既有执行重构目标；本轮解决旧代文件混入新代候选及受管目录恢复，不开放任意shell或生产任务。

## 设计

- 一个run/generation对应一个新目录，路径由Host根据身份摘要产生，不能接收模型指定任意目的路径。固定源仓库、固定base commit；不复制源工作区的未提交变更，也不自动合入旧代文件。
- 目录准备是一项控制账效果：先持久prepare/begin，再创建。metadata只承载不可变归属/基线，不另建第二份权威任务账。跨进程崩溃留下的未完成目录保持unknown，由原身份检查；不能覆盖或重克隆未知目录。
- 使用独立Git仓库而非共享worktree对象库，避免候选执行目录借用主仓索引/配置。仅本地源，clone不运行任意用户shell；拒绝hook/filter/危险Git配置和特殊文件等不受支持源。
- 读取原始base tree得到初始manifest，初始化后校验精确HEAD与tree。完成后用户的编辑不被当成初始化失败而重置；归属/HEAD/元信息冲突必须明确报错。
- 仅受信code节点能调用Host绑定的workspace准备能力，任务代际与输入身份由Controller给出。旧执行必须真实排空才能应用输入换代。目录写权限隔离、通用编译shell、自动垃圾回收不在本批实现。

## 验证

真实临时源仓库：A代删除/修改/未跟踪文件、外部用户变更保留；B代从固定base全新开始，失效A删除不进入B。并发/重投只分配一次，跨进程控制账恢复复用同身份；目标目录占用或残缺不覆盖；取消/输入屏障/撤权先提交则不能创建；不得修改源HEAD、index和文件。
