# 执行事件查询索引治理

## 目标与现状

当前正式任务详情返回17010字节，Node直接请求仍约4秒。独立只读完整投影约0.4秒，Run与工件读取均不足以解释秒级延迟；HTTP鉴权仅核验群归属。当前约459MB控制账的execution_events没有kind索引，详情与每5秒通知轮询反复按kind扫描事件表，占用同一原生worker。

同一原生备份的两份隔离副本对照：只有索引不同，查询数332、详情字节数和业务状态一致。无索引负载下详情约1.2–2.1秒、后台约4.8–5.7秒；增加(kind,seq)后详情约62毫秒、后台约192毫秒。EXPLAIN由SCAN变为按kind SEARCH，完整性检查通过。正式在线改善仍需部署后验证，不能以副本测量替代。

## 实施路径

1. 原生控制账schema升级7→8；新库建立execution_events_kind_seq(kind,seq)。启动严格校验版本及索引列序、非唯一、非部分属性，不在启动时静默迁移。
2. 独立迁移脚本沿现有迁移契约实现--check零写、--execute受控离线：已停止旧PID、封存维护、排空、独占owner锁、事务及完整性校验。仅新增索引和版本；规范化全表摘要证明业务行、事件、效果及审批不变。单独脚本必要，因为既有continuous迁移的职责是6→7运行上限移除。
3. 既有正式部署helper加入明确的事件索引迁移模式；输入及回执摘要绑定、完整备份后执行、安装启动前核验，Readback/Resume复核；失败保留封存和备份。不得通过手改正式SQLite或复制开发源码部署。
4. 保持原生单worker、全部详情节点、版本一致性、删除账与审批语义。无需缓存删除状态、截断历史或新增投影框架。

## 验证

定向原生store/迁移测试覆盖旧版本拒绝、缺失/错误索引拒绝、check零写、未封存/未排空/仍运行拒绝、事务及幂等、全部业务行不变。正式包逐文件校验、新PID/健康/维护恢复独立回读；同一真实Task直连多次测量详情及看板，并核对17010字节内容及待审绑定。浏览器安全校验不可用时明确页面验收边界，不绕过限制。
