# 通用 Agent 身份边界

Agent 名称、工作区与群职责来自用户配置，名称不构成授权，也不自动生成署名。插件没有默认私人身份。

## 配置契约

`GET /state/agent-config` 返回 `replySignature`；`PUT /config/agent` 可保存或用空字符串清空，省略保留原值。值去除首尾空格，最多80字符，不接受控制字符或开头列表标记。非法署名在同次配置写入前拒绝。scheduler storage 保留字段及 getReplySignature/setReplySignature；profile `agentReplySignature` 仅在持久值未设置时初始化，持久空值优先。

## 最终正文

完成回复、requester问题、实质性话题回复在 `task-session-service` 调用同一个格式器：先清理模型各字段中与当前配置精确相同的独立落款，再拼结论、证据、限制，最后统一附加 `- 配置署名`。清理不猜测其他身份，不全局删除姓名，不删除引用、围栏代码、缩进代码或业务列表。空配置保留模型原文，不尝试推断或删除旧身份。

话题确认与中间内容不加署名。模型提示明确由Host负责最终署名。群职责不再承担署名生成职责；现场重复要求须在部署及配置核实后人工清理，本次代码不修改现场。

通知准备前完成格式化，持久化正文作为 digest、发送、回读、重试的共同来源。恢复已准备的人工问题或话题回复时复用原正文，不能按新配置重新格式化。历史已准备/已发送通知不改写、不补发。旧 workflow-notifications 不恢复，也不复用其任意行匹配即返回逻辑。

## 验证边界

定向测试覆盖配置、设置保存/清空/刷新/失败草稿、正文缺签/重复/中间签名、证据限制、引用代码保护、长正文与固定payload重试。DWS分片由外部CLI承担，插件只提交一次完整正文；代码测试不等于真实钉钉分片或现场部署验证。
