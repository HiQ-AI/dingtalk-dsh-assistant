# 通用 Agent 身份边界

## 身份与署名

个人身份、项目环境和业务规则由实际 Agent 的私人工作区与群职责提供。`agentNames` 表示名称/别名，不构成执行授权，也不自动生成署名。公共插件不包含默认个人名、私人署名或个人项目环境。

群职责在群会话及任务会话新建、续办时注入。公开回复与向需求提出人的问题是否需要署名、署名内容由工作区和所属群会话职责决定；有要求时由模型按要求生成，未要求时不默认添加。Host 不添加、删除或替换署名，不从名称、职责自然语言或用户原消息抽取署名。

## 格式与配置边界

完成结果、状态查询和业务提问共用 `formatTaskGroupReply`。格式器保留正文署名、业务列表、证据引用和代码示例，继续校验原消息、真实发送人和 @ 绑定及公开正文安全性。它不检查模型是否遵守个人署名要求。

已删除设置页的全局署名字段、`replySignature` 配置读写和 profile `agentReplySignature` 初始化入口。旧字段不再生效，旧客户端提交 `replySignature` 明确拒绝且不保存同次请求中的其它配置。刷新设置页后再保存。已有通知不改写、不补发。

历史 `workflow-notifications.formatGroupReply` 属于已退役工作流，当前 resident 不挂载，不作为新任务会话入口。本次不恢复旧任务、不修改原生运行权限。

`group-reply-format.test.js` 验证模型署名及业务正文保留；`task-session-reply-identity.test.js` 验证旧配置不暴露、不接受，真实原生会话的系统提示及完成/状态/业务提问通知；`client-reply-signature.test.js` 验证发布 bundle 的字段删除与其它配置保存、失败草稿保留。
