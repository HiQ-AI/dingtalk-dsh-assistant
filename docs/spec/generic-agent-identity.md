# 通用 Agent 身份边界

## 当前任务会话运行时

个人身份、项目环境和业务规则由实际 Agent 的私人工作区与配置提供。`getAgentConfig().agentNames` 继续表示名称/别名，不构成执行授权，也不自动生成群回复署名。公共插件不包含默认个人名、私人署名或个人项目环境。

群回复唯一的署名来源是可选结构化字段 `getAgentConfig().replySignature`。它在既有 Agent 设置页、`PUT /config/agent` 和 `GET /state/agent-config` 中读写，存储于当前 profile 的插件 storage。首次初始化可使用私人 profile 的 `agentReplySignature`；已有存储值优先，显式空字符串在重启后仍表示禁用。不同 profile 的配置不共享。

- 默认未配置或空白字符串：不署名。
- 显式字符串：去除首尾空白后，以独立末段 `- <replySignature>` 附加一次。不要求特定姓名或“代回”后缀。
- 只接受不超过 80 字符的单行字符串；拒绝对象/数组/null、控制字符、换行、零宽格式控制、开头列表符号和禁止公开的内部标识。
- 不从 `agentNames`、群职责自然语言、用户原消息或模型结果猜测/抽取署名。多行多个署名直接拒绝，不挑选第一个。
- 配置变更从下一条新准备的通知生效。已经准备或发送的通知正文不可变，不为改名重发。

完成结果、主动查询状态、需要补充信息的问题共用 `formatTaskGroupReply`。原消息 ID、真实发送人 ID 与真实 @ 绑定仍必须完整；无来源时拒绝，不退化为普通群发。结论、证据、限制及有效业务链接的能力保持不变。

## 模型正文边界

模型在 `summary`、`evidence`、`limitations`、`question` 中只写业务正文，署名不属于模型输出契约。格式器只清理末尾独立、未缩进的署名段：前有空行（或整个字段只有这一段），整段只有 `-`/`*`/`•` 加空白及当前配置署名，或一至四十字符名称加“代回”。该窄结构不包含换行、引号、句读、分号及引用尖括号。前一非空行是列表项、代码缩进、引用或冒号引出的列表时保持原文，不通篇过滤。没有列表符号的业务语句与结构化证据项保持原样，不能只因以“代回”结尾就删除。实现不列举私人姓名黑名单。

普通正文提到某个人、带引用符号的引用文本、代码围栏里的签名样例均保持原样，不做姓名全局替换。只含签名、清理后没有结论的 summary 拒绝发送。未配置时独立旧签名不会成为当前身份；任意自然语言中的姓名属于业务内容，不能靠文本猜测删改。

## 个人配置迁移

需要沿用署名时，在私人 profile 初始化字段或插件 Agent 设置中明确填写完整署名，并回读确认。旧群职责中自然语言写的署名不会自动迁移。个人 Agent 工作区指引和业务 Skill 应改为提交不带签名的业务正文；不要把这些私人值写回公共仓库模板。

历史 `workflow-notifications.formatGroupReply` 的职责解析属于旧工作流实现，当前 resident 不挂载该流程；它不作为新任务会话配置入口。本轮不恢复旧任务，不改历史通知正文，也不修改凭据或原生运行权限。

## 验证

`group-reply-format.test.js` 覆盖两种个人署名、未设/清空、旧模型署名残留、正文及代码保留、引用/@绑定。`task-session-reply-identity.test.js` 使用真实配置 HTTP、store 与 SQLite 通知路径验证保存、清空、重载、不同 Agent、完成/状态/问题及既有通知不可变。`client-reply-signature.test.js` 执行发布 bundle 的交互回调，覆盖保存、换配置、清空、刷新和失败草稿保留。它们不等同于真实钉钉发送或本机部署验收。

测试 fixture 与历史验收记录中的个人名是显式输入素材，不属于 runtime 默认；公共源码姓名扫描单独验证没有这类绑定。
