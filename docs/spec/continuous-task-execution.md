# 持续任务执行与受管操作

## 问题与目标

2026-10-03：用户要求综合早期单会话易推进但易走弯路、当前流程稳定核验但频繁中断的缺点，改造并验证。当前已有每 Task 唯一持久 Owner，却只有读材料和提交计划能力。节点失败时 `execution-session.js` 结束本轮，`task-workflow-contracts.js` 仅对 running 且有领域修复合同的阶段暴露修复；调查等失败因此只能等 Web 操作者。`task-owner-session.js` 第二次重复候选又会成为不可自动恢复的错误。问题是责任和恢复能力断开，不能靠继续加错误码特例解决。

## 方案取舍

1. 全部退回无编排单会话：上下文连续，但不能丢弃已有精确审批、未知效果对账和最终事实核验，排除。
2. 继续扩大自动重试名单：能解决暂态网络，不能修复错误策略、参数和产物，且无法阻止同一路径空转，排除。
3. 保留一个持续负责的 Task Owner，将工作流定位为受管操作：采用。Owner 负责目标、问题诊断与路径选择；节点会话负责具体动作并能带着原历史继续；Host 仅以事实守住控制、授权、外部效果和验收边界。

反证：单会话也会反复生成同样错误；纯重试不能创造工具能力；Host 的所有失败都改成可重试会掩盖损坏或越权。因此本方案不取消验证，不把所有异常自动重放，不让模型自改权限或批准。

## 执行闭环

- 同一会话内可纠正参数和输出直接反馈；保留原始工具错误码与位置，不能只上传笼统 execution_tool_failed。
- Owner 快照始终显示当前运行/等待/失败动作及 Host 准入的恢复能力。失败是下一次诊断的输入，不自动变成人工前置条件。
- 对失败或 recovery 等待的 **agent 节点**增加通用受管续行。冻结定义已限制 agent 只具 pure/read 能力；恢复同一 node、generation、session，保留成功前缀。Owner 必须读取诊断并提交修复方向；Host 以当前版本、排空、输入围栏、节点无外部效果和其他效果全部已确定为准，原子接纳后再调度。恢复上下文独立附加给会话，不修改用户需求或节点输入摘要。
- 领域产物修复继续使用既有 `inspectRepair/prepareRepair`。外部操作和 code 节点不纳入通用重放；审批等待和未知效果沿原效果账恢复。没有真实恢复能力时明确内部问题责任，不能伪称用户缺资料。
- 当前有可执行修复时，Owner 不能仅 wait/block 消耗事件后闲置；应修复或重规划。真实审批、用户输入、控制暂停仍等待原生事件。
- 防空转以相同节点、输入、失败原因的持久恢复记录判断；同一问题恢复后原样再次出现，不再次机械恢复，交 Owner 换路径或诊断实现问题。重复无效候选结束当前思考轮并退避，保持同一 Owner 可继续，不永久终止业务任务；指纹忽略说明文案，避免改写措辞绕过检测。

## 长期任务的验收作用域

本轮真实反证：旧加列阶段已批准并完成，本轮删除阶段也已批准、执行及回查成功，但 Owner 浏览所有历史阶段时无条件触发旧加列的生产实时回查，要求已删除的列仍存在，导致 POSTGRES_COLUMN_VERIFICATION_UNCONFIRMED。这是持续 Task 先后合法动作的通用冲突，不是删除 SQL 的特殊情况。

历史事实与当前状态必须分开：`task-release-workflows` 的领域证据读取仅核验冻结节点、审批、效果、当时独立回查和身份；Owner 浏览历史不能隐式访问生产并重验过时目标。最终验收先按每项 evidenceRefs 与具体 stage.outputRef 分派责任，而非把同一领域的全部验收项交给该领域的所有历史阶段。只有承担当前验收项的阶段做实时领域回查，并将原始回执交给验收策略保存。历史阶段批准/执行绑定仍逐项核验；历史证明损坏、当前证明缺失或验收归属错误仍不能完成。

## 不变量与发布边界

不新增 Task、不新增调度器、不迁移持久 schema。不重建成功外部效果，不将 Bytebase SKIPPED 当作插件审批。不扩只读权限、不伪造成功、源消息或审批。当前 #858 的 pending 插件审批保持原身份，真实删除仍等待人决定。历史冻结工作流保持摘要；运行恢复属于 Host 生命周期合同。

所有任务内部进度继续静默；必要业务问题、插件私聊审批、最终结果保留。内部修复能力存在时禁止生成群里的人为阻塞提示。

## 验证

定向原生会话和 SQLite：同会话纠错；非调查 agent 节点也能恢复；失败阶段重新接入同一会话；成功前缀保持；错误码真实保留；相同问题跨重启不盲目重放；重复候选不永久 blocked；活动恢复不能被 wait 吃掉；暂停/取消/过期绑定/待输入拒绝；审批等待和未知效果不可通用恢复；完成必须继续通过领域验收。按 runbook 正式打包部署，验证精确包、新进程和健康状态，独立检查原审批身份与未重复发送。
