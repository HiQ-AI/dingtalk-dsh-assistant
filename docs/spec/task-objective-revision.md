# 同一任务的授权目标修订

## 问题

群聊中的调查任务可能在调查后被继续要求修复、合并或部署。当前 Runtime 能把后续消息关联到原 Task，也能重开已完成 Task，但只追加上下文；叶子 Goal 仍使用首次创建时的 `objective`。由于 `objective` 同时是动作授权上限，后续明确授权无法生效。

## 目标

- 保持同一 Task、叶子 Session 和历史上下文，不因授权范围升级创建重复任务。
- `task-context` 与 `task-reopen` 在原消息明确改变动作范围时携带修订后的完整目标。
- Runtime 持久化目标修订历史，并以最新目标重建叶子 Goal。
- 普通事实补充不修改目标，也不扩大授权。
- 叶子必须以当前目标对应的流程和证据要求判断完成，调查证据不能完成已升级为修复、部署的任务。

## 方案

Task 继续以 `objective` 表示当前有效目标，并新增可选的 `objectiveHistory` 留存每次被替换的目标、来源消息和修订时间。续接协议新增可选 `objective`：只有原始消息明确改变动作范围时才填写，而且必须概括累计后的完整目标，不能加入未经核验的根因或方案判断。

Runtime 接受目标修订后先持久化 Task，再结束旧 Goal、以新 `objective` 创建 Goal，最后把来源证据信封和授权变更明确传给原叶子 Session。已完成任务重开和运行中任务追加上下文共用同一修订逻辑。

## 验证

- 决策协议接受带或不带 `objective` 的 `task-context`、`task-reopen`。
- 普通续接保留原目标。
- 运行中调查任务收到修复要求后更新 Task 目标、记录历史并重建 Goal。
- 已完成调查任务收到修复和部署要求后以修订目标重开原 Task。
- 完整 `pnpm test` 通过；本机 Web profile 重新安装依赖并重启后回查插件和 Runtime 健康状态。
