# 任务名称、生产只读调查与受阻通知

## 当前问题

任务读模型直接使用完整 requirement.request 作为 title；看板卡片有32字符截断，但关联任务入口直接使用原始标题。生产只读数据库通过已登记连接执行 BEGIN READ ONLY，并核验 pg_is_in_recovery；然而未知表在连接前被表白名单拦截，结构调查无法读取 process_id_temp。Owner 阻塞报告已有 summary，但通知仅输出固定受阻句。

## 修复范围

- 新任务动作提供可选8–20字、最多30字的简短 title，保存到既有 requirement 中；旧任务读模型使用30字短名称，所有看板入口复用已有32字显示上限，目标完整保留。
- 数据库资源增加显式 metadataSchemas，用于授权 schema 内的表目录和完整列结构查询；数据 select 保留精确表列白名单，生产身份和事务核验不变。目录向模型明确环境、连接别名及结构查询范围，提示先使用登记连接自主核验，不把工具范围错误当作缺用户材料。
- 受阻通知附 Owner 的简短 summary，最多160字符，保留既有幂等事件身份。

## 验证

覆盖标题最大长度、原目标保留、未登记表 metadata 调查可连接生产只读副本、select 越界及非副本拒绝、阻塞通知摘要和重扫幂等。正式部署仍须解决先前发现的4个历史工件缺失问题，不通过扩大权限或伪造工件绕过部署检查。
