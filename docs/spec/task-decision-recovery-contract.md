# 任务决策与恢复合同

实施前快照，2026-10-02；承接用户批准方案。原目标文件仍为acceptance/board-loading-session-repair/goal.md。新建本方案因为本轮修正Task与阶段状态及恢复合同，旧看板性能方案无法承载其状态矩阵。

## 现状及根因

task-owner-store accept把整体wait/block绑定未成功阶段；阶段完成后Owner发现目标未完成却无法表达等待。candidate只检查计划变化，accept才检查决定合法性。release把未分类错误置blocked，内部决策错误伪装为业务受阻。数据库columns工具SQL仅三属性，无完整定义/依赖操作；原调查第二页nextOffset=400后提交completed。

## 设计

复用现有decision与SQLite单写事务，不增加第二状态机。阶段状态描述执行，Task完成由Owner已接纳complete和独立验收证明；Owner运行状态仅描述决策执行。wait/block可在阶段全部成功后提交，必须绑定具体condition（类别、缺失事项、责任方、恢复条件和证据）；不得以summary自由文字作为恢复授权。活动阶段不得由业务等待取消或绕过；完成/取消/暂停/租约和授权门禁不变。

提取同一决策合法性校验供candidate和accept使用：candidate提前反馈，accept事务内再次核对版本。参数/状态候选拒绝可修正；相同快照反复相同拒绝停止为内部异常，不无限重试；新事件/版本可重新判断。业务等待由既有新信息/审批/能力恢复事件唤醒，同事件不重复通知。

数据库扩充登记schema内结构查询，完整列属性、约束/索引、依赖与估算规模；业务数据select仍登记表列授权，生产副本和只读事务证明保留。无任意SQL入口、不读取或扩权目标业务数据。调查搜索必须完成必要覆盖或明确范围排除理由，工具证明支持机械核验，不承诺自然语言零遗漏。

恢复原Task沿受管入口核对版本、排空及未知外部效果；事件重评保留成功证据，不SQL改完成/伪造人工批准。既有历史决定不重写，旧错误诊断仍保留。

## 验收与部署

定向原生SQLite/会话/服务/查询测试覆盖成功阶段后wait/block/append、非法候选反馈、相同拒绝收敛、并发输入、真实业务条件、内部错误投影、恢复幂等、只读授权及完整元数据。docs/ops runbook执行Check、维护排空、备份、精确包安装、独立Readback和Resume。真实原任务补只读调查并推进到业务确认/本次审批；生产DDL不执行。每轮证据追加既有matrix和round记录。
