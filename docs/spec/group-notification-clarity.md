# 群聊结果与补充请求的清晰呈现

Owner现有summary类型为string，完整决定与证据由Task持久保存。通知直接加“任务已完成”并输出完整summary，混淆排查完成与修复完成，单换行还可能被渠道折叠。保持现有schema、业务状态与冻结工厂，不引入第二次模型总结或结构化新字段。

Owner完成摘要用既有string显式写【结论】【结果】【下一步】，2–3条短结果，约300字内；排查结束但未修复须明确标注，谁需关注/是否需要行动说清楚。日志、hash、账号、SQL全文留证据。formatter只对明确换行转为空行、包上必要标题；不按句子/关键词自动缩写，不删半句。旧长摘要无结构时完整保留，不冒称已经语义压缩。

待补充从condition.missing取具体信息清单，并列责任方和恢复条件，不贴Owner长分析。消息澄清/授权使用同样空行与明确标题。原消息引用提供事项定位，末尾提示到原事项任务详情查看完整证据；无已配置公开URL时不生成链接。DWS payload必须逐字保留，包括已有SQL；实际外部renderer若缺片段，缺失正文不能通过送达比较。测试覆盖原Owner schema提示、formatter、真实DWS编译参数与已知段落回读差异，不发送现场消息。
