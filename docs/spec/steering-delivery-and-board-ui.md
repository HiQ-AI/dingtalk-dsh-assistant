# 插话投递与运行看板修订

## 目标

- 群聊 Inbox 持久化后等待 5 秒，再以 DSH `steer` 投递至常驻主会话。
- 主会话向运行中/阻塞中的叶子会话补充消息时使用 `steer`，不进入 follow-up 队列。
- 运行看板全程保留左侧菜单，同时折叠动画不透出底层 Session。
- 任务卡操作及活动摘要使用业务可理解文案；审批状态复用群消息 Agent 投递 Tag。

## 根因

- `runtime.ingest` 在群级串行区内先 `whenIdle()` 再 `followup()`，因此所有 Inbox 消息都等待当前轮结束。
- `followupTaskInternal` 同样固定调用 `followup()`。
- 全视口看板遮罩层的层级高于侧栏，背景阻止了透底，也把侧栏绘制在下面。
- 任务活动直接展示底层事件名 `tool/call`，审批列表另建了一套 Tag 样式。

## 实施与验证边界

- 5 秒延时发生在持久化之后、Agent 投递之前；测试使用可注入延时避免真实等待。
- 使用 `agent.steer()`；不把历史导入、结果审核等必须独立成轮的内部流程改成插话。
- 侧栏本体在看板打开期间提升到遮罩层之上，关闭时恢复原内联样式。
- 单元测试验证调用方式与延时；浏览器验证左栏、卡片文案、Tag 和折叠动画。
