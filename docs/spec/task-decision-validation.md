# Task 修订决策校验与恢复

## 已确认问题

2026-09-11 现场同一 Task 已完成排查并进入修复轮次。新轮次 stagePlan 缺失，主会话提交不存在的 stageId；Store 接受决策并预约 Task 后，执行层才抛 task_revision_stage_invalid。Topic 后续输入和叶子 plan-confirmed 报告都被永久阻塞。上轮标题兼容没有修复该协议缺口。

## 设计

- 阶段身份由 stagePlanFor 唯一生成。主会话上下文与叶子输入在未批准计划时也提供同一稳定阶段索引；这仅是身份，不代表计划获批准。
- 删除标题匹配。Store 在原子接纳点使用与执行相同的纯修订校验，覆盖 Topic 与 Web 入口；未知 ID、错误来源、无依据 replan 和非法阶段数组在落决策、预约或 Outbox 之前拒绝，原请求仍可纠正重提。
- 已存坏决策在执行副作用前检查。仅针对整份决策均为 task-context、动作映射完整、执行版本未变、确定的输入校验失败且所有任务动作均未执行的记录，原子记 rejected、释放自己的预约；不提高 processedRevision、不改 Task、不删除历史 Outbox。新请求带 rejected 决策身份，重启仍可恢复且不复用旧请求。含取消动作的旧意图可能已经执行过尚未落盘的取消副作用，不自动退回。
- 已写入 Task.appliedOperations 的动作即使决策 operation 状态仍 pending，也不能被退回或再次授予执行权限。部分执行、存储失败、外部副作用不明继续按原持久幂等路径处理。
- rejected 是终态但不表示业务输入处理完成。原消息仍需由新的有效决策完成；已发送确认进入正常回复审阅。

## 验证范围

复现当前重开且无 stagePlan 的故障；错误/标题/旧轮 ID 零副作用拒绝、同请求改正、当前 ID 正常重规划、持久旧坏决策重启恢复、无新消息同 revision 重决策、已应用但状态未写回、部分执行、Outbox 不重复、并发版本改变和正常报告审阅推进。用现有真实 DomainFacility/DSH Session 测试设施，并在本地安装后回读实际决策、报告、Session 与渠道状态。
