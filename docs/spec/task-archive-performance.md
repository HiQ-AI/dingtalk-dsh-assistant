# 任务归档性能优化

目标：减少旧任务单个登记工作目录归档的固定开销，保持所有清理安全门禁；使用一次性 Git 样本测量前后耗时，复跑归档及 Runtime 定向测试。

当前 Runtime 对单目录执行一次 checkOnly，然后归档入口 prepare，再在迁出文档后 prepare。每次 inspectTaskWorktree 串行运行七个 Git 命令，每次 prepare 都独立 ls-remote，单目录共查询远端三次。

方案：单目录直接进入归档入口的 prepare；多目录继续全部预检后逐个归档。用原生 rev-parse 一次返回根目录、Git 目录、公共目录及 HEAD，其他身份信息仍独立核验。文档迁出后的 prepare 和远端实时复核保留，不缓存网络结果，不后台删除目录。

反证与边界：新版 workflow 归档不调用这些函数，因此不声称改善新版任务；大量文件删除、网络延迟及归档后的全看板刷新可能另有耗时，本轮不以本地样本推断正式环境响应时间。多目录预检防止第二目录失败前删除第一目录，不能直接取消。

验证：同机交错执行三轮 baseline/optimized，计时只包含单目录预检和归档，独立回读文档、磁盘及 Git 登记。已有测试覆盖脏代码、未知文件、未推送、历史改写、换分支、复制期间修改、目录缺失恢复及失败重试；Runtime 定向测试覆盖跨任务占用与完整归档入口。基准脚本单独放 acceptance，以便复现，生产代码不增加测试参数。
