# 审阅流程提示词批量读取

## 现状与根因

组合任务会选择多份任务流程。常驻主会话的 `group_task_prompt_get` 当前一次只接收一个流程 ID，审阅提示又要求逐项读取，因此同一个审阅请求会连续调用同名工具。实际会话 `dfcb1cd1-c309-45b5-adcf-0dc3e1443231` 的三次调用分别读取排查、实现和 UAT 流程，并非相同参数重试或 Runtime 重放。

## 修复

- 将审阅工具参数改为 `requestId + ids[]`，一次返回 `prompts[]`。
- 对整批 ID 按首次出现顺序去重，再校验可见性与当前修订，最后统一记录已读状态，避免重复结果和部分成功。
- 审阅提示明确要求把已选流程和本轮需要的候选流程合并为一次批量调用。
- fake 模型和测试按批量协议执行，验证多流程组合只需要一次工具调用。

## 验收

- 三份已选流程可通过一次调用读取，随后允许提交审阅。
- 重复 ID 只返回一份；缺失、不可见或过期流程保持失败关闭，且不会留下部分已读状态。
- 单流程、无流程和诊断检查点边界保持可验证。
