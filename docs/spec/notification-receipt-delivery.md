# 原发送回执确认通知送达

目标：修复已成功发送的群通知因钉钉正文渲染差异长期 unknown；部署本地后只核验原消息，绝不重发。

现状：原 openTaskId 查询 SUCCESS，回读精确消息存在；正文列表/段落换行变化使 sameDeliveredText 拒绝。

方案：只在原发送任务 SUCCESS、会话一致、回读 messageId 等于回执 messageId 时直接确认送达。此路径只证明送达，引用及 @ 不标为已核验。无成功发送任务回执仍沿原严格内容/发送者/引用匹配；不更改正文归一化规则。

验证：成功回执允许正文渲染变化/元数据缺失；错误 ID、错误会话、缺失消息及非 SUCCESS 不结清；历史匹配仍拒绝内容与身份变化；unknown 分支 send 调用为零。定向测试、受控部署 Check/Readback/Resume、原通知独立只读回读 sendAttemptCount=1。

## 部署阻碍的必要修复

原生安装阶段暴露 CLI 入口与 profile 声明不一致：profile 中残留旧平铺 CLI 缺少依赖，声明的 file: 完整运行时 CLI 可通过 plugin --help。部署脚本在停机前检查声明与已安装宿主版本一致，并用实际 profile CLI 验证依赖装配；普通代码部署遇宿主漂移即拒绝，避免隐式切换宿主。原失败轮次保留，核对停机/原包/profile摘要与离线账本后，仅接续原安装阶段；不改业务数据库或重发通知。
