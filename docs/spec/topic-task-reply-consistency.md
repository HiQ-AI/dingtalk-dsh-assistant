# 话题任务更新与回复一致性

目标：真实群补充消息更新原任务后再发送承接回复；自身通知回声不得成为授权来源或阻断用户补充。

现场已核验：新消息存在于动态来源账；话题固定历史还包含一条已送达自身通知，该通知没有动态来源。applyTopicAction 遍历所有话题历史，因自身通知无准入来源而报 TASK_TOPIC_SOURCE_VERSION_MISSING。topic-runtime 在 applyAction 前发送回复，导致任务未更新却声称已补入。

方案：使用现有通知身份核验排除自身回声，不按昵称或正文过滤；其余来源继续精确版本准入。所有动作持久完成后才入回复账；动作已提交但后续失败时依现有 operationId 对账恢复，回复仍幂等。显式消息重试针对该来源缺失错误复用现有 retryOperation 的版本/已应用检查，不清除未知效果。

验证：原生隔离宿主复现历史自身回声、同账号人工补充和未准入真实来源拒绝；话题测试核验动作失败零回复、动作成功先于回复、重启不重复动作/通知。定向测试、包及本地部署、原消息受管重试分层取证。无 schema 迁移，不改业务工程或原执行结果。
