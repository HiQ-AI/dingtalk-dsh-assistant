## 对方案的具体补充

1. 卡片显示保持现状，长约束和历次补充可在详情整理呈现，不因此修改卡片标题。
2. 历史范围是完整关联树，包含兄弟重执行、后继重执行和已归档记录；执行编号按接受顺序稳定分配。
3. 区分整次结果、阶段成果和步骤重试。已取消不等于各阶段全部失败，首次工程成功不等于后来新增的部署已完成。
4. 当前详情查询应覆盖本次所有运行；现有执行步骤组件保持不变，被替代的失败过程放本次补充历史；执行次数不得沿用底层运行数量。
5. 前序仅分析任务放相关资料；它不改变修复次数，也不能贡献修复完成状态。
6. 保留卡片来源显示；任务身份不依赖群标识、Web 来源、相同 PR 或相似标题。
7. 最新两条 API 记录的 result 均为空，workflowProgress 则是最后一次部署或重建步骤。详情的整项交付摘要应组合本次工程验收、PR 合并和部署的已验证证据，缺失项明确显示待核对；不因此改变卡片现有摘要或进度展示。
