# 叶子流程审计问题修复

## 事实与边界

UAT2 重构建任务已成功加载流程，但临时 PowerShell 查询直接过滤 Invoke-RestMethod 数组导致查重失真，完整 variables 输出包含下载令牌，两次累计式检查点被拒绝后延迟补报。通用 UAT 流程未明确同提交重跑的适用步骤。

## 实施

1. 通用 Runtime 保留单阶段校验，不自动把累计项修剪成成功。仅对阶段推进错误返回结构化拒绝、当前输入版本、下一项与正确 remainingItems；明确本次新增完成项语义。其他授权/版本错误仍拒绝。补回归证明错误不落盘，按回执修正后才能推进。
2. D:/baibu-agent 无 Git，是实际叶子工作区。其 scripts 当前只有运行于服务端的 Woodpecker poller，没有可供叶子安全查询的 CLI，因此新增独立只读 PowerShell 脚本；不修改 poller、上传或部署服务。显式接收参数和 SecureString token，完整分页、校验目标存在、按 SHA 与分支查重，输出白名单字段。错误状态或未知响应不得判定无冲突，禁止输出 variables/认证值。
3. 插件配置新增“UAT 同提交重构建与恢复”；原 UAT 流程限定新交付场景并说明组合边界。计划列明适用项、复用证据及不适用依据。两项均引用实际查询脚本路径，加载仍依赖任务目标语义，无固定 workType 映射。
4. 本地配置先快照/版本检查再更新，保留其他流程和用户补充。已有流程修订遵循现有 revision 机制；活动叶子收到更新提示。现有已泄露令牌不复制传播，本次不擅自改写历史 Session 或吊销凭据。

## 验证

插件全量回归、累计检查点反例及纠正；隔离 HTTP API 真实执行 PowerShell，覆盖成功/在途冲突、空响应、分页、未知状态、敏感字段与错误响应。真实流水线仅白名单只读回查，不重跑业务。PR 合并后部署本地并回读安装文件与配置。验收证据在 docs/acceptance/leaf-workflow-audit-fixes/。
