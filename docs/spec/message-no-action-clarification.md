# 无待办消息与澄清状态

基线：真实收信验证消息已经入站，S却返回needs_clarification，Web把waiting/routing_blocked显示为关联受阻。认证及落盘正常，非收信失败。现有旧话题路由忽略规则没有覆盖消息工作流S。

方案：S语义输出no_action及全原文覆盖；Host核验成功S记录、无已拆事项/命令/待补请求或屏障，静默收束。明确请求及混合事项保持原有拆分路径，不添加关键词过滤。mailbox按待补请求分别投影waiting_clarification/waiting_context及原因，复用现有状态标签与筛选。

验证：纯测试静默、覆盖不完整拒绝、伪造无节点拒绝、正常事项回归、两类等待与真正错误区分；精确双包部署并对原测试消息逐条重处理后查真实模型输出。旧通知保留，不重发。
