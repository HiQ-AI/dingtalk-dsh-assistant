## 路由召回

保留 query 原合同；新增互斥 queries，1..5 个非空有界词组，去重后 OR 匹配标题/摘要，按命中词数排序、原目录稳定打平、排序后分页。返回命中字段与词组，匹配不是同一性证据。首包原生引用相关优先，有限词面候选共享既有目录预算，目录原序及续读游标不变。优先原生 Intl.Segmenter，不建词典或样本特判。

新建/复用说明应可审计；若需要额外记录，沿既有 route receipt 保存候选与理由。不为纯理由变化增加 Topic 业务修订或重放动作，不影响已消费效果。

## 显式待判与安全屏障

比较三个落点：routed+reason 会误收口；pending+隐藏标记让可调度和待判混同；选择 routingStatus=needs-context 加持久元数据，同时修改实际运行时消息 schema 和关联消费者。storage-v8-schema.js 是冻结归档，不是运行时 schema，不修改它。

本轮采用整条消息待判分支，与 units/ignored 互斥；原文留存、不建立虚假 Topic、不标忽略、不消费来源。批次其他已明确消息可先入账。局部事项待判需要扩大覆盖/继承协议，本轮不引入此第二种路径。

持久信息至少绑定 messageVersion、恢复 epoch、原因、创建时间及必要澄清信息。路由身份包含 epoch；提交与显式恢复在群串行事务内校验版本/epoch，拒绝旧请求、并发重放。已 accepted 操作先查原账恢复，不被新分类合同重新解释。

自动路由只选可运行 pending/实际失败重试输入；needs-context 不自动循环。明确恢复触发限于本消息/材料版本变化、可信精确引用答复和本地受信显式操作；任意新群消息不能重开所有待判。

模型候选或原生引用只能证明关联，不能证明范围封闭。未知范围尤其含混停止/取消保留群级屏障；只有 Host 精确目标或经鉴权的本地明确范围可限定至本群有效 Topic，绑定消息版本/epoch CAS，并在接纳事务中重验。范围缩小不代表本消息已 routed，不授予额外执行权。受信窄范围的 A 待判不得阻塞独立 B；“引用A+其他也停”不能自动窄化。

屏障必须覆盖路由/决策监控、Topic/事实接纳、任务 pending 检查、聚合/恢复；needs-context 对应可见待澄清、source 未路由，不能被消息终态结算为已完成。

## 澄清与兼容

仅明确向 Agent 交办且问题必须由用户补充时允许澄清。沿既有 Host 通知审阅和出箱去重，但待判无 Topic，需要明确来源版本、授权和审阅合同，不能伪造 Topic/固定类别套发通知。普通同事讨论不主动追问；路由角色不新增发送/执行工具。新答复结合原消息重新判断，不把回答视作自动授权。

新提交合同保留业务对象、Agent交付、外部后续、Unit来源；移除活跃 Task 入口的旧流程选择义务。历史已接受账可读且不重放；未接受旧草稿按合同摘要失效重建，不能捕获旧retry闭包混用。
