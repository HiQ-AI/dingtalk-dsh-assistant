# 发件箱读取权限降级修复

## 现象

当前组织未开启 DWS CLI 数据访问权限，`chat +chat-messages` 返回 `CLI_ORG_NOT_AUTHORIZED`。发件箱在发送前强制读取群历史，因此任务完成通知一直保持 `pending`，即使写权限和实时 listener 可用。

## 修复

1. DWS adapter 从结构化 stderr 保留服务端错误码，不用字符串猜测错误。
2. 仅当读取失败码为 `CLI_ORG_NOT_AUTHORIZED` 时，允许使用 Outbox 的稳定幂等键继续发送；其他读取异常和不完整历史继续保持原有安全策略。
3. 发送接口返回确定成功后，即使同一权限导致发送后回读不可用，也按确定回执确认 Outbox；未知回执继续保持 `pending`。
4. 在 Outbox 持久化最近尝试时间、次数、pending 原因或错误，运行看板能够解释消息为何未发送。

## 验收

- 读取权限缺失、发送确定成功：只发送一次并标记 sent。
- 读取权限缺失、发送结果未知：保持 pending，不确认投递。
- 普通读取错误或历史不完整：不发送。
- 重试失败原因写入 Outbox；后续成功时清除失败字段并记录送达时间。
