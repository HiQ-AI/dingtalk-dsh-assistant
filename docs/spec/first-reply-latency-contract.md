# 首次回复关键路径优化

日期：2026-11-04，实施前快照。唯一目标见 docs/acceptance/topic-routing-quality/goal.md。

## 目标与证据

- 基线origin/main=350d8d7c（含#338/#339），工作分支worktree-first-reply-latency。
- 首次答复须说明真实接纳/进度，不用提前发无信息“收到”替代，不等待业务执行完成。
- 上午5条首次答复：receivedAt→deliveredAt均值93.648秒、中位88.336秒；路由及交接25.636秒，事项决策至入账42.093秒。
- 最终决策调用均值28.474秒，首个可观察流事件6.631秒，参数流输出21.199秒；输出1096至1601 tokens，实际群回复63至174字符。流阶段包含服务端与传输，不冒充纯推理。
- 首个决策轮次均请求Task资料，平均模型响应5.620秒；UPR返回约4.7万字符、request字段约2.6万字符，不能未经核验就断言其中无有效合同。
- 空Topic查询已被必填schema和提示禁止但仍出现；错误各携带约5225字符候选，不能仅加相同提示。

## 方案选择

1. 仅压输入/改提示不能移除长参数输出，不作主方案。
2. 立即合并两级扩大来源、跨Topic及接纳合同变化，不作本轮起点。
3. 采用精简模型传输协议、Host完整展开校验，前置必要资料、摘要不阻塞首回；保留两级职责与规范账。

## 不可变边界

- 请求身份、群、Topic、revision由当前会话冻结绑定；过期、跨群、其他请求引用照常拒绝。
- 模型明确决定来源范围、事项、动作、增量要求、真实合同变更、同事项回复/替换和收件人；Host不猜语义。
- 短引用必须指向Host已提供/确实读完的冻结对象；快照引用不等于已审，漏页或候选变化仍拒绝。
- 展开为现有完整route/decision/operation审计数据后，沿原校验、幂等与恢复；旧成功账不重判/重放。
- 不弱化消息version/epoch、Unit来源守恒、Task版本、授权、唯一回复归属及通知去重。
- 兼容调用与测试逐项明确；持久旧数据不改成短引用，历史冻结函数不加入新行为。

## 一级初诊与有界批次（2026-11-05，SG7实施前快照）

用户新合同：初步回复前移一级；分诊尚未完成时新来源继续进入同一会话，每批最多15条，溢出下一批；同批可涉及多个Topic，逐Topic分别引用对应原消息回复。初诊只能表达初步理解、尚缺信息与下一步，不给原因已确认、已执行或已完成的结论。二级保留Topic业务决定、真实Task动作与后续事实反馈，不重复一级同源同版本的初诊。

当前源码证据：一级已曝光目录及相关Topic的有界摘要、摘要版本与未汇总标记，不能等同完整历史；在途route仍冻结来源，原选批最多50且required来源可绕过数量预算。真正保留request对象的追加在二级；会话控制器目前等待idle再steer。一级提示/结构禁止群回复；二级出箱依赖已接纳decision与业务动作。既有通知引用校验只对传入participants有效，不能自动保证多Topic各自引用正确。

方案比较：仅提示或首包slice到15不能约束真实接纳与在途追加；每来一条重建request会换会话和通知身份；采用现有一级request/原生session/持久出箱的必要增量，保留两级且不增加独立ACK模型调用。SG6候选部署已暂停，本轮解除开发源码冻结；旧包和旧测试结果不得作为SG7新源码通过依据。

实施合同：

- 在消息进入request前执行15条不同来源的硬上限。普通恢复原来源/答复组合计入容量并优先共同入批，放不下的普通组合留下一批；若当前有效恢复链本身超过15，采用下述有版本证明的分阶段路由，不要求整个连通组件原子提交。溢出来源保留pending排下一批，不仅截断模型显示，不要求当前批覆盖所有pending。
- 活跃一级保持同一request/session，追加同步真实来源/version/epoch与曝光材料，通过原生steer在处理中消费更新。批次修订及已消费更新保护与提交处于同一责任层；旧输出不得落路由或回复，不为新消息延长到无界批次。
- 模型仅提交结构化初诊草稿；Host沿真实路由结果将每份草稿绑定对应Topic/unit、原消息及版本和作者。新Topic仅在真实创建后绑定，不能猜ID；同一原消息拆多个Topic时初诊允许逐Topic，业务effectOwner/Task授权不因此改变。
- 复用持久出箱、审阅、发送许可和送达回读。初诊身份须区分批次、Topic和阶段，避免现有sourceMessageId去重吞第二话题或随steer重发。路由提交/初诊持久化/二级可见性必须有明确恢复顺序；二级不得在不可见初诊时抢先重复发同份初诊。
- 初诊允许先于二级决定/执行完成送达，不宣称Task已创建/启动/修好；职责外继续静默，真正缺口沿既有有界澄清，不用泛泛“收到”降低指标。初诊不替换既有实质结果，starting/unknown只核原账，已送达不重发。最终Task通知quote:false合同不变。
- 已证失效边：同一答复改变引用后可能遗留旧恢复边，16条组件会使当前选批throw中断同群工作。Store按当前真实引用及可信送达证明失效旧关系，保留来源pending/历史和同ID有效补充关系；既有群恢复/路由入口处理已持久旧边，不扩全库迁移或新API。已送达问句仍按精确delivered ID/sourceRef/proof验证，不能按正文或ID字符串猜测。
- 有效链反证与取舍：晚到quote富化可形成全部当前有效的16节点引用链，仅清失效边无法解决。保留硬15及旧全组件原子性无合法批次，放宽15违约、永久throw/skip饥饿；采用有界分阶段路由。跨批直接恢复依赖只作上下文真实曝光/读完，由Host冻结当前messageVersion/epoch及可信关系、Store锁内重验；未读或漂移拒绝旧输出。溢出来源本身仍pending，无该来源的route/reply/Task副作用，后批可读取已路由依赖但不重复处理。仅增必要的边界快照/消费证明，复用原分页和CAS，不新建通用图调度。
- 单元与真实隔离Native覆盖：运行中同会话消费追加、15/16与恢复组合容量、溢出不丢不重复、多Topic各自精确引用及独立送达身份、旧修订/来源变化拒绝、重开/unknown/已送达不重发、二级不重复初诊且新增事实可正常反馈。脚本provider的固定文案只证明协议与传递，不当真实模型语义/实际钉钉或60秒性能验收。
