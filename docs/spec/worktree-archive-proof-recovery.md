# 归档提交与已删除文档核验

现状：旧任务归档要求同名远端分支 HEAD 完全一致。没有开发提交的调查分支即使基点已包含在远端 UAT 分支中也被误拒绝。另一个旧任务的目录及 Git worktree 记录已删除，登记的 11 份文档仍在登记 HEAD 的 Git 对象中，但缺少归档路径/摘要，因此恢复入口拒绝。

方案：清理前以 origin 实时公布的分支头证明登记 HEAD 等于或为其祖先；仅用本地已有 Git 对象验证，不 fetch 或改引用，缺对象无法证明则拒绝。脏代码、未登记文件、身份、跨任务占用门禁保持。已删除目录只从准确登记 HEAD 的普通文件 blob 恢复，写到现有任务专属归档路径，逐字节冻结 SHA256 并回读；不从同名工作区文档猜来源。目标冲突、缺 Git blob、符号链接或不一致已登记摘要拒绝，checkOnly 不写文件或元数据。

验证：远端分支已推进、源分支删除但提交仍在远端、远端改写且无可证明提交、未推送及脏代码；已删目录的 tracked 文档精确恢复、二进制字节、零写预检、目标冲突、缺源拒绝；相关 Runtime 定向测试。通过后 PR 合并和本地安装回读，再对两项实际任务预检并从正式归档入口执行。
