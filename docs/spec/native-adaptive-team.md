# DSH 原生执行团队按需拆分

## 目标与现状

用户撤回至少3名、最多10名执行会话要求，要求先保证DSH原生会话正常，由统筹按实际情况拆分。基线为新鲜 origin/main 12f13e0；此前Claude认证/原生Teams接入候选和证据留在原工作树，本轮不混入交付。

现有约束同时位于统筹system prompt、提交工具description、task-session完成校验及Store执行创建上限。只改提示词仍会拒绝少于3人的complete或第11个成员；只删Host门禁仍会诱导模型凑数。因此一并移除固定人数要求，继续使用既有动态委派和执行身份，不引入人数配置或新调度模型。

## 实施与边界

- 统筹按复杂度、可独立完成性、依赖、共享写入和拆分成本选择直接处理、单执行或多执行；就绪独立工作可并行，后续复用原成员，不为人数新增职责。
- 删除团队最少人数完成条件和新成员最多人数门禁。保留同一执行单飞、已配置并发容量、资源互斥、需求/控制版本、未知效果与排空校验；人数不等于同时运行进程数。
- 保留本轮职责交接、阶段报告、每轮独立文档与旧轮冻结、消息通信和按风险核验。
- 保持DSH默认后端，不删除已发布的可选CLI代码，不修改现有任务后端或历史账本，不触发真实业务消息。

## 验证和交付

在既有Store与原生Host测试中验证零执行可完成、1/2执行成果齐备可完成、超过10人可登记运行、原成员续办及逐轮文档保留，并用未排空/未知效果/同资源互斥反例证明保护仍在。只运行受影响回归及release-smoke，先读真实测试结果再交付。主检出和旧Claude候选保留；按既有PR、部署runbook及用户授权收口，不启动CI。

每位执行人的R18职责和结果分别写在本验收桶 round-18/；唯一权威目标随本轮转移到当前工作树 docs/acceptance/task-collaboration-quality/goal.md；旧入口只保留指向，不维护第二份状态。
