# 群聊回复使用业务语言

现状：固定回执直接包含执行会话、规划错误码和原始状态；问答、负责人摘要和旧群聊路径也会生成公开正文。

目标：群成员看到已做的工作、结果、限制和需要确认的问题；内部编号、调度术语和诊断保留在内部记录。

方案：复用 workflow-notifications 提供共享提示与窄范围正文校验。只检查公开正文，模型提交失败可修正；发送前拒绝明确的插件内部标签/机制，不自动删改已准备消息，保留幂等与回读一致性。固定回执翻译状态并省略诊断错误码。调查阶段内部摘要不受公开正文限制，避免损失后续调查依据。

验证：正文禁止项反例、业务代码与链接正常例、原生问答与负责人提交、通知恢复和工作流相关测试。未授权真实群发送与部署，本轮仅本地验证并提交 PR。
