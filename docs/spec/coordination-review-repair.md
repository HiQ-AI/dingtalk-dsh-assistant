# 协调层审查问题修复方案

基线：2026-10-22 fetch 后 main `3d7a188`。范围依据两轮审查及用户“修复上述两轮发现的问题”。仅修复源码、回归与文档，经本地验证后创建 PR；不部署、不发送真实钉钉、不触发 CI。

## 问题与设计

1. R1 历史 schedule 定义缺稳定身份：实例化保留接纳定义与 scheduleId，测试 future 修改后当前及下期均可执行。
2. R2 ready 指令重排遗留旧 Owner 评估：以新 revision 替换评估并保留已开始执行的边界，不接受旧 assessment 回执。
3. R3 局部取消 applied 指令阻断原 Task：取消的安排约束退出未来门禁，保留历史效果与其他活动约束。
4. R4 固定前 20 个作业饥饿：维持处理预算而保证跨扫描公平，暂停/等待项不能永久阻断后续任务。
5. F1 时间与只观察前置任务组合：观察项不成为执行动作；到期后仍须当前正式完成证明，周期实例必须正确关联依赖身份，不能对 A 补输入或 reopen。
6. F2 查询丢失异常事实：复用权威 snapshot，统一格式化计划、执行结果、等待/失败原因与可用标识，包含必要时间信息。
7. F3 无成员的过期查询不通知：接入现有聚合通知与发送许可，不为失败伪造成功结果，不重复通知、不重放 unknown。
8. 修正 README 旧架构叙述；修复 Windows 强制退出用例的退出信号断言，使后续恢复断言实际运行，不跳过用例或削弱持久恢复检查。

## 验证与反证

将既有审查反例转为正式回归，补相邻正常路径：未修改计划、非观察成员、依赖前后两种时序、旧 Owner 评估拒绝、其他依赖保持、跨安排公平、过期通知重启不重复、许可后未知不重放。
先运行分组定向测试，再串行运行相关 native profile 和共享通知/账本合同、测试分类校验；按实际风险选择 release smoke，不机械跑全量。记录到 acceptance 下 matrix.csv 与每轮记录。实现阶段不修改历史审查结论；最终新增修复结果说明。
