# 问答与项目排查的 Agent 执行方案

日期：2026-09-27。检查基线：main `06a2955319e4fffa14dc7f69c08e1bcbf1841f8f`。状态：已核验现状，待实施。本文是新范围方案，不追改历史实施快照。

本次方案范围包括普通问答、项目问题排查分析，以及妨碍 Agent 自主执行的已有编排调整。用户已明确允许在实施中删除或调整受影响的既有流程；应按下文去留表落实，不以保留旧流程形式为前提。当前仅更新方案，尚未删除流程或修改运行实例。

## 2. 方案选择

1. 给 I/IB 开工具：不采用。身份关联和意图判断同时执行查询，将扩大消息判断重试的职责，并混合控制判断与业务执行。
2. 为项目、代码、数据库分别建立问答 Workflow：不采用。领域差异主要是工具和授权范围，固定阶段会继续把一次搜索、参数调整变成流程切换。
3. 复用原生 Agent 会话，支持消息事项和任务节点两类执行归属：采用。普通问答直接进入会话；已有工作流继续负责确有阶段交付要求的任务。共享执行基础，保留各自业务控制器，不新建第二套调度框架。

## 3. 最终路径与职责

消息 → S/R 解析与关联 → 意图选择处理方式 → 消息所属 Agent 会话 → 结果持久化 → 既有通知链路 → 引用回复。

意图判断输出用户要解决的问题、话题及必要范围，不提前生成需要调查的答案。Agent 根据材料是否充分决定直接答复或使用工具；有材料的一句话回答也走同一问答执行入口，不由两个不同层分别承担最终答复。

任务状态查询仍使用权威控制账。明确的开发、写库、部署等工作继续进入已授权任务流程。需要项目查询不自动等于需要工程任务，也不因查询时间较长自动创建业务 Task；只有明确的持久交付目标或阶段约束才使用任务。

Agent 负责检索顺序、查询条件、阅读结果、可处理错误的纠正和答案组织。Host 负责来源身份、工具范围、持久化、预算、取消、版本检查和送达。话题用于提供事实与近期依据，不作为一个永久增长的执行会话。

## 4. 框架修改边界

### A. 把会话执行基础与 Task 身份解耦

从 execution-session.js 抽取实际共用的原生创建/恢复、工具安装、预算、取消、排空、结果提交能力。执行归属采用受信 Host 提供的明确类型：message unit 或 task node；两者都有稳定执行 ID、输入版本/摘要与 lease。任务控制器保留自己的身份与提交规则，消息控制器提供消息事项的身份与提交规则。

不能使用虚假的 taskId/nodeRunId 借道，也不能将所有身份字段简单改为 optional。新消息执行通过既有控制账命令和查询持久化会话绑定、状态、产出引用；只增加缺失记录，不另建平行任务库。需增加 schema 时按现有版本迁移机制执行，旧任务会话身份原样保留。

### B. 统一受信能力向 Agent 暴露的入口

复用能力注册，按 Agent 自身职责、项目/环境和现有授权选择可用工具，群成员仅作为请求来源。能力合同声明参数、范围校验、执行、结果来源和错误类别。消息会话和任务节点共享该安装机制。

接入项目资料读取、仓库目录/搜索/文件读取、数据库元数据与只读查询，并为项目排查提供日志、配置、部署版本与运行状态读取。按项目实际登记这些资源及权限；未接入的能力明确标注不可用。仓库读取目前依赖工程任务绑定，需要由 Host 将明确仓库和版本解析为只读作用域，不能伪建工程目录。数据库工具须使用实际只读身份及数据库侧限制，配合超时、行数与输出限制；不依赖 SQL 字符串前缀证明只读。数据库连接由 Host 管理，模型只使用逻辑资源标识。共享 UAT 数据库与各 UAT 部署代码版本分别记录，存在歧义才询问。

不把终端或带写能力的整套工具直接交给普通问答。超出 Agent 读取权限、能力未配置、资料不存在分别返回真实原因，不伪装成已完成查询。

### C. 一次会话内处理正常查询反馈

现有 tools/result 对一般 isError 停止会话，需形成共享的错误分类合同。可修正参数、无匹配结果、受限的瞬时查询失败作为反馈供 Agent 继续；越权、身份失效、取消和无法确认的外部效果由 Host 终止或挂起。恢复次数和时间计入同一次执行预算。

分类由受信工具实现给出并经 Host 执行，不让模型决定是否忽略权限错误，不在中心控制器按项目名或一串错误码不断加分支。

### D. 结果和结束条件

执行结果包含：答复正文、实际证据引用、资料时间/版本、已知局限，以及是否确实需要用户补充。来源元数据由 Host/工具产生，Agent 不能自造引用；Host 验证引用可访问且属于本次授权，但不把引用存在等同于自然语言结论必然正确。

“已查询但无法确认”可以是已完成的调查答复；“缺少哪个环境，无法执行查询”进入等待并保存问题；工具不可用记录执行受阻。正文产生、执行完成、通知送达分别记状态。问答结果最终仍走原通知准备、送达回读和幂等机制，Agent 不直接发送钉钉消息。

### E. 连续消息、取消与恢复

一次具体问答执行拥有会话，同一问答的必要补充继续该执行；新问题建立新的执行，并从话题检索相关事实和证据。不同发送者使用同一 Agent 职责范围和资源权限；来源身份不作为资源授权依据。

输入修订/取消先使旧执行版本失效，终止并排空原会话；旧结果不能覆盖新问题。补读、重启、重复事件恢复到原执行与通知身份。恢复身份或句柄无法确认时明确受阻，不新建替身假装续接。

### F. 页面展示

复用消息处理详情展示“正在查询、待补充、已答复”、耗时、答案及证据摘要。工具事件按需展开，查询几次不决定顶层步骤数量。普通问答不进入业务任务列表；原始会话按需查看。

## 5. 项目排查分析的执行方式

消息问答与调查任务共用同一 Agent 执行基础和能力注册。是否建立业务任务，由用户要求的持续跟踪、独立产物、阶段交付与授权边界决定；不按“是否需要查询”、运行分钟数或工具调用次数机械分流，也不见到“排查”二字就创建任务。

| 请求形态 | 执行归属 | 结束与后续 |
| --- | --- | --- |
| 解释某接口、代码或数据异常 | 消息事项直接执行 | 查清并回复，或说明已查范围及无法确认的原因 |
| 持续排查一次故障，交付根因和修复方案 | 调查任务中的一个 Agent 执行阶段 | 按目标交付调查产物，由 Owner 核对要求；需要后续开发时交接 |
| 排查、修复、验证并提测 | 持久任务，按实际交付分阶段 | 调查与方案 → 修改及本地验收 → 明确 UAT 的提测；遵守用户指定的确认点 |

调查会话自主完成读取现象、收集证据、提出假设、寻找反证、调整检索及查询、比较版本、整理原因与方案。它们是会话内动作，不各自生成 Workflow、Stage 或 Owner 规划轮次。仅分析时无需工程 worktree；隔离复现确有必要时使用登记的执行能力，并明确资源和写入范围，不因“排查”获得修改共享环境的权限。

调查产物包括：问题及影响范围、查询的环境/版本/时间范围、事实和来源、候选原因及支持/反驳证据、已确认或未收敛的结论、修复建议与验证方法。要求文档时保存文档工件；短问答直接形成可回查的答复工件，不强制生成方案文件。

完成判断跟随用户目标。若要求“依据现有信息给出分析”，交付有边界的结论可以完成；若要求“查明并修复”，原因未确认或修复未验证时不能宣称完成。还有已授权可行查询就继续执行；确实缺输入才等待；能力故障明确记受阻。不能仅因存在 limitations 就让整个任务一直等待，也不能用“无法确认”绕过尚未执行的必要调查。

进入后续工程阶段时，交接目标、证据、方案和未解决项的工件引用。后续会话按实际版本复核，不能把调查建议当作修改已完成或测试已通过。没有开发授权时只交付方案，不自行追加修改。

## 6. 现有编排的去留与迁移

下表依据当前 taskWorkflowCatalog、task-readonly-workflows.js、task-general-workflow.js 和 workflow-service.js。删除针对已被共享执行机制替代的新请求入口与多余调度，历史记录和正在执行的身份需按迁移规则处理。

| 当前部分 | 方案决定 | 实施后职责 |
| --- | --- | --- |
| S/R、I/IB 消息判断 | 保留并调整合同 | 解析、关联与分流；移除生成最终 answer.text 的职责，不开放调查工具 |
| answer 直接返回 text | 替换该执行路径 | 接入消息所属 Agent 会话，结果接纳后走原通知链路 |
| research 一律 createTask | 删除一律建任务的绑定 | 按交付需求选择消息执行或持久任务；调查动作本身不作为建任务条件 |
| task-analysis 材料分析 | 从新任务可选编排中退出 | 材料分析成为共享 Agent 的能力使用方式，保留必要的证据规则 |
| task-investigation 问题排查 | 改造为真正的调查执行阶段 | 一个带工具的 Agent 会话自主排查；替换仅接收 materials 的 prepare/assess/validate 空壳，保留有意义的结果接纳和任务验收 |
| task-planning、task-pr-review、task-data-query、task-retrospective | 合并重复的只读执行骨架，从新请求目录退出独立固定流程 | 保留方案、评审、数据口径、复盘的专业指引和产物合同，交给共享执行阶段；需要独立阶段交付时由合同定义边界，不再为每个标签复制相同编排 |
| task-general 固定 plan-N/execute-N 循环 | 退出新请求执行 | 搜索选择、查询和调整在 Agent 会话内完成，预算由共享执行基础约束 |
| task-general-capability 每次只读能力一阶段 | 删除调查场景的这种调度方式 | 只读能力作为会话工具调用；其已有文件写入等效果能力仍按原授权、执行、核验和对账合同处理，不随只读迁移一起放开 |
| task-general-intake | 核查并移除无独立产物的占位阶段 | 必需的需求接纳与校验归 Task 接纳边界，不为进入通用执行再创建空阶段 |
| Task Owner | 保留，收缩调查内部调度职责 | 管理持久目标、真实阶段、授权等待与交付验收；不为每次读文件/查日志反复规划 |
| 工程开发、本地验收、UAT 合并部署、main 合并、生产发布、数据变更 | 保留必要编排 | 继续承担独立产物、权限、验收和外部效果边界；接收调查工件，不强制重跑材料分析流程 |
| 控制账、Artifact、会话身份、预算/租约/排空、通知对账 | 保留并复用 | 承担共同可靠执行职责，不随业务编排合并删除 |

新请求只保留一个权威入口和一套能力调用机制。不能在新 Agent 路径失败后静默退回旧材料分析流程，也不能把旧固定流程藏在“通用工具”后面继续逐步调度。

### 调整判定与交付要求

逐个阶段按实际职责判断去留：只有提示词不同、没有独立产物或授权边界的阶段并入 Agent 指引；为了读文件、查询数据或修正查询条件而设置的阶段退出调度；承担独立交付、权限或外部效果核验的阶段继续保留。项目排查不因涉及多个仓库、数据库或多轮查询而自动拆成多个工作流。

实施清单必须记录每项旧编排的替代入口、专业规则迁入位置、活动实例处置结果及最终删除位置。仅从页面隐藏或目录移除不算删除完成，还需检查注册、Owner 可选项及恢复入口，避免新请求仍可绕回旧路径。未盘点的历史实例不能直接套用新定义。

迁移顺序：

1. 实施前清点被替代流程的注册、可选目录、Owner 提示、配置、完成合同、接口投影、文档，以及真实运行实例中的活动引用；形成具体删除/改造清单。
2. 接好共享执行与真实能力，再切换新请求的路由和阶段目录，同步清除重复提示与调度入口。专业指引和证据检查先迁到新合同，再删除旧副本。
3. 停止受影响的新输入接纳并排空在途执行。已完成历史保持原记录。被替代流程仍有活动任务时逐项确定：按原冻结定义收尾，或记录停止与替代执行关系后从已确认产物继续；不改写历史为新流程成功，也不重放已发生的外部效果。
4. 历史展示所需的读取合同与新执行注册分离。只有活动引用归零、恢复验证通过，才删除对应旧执行实现；过渡支持范围限定为盘点出的存量记录，不建立无限期双轨运行机制。
5. 部署保留对应代码、配置和状态备份。回滚使用配套版本，先处理新执行的在途状态，不用只回退代码来解释新状态。

## 7. 实施顺序与验收

1. 先落实共享会话执行与能力安装合同；用现有任务节点确认身份、权限、取消、提交和重启行为未退化。
2. 接入消息问答执行及结果合同；新输入不再由 I/IB 生成业务答复，已送达的旧记录保持历史事实，不重放。切换前排空在途消息；存量未完成命令明确升级或完成旧合同，不能静默猜测两套参数。
3. 接入问答与项目排查所需的真实只读能力，完成授权范围验证；共享调查执行阶段接入 Task Owner，支持独立调查和后续工程交接。
4. 按第 6 节清单切换并收口已有编排，更新界面、目录、配置和建设手册，再部署运行实例。
5. 在独立测试群验证以下案例，真实数据库验证需要明确可用只读连接，不用假工具通过替代实际接入。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 现有材料即可回答 | Agent 答复，0 个业务 Task，不要求工具调用 |
| 项目资料问答 | 会话实际读取资料，回复包含可回查依据 |
| 代码行为问答 | 实际搜索并读取指定版本代码；修正一次错误路径仍在原会话完成 |
| 数据库问题 | 实际只读查询，返回范围与依据；越权和写入反例被拒绝 |
| 合理查询仍无法确认 | 如实回复并结束，不永久等待 |
| 环境缺失与补充 | 只询问必要信息，补充后继续同一执行 |
| 连续消息与发送者差异 | 复用相关话题事实，Agent 资源权限不随发送者变化 |
| 取消、重启、重复补读 | 无旧结果覆盖、无重复回复，绑定和预算可核对 |
| 需要改代码/写库/部署 | 明确交给对应任务授权路径，不由查询工具执行 |
| 跨代码、日志与数据库的项目排查 | 一个调查会话实际收集多源证据、寻找反证并交付有依据的结论，不按查询次数生成阶段 |
