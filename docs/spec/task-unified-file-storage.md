# 任务文件统一收纳方案

日期：2026-09-29。状态：方案讨论，未实施、未迁移。用户确认：原始会话目录保持现状；其余任务文件集中管理，避免引入额外存储体系。

## 范围

每个逻辑任务一个固定目录，集中输入材料、工作文件、中间产物、工程源码副本、验证记录、临时文件和交付物。

DSH 原始会话日志继续由现有持久化后端管理，保留存储 root、布局规则、日志格式和读取恢复机制；不搬迁历史日志，不向任务目录复制一份日志，不修改 DSH 存储后端。宿主公共附件存储保持现状，任务实际使用的输入文件按需保存到任务工作目录。

## 目录

```text
<Agent工作区>/tasks/<logicalTaskId>/
├── work/       # 输入材料、源码、草稿、脚本、中间产物、验证记录
├── tmp/        # 临时文件
└── outputs/    # 正式交付物
```

复用已有 task.family.rootTaskId 作为 logicalTaskId，不新建业务任务身份或目录映射表。路径由现有 Agent 工作区和稳定 ID 确定；同名任务互不混用，改名不搬目录，重跑继续使用同一任务总目录。

子目录按需建立。多次执行使用现有内部 taskId 区分；并发节点、工程修复代次继续用已有 run/node/generation 身份隔离。普通任务不预建完整层级。JSON 工件可放在 work/artifacts，输入材料可放在 work/inputs；沿用现有摘要和文件命名规则。

## 必要改动

1. **统一路径计算。** 在现有目录辅助实现中增加任务目录计算函数。调用方传入受信逻辑任务和执行身份；各组件复用该函数，不依赖模型自行选择目录。保留路径越界和链接检查。
2. **任务工作目录。** 新建任务 Owner、执行节点及子代理使用任务工作子目录，验证 Agent 指引仍正确加载。子进程明确传 cwd；任务临时目录通过该进程的 TEMP/TMP 等原生参数传入，不修改进程全局 cwd 或系统环境。新会话日志仍由 DSH 按原有规则存到既有日志根，历史会话恢复不改其 cwd。
3. **现有写入入口接入。** 工程目录、构建与本地验收、文件生成、Markdown 写入、下载、截图及命令日志都接收任务目录。受管仓库内只保留源码和构建所需文件，旁路产物放在 work 的其他子目录，避免进入候选树或提交。
4. **工件及交付路径。** 任务 JSON 工件进入 work/artifacts，正式交付文件进入 outputs。沿用已有 descriptor、摘要核对、效果账和下载/发送入口；任务工件读写显式传入任务作用域，不按摘要全盘猜位置。非任务消息工件仍保留原存储，任务采用的来源材料按原授权读取并保存必要快照。
5. **保留执行历史。** 新执行不能覆盖旧文件；当前有效产物由现有任务及工件记录判断。重启仍根据原任务身份定位目录，归档保持现有语义，不自动删除文件。

文件路径用于收纳，不改变文件读取权限、交付授权或任务完成条件。不增加 task.json、交付索引、文件管理平台、新看板或自动清理系统。
