# 统筹主动判断执行方向

## 问题与目标

2026-10-20 两轮任务的 39 次巡检均提交 wait。读取真实日志已经生效，但原指引把纠偏重点放在重复已验证工作和不必要步骤，容易把巡检降为进展复述。用户要求统筹负责整个任务的执行和进度，首次发现方向偏离就及时纠正；人工等待不是本轮问题。

可验证目标：每次巡检对照最新整体目标、受托目标、范围及验收要求，检查实际动作是否在推进当前必要结果；首次走偏即可向原执行反馈，后续以实际行为核验纠偏效果。必要验证、正常等待及证据不足不能被误判为走偏。

## 方案与边界

- 修改现有 task-session 运行时指引、工具说明及巡检唤醒说明。覆盖对象/范围错误、遗漏必要验收、前置依赖未满足、忙碌但不推进目标等情形，不等待重复错误或下一次巡检才处理已确认的偏离。
- 使用原 task_delegate(executionId, feedback=true, key)，反馈包含当前要求、偏离证据、下一必要动作与核验结果。原目标、授权和执行身份不变；真正需求变化仍走原修订机制。
- 用既有 summary/evidence/limitations 记录方向判断和下一检查点；不增加业务阶段枚举、关键词判别器或另一套审批/决策表单。Host 能验证读取与投递，不能代替模型判断语义。
- 先查已有反馈，不重复未消费或没有新证据的相同意见；已进入模型步骤不等于纠偏完成，后续核查实际行动。新证据显示仍偏离时继续调整指导。
- 十分钟周期、人工等待、暂停、未知效果及原生在途操作边界不变。反馈在安全模型步骤进入，不承诺立即中断正在执行的工具。

## 验证与交付

先运行现有真实 SDK 巡检/反馈用例作为基线，再扩展首次偏离和正常等待反例；另用真实配置模型在隔离、无外部写能力的固定场景中检查方向选择与反馈内容。场景不能只要求模型返回预设答案。确定性测试证明链路，真实模型样本只能证明本轮观察结果，不能保证以后每次都识别正确。

同步 README 与运行核验指引；运行定向测试后以新 feature 分支开 PR，不触发 CI。只有取得实际安装和运行证据后才声称已部署。
