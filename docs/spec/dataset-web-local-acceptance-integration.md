## 接入步骤

1. 分别登记两项目的固定依赖准备、构建和启动配置；账号与连接秘密保持在仓库外。
2. 明确选择 uat1～uat9 后登记实际 SSO、后端及按场景需要的其他服务地址，不通过拼接域名推测连接。
3. 前端任务启动本地前端候选，记录其依赖的明确后端身份；前后端联合修改时须同时绑定本次两侧候选，不能把旧 UAT 后端结果作为新后端修改的证据。
4. 复用固定 API／浏览器执行器，由任务提供业务步骤与断言。执行地址限制在已登记目标；浏览器使用独立上下文，不能注入页面内部数据或权限伪造验证。
5. 为创建的数据库记录、文件对象和异步操作登记任务归属及真实 ID；按账本清理并独立回读。现有草稿删除接口仅软删且保留文件快照，不能直接产生清空回执。
6. 基础配置可独立准备；具体任务缺乏可验证条件时才针对该缺项询问。不得把基础配置缺失长期留给用户补办。

## 现有材料复用限制

- `vue.config.js` 已支持显式代理覆盖；目标是回环地址时自动剥离 `/api/dataset` 等前缀。直连后端不能照搬网关 URL。
- 前端 `.env.development` 默认指向 UAT1，当前源目录没有 `node_modules` 或 `.env.development.local`；新候选须自行安装依赖并显式设置代理。
- 受信测试账户文件存在，Host 应选择专用验收账号；不在文档复制账号或密码。SSO 登录可能影响同账号已有会话，不能随意使用共享个人会话。
- 历史脚本存在固定环境、旧资源、缺少 finally 清理、复用浏览器页或注入页面数据等行为，不能原样登记为通用业务验收器。
