# 消息处理步骤与判断结论

## 目标与选择

用户明确优先看清处理步骤与判断结论。现状为节点时间列表和折叠 JSON，原文、业务结论与阻塞位置缺少主次。选择中文纵向步骤记录：顶部原消息与当前处理状态，步骤内直接呈现拆分事项、话题关联、意图动作及限制；技术输入输出折叠。排除仅翻译状态（仍需读 JSON）和自由画布节点图（多事项时增加阅读成本）。

## 实施

- 复用 TraceDetail、readout、现有状态与接口。trace 补充原消息字段，分页时不依赖当前页是否包含 S。
- 状态和动作采用中文标签；未记录不推断。按真实记录顺序编号，材料与重试保留各自记录，不把多事项伪装为一条线性依赖。
- 页内阶段数量只表示记录数。处理结束不表示任务完成或消息送达；命令接纳与渠道回读分开。
- 未知历史结构保留原始详情。阶段失败、不确定和待材料优先展示。默认无 JSON 和执行 ID 堆叠。
- 中文桌面与 390px 窄屏、键盘折叠、未知状态、长文、多事项、分页及错误态定向验证。

## 设计约束

本页是运营看板。保留 DSH 运行时主题、Button/Pill 组件和现有字号；用左侧步骤序号与连接线表达时间顺序。无品牌改造，无新的业务写操作。设计上下文依仓库产物规则放 docs/manual/observer-design.md。

## 连续消息和耗时

同话题同批次的共享判断仅展示一次，列出参与消息、发送人、时间，高亮当前消息；可切换到同批其他消息查看其拆分和关联过程。每条决定按输入 unitId 对应事项；不同批次保留独立记录，不因相邻同话题强制合并。trace 接口仅返回同群来源消息。

每步耗时使用持久 startedAt/completedAt，本次重试以 leaseEpoch 标记。无时间、倒置时间显示未记录；进行中以页面时钟显示已用时，手动刷新回读真实状态。不以 createdAt 代替执行开始，也不重复相加共享判断或声称纯模型时长。
