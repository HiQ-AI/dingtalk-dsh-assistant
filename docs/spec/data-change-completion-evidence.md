# 数据变更最终验收证据交接

## 当前事实与目标

原#857插件批准后已有TaskRun901，Bytebase只读回查DONE；原数据变更阶段成功，但最终产物仅包含资源ID、SQL摘要和生产列摘要。负责人再次安排调查，调查仅具数据库读取能力，无法获取工单/审批/执行原始证明，最终以能力缺失受阻。

目标：沿原生阶段合同把已成功节点的原始证明交给负责人及最终验收，严格核验审批与执行身份和先后绑定，在同一任务恢复只读验收；不得重新建单或执行DDL。

## 排除与方案

已排除实际未执行：Bytebase任务DONE且TaskRun901存在。生产回查摘要不能独自证明执行批准；增加无边界的通用平台工具也不能代替原生执行证明绑定。

复用ownerContract.readArtifacts、当前成功节点工件、原生审批/效果账以及领域验收输入。仅暴露同Task/Run/代次成功节点引用，对准确SQL、目标、审批决定、执行效果和生产回查交叉核验。保留冻结历史产物，不改写旧节点输出；旧定义的合同恢复须显式保留版本语义。最终业务判定仍按原验收项，不新增业务硬条件。

## 验证与恢复

定向覆盖真实服务、节点交接、验收输入及篡改/跨任务/缺证明/拒绝批准/先后错误反例。部署按现有runbook，默认无历史副本、仅读取核验汇总。原任务沿受管恢复入口重评成功阶段和当前等待，独立回读完成状态与生产/Bytebase证据；群通知纠正后独立回读。
