# 工作流目录在插件设置页的展示

日期：2026-09-24。本轮修正已切换本地实例的配置页仍展示旧“任务流程提示词”的事实与界面冲突。

## 当前证据与目标

`client.js` 的 `TaskPromptEditor` 无条件出现，`/config/agent` 保存时总是发送 `taskPrompts`；这些字段属于旧叶子任务。新群的消息入口依据 `workflow-service.js` 的代码注册表和 Host 适配器准入，运行状态在 `/state/workflows`，但该接口尚不提供定义目录。用户无法从设置页分辨可发起流程、代码已定义但缺适配器的流程，或查看节点顺序。

目标：已切换群显示只读“任务工作流”目录；每个流程标明版本、准入状态和从实际定义取得的节点（若尚无可实例化定义，则明确说明）；消息处理 S/R/I 与任务节点分开展示。新任务卡片点击进入任务实例的节点详情，包含节点状态、等待原因、产出已记录标记和最终结果；模型节点的会话记录从该节点按需打开。旧任务保持原会话入口和原卡片进度。旧 `taskPrompts` 数据及 API 保留供历史/未切换群读取，不删记录、不触发任务。只有存在未切换群时才显示旧提示词编辑区；新群保存通用模型配置时不再无意重写它。

## 合同与交互

- 后端目录以 `taskWorkflowCatalog` 的业务身份为全集，以当前注册定义和受信 Host 配置判定 `available`/`unavailable`。`version`、`nodes` 只从该定义读出；无定义不猜版本或节点，不将代码文件存在解释为可执行。工程流程按任务及仓库冻结定义，目录只显示准入仓库；具体节点从任务详情 `executionNodes` 读取。
- 新增轻量 `GET /state/workflows/catalog`，不附任务正文、模型提示词、环境凭据或仓库路径。`/state/tasks` 的执行进度展示不改；新任务视图补流程 ID 和版本供详情识别。
- 设置页在 Agent 配置之外展示目录摘要和可折叠的节点清单；每项的状态用文字与颜色共同表达。未接入适配器时写清原因，不给开启按钮或“已执行”暗示。小屏纵向排列，键盘可展开，保留当前 DSH 色彩/字级。
- 旧版编辑区只对未切换群出现，并明确其仅影响旧引擎。隐藏后保存普通配置不提交 `taskPrompts`、版本或叶子专用字段，避免隐式覆盖。
- 看板卡片的进度图标和折叠区不改。`workflow-v2` 卡片即使排队且尚无会话也可打开任务详情；各模型节点仅在持有 `sessionId` 时提供辅助会话入口。旧任务仍直接进入原叶子会话。

## 验证

后端服务/HTTP 合同测试比较目录与注册定义、缺适配器反例；前端源码与构建产物测试确认旧控件条件展示和配置保存参数；本地原生包替换后回读精确文件哈希、目录 API、旧 68 个任务、Web 认证页并在真实浏览器查看桌面与窄屏呈现。不因浏览器连接失败声称视觉通过。
