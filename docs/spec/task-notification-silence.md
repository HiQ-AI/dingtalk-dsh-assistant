# 任务执行通知统一静默

用户要求所有任务流执行期间不主动汇报中间进度，调查失败和内部恢复也不构成群通知理由。当前通知器把 wait/block 全部归为 required_action，并从阶段成功、开始、承接及系统等待生成消息；只对 readonly-reassess 做例外，因此正常新需求仍外发。

统一按结构化事实决定是否通知，与工作流类型、恢复事件及正文关键词无关：承接、开始、阶段进展、执行/能力受阻和审批等待静默；最终结果、用户主动查询/控制的回执及明确业务信息/权限确认保留。插件私聊审批由原审批渠道负责，不再在群重复待审进展。状态、原因和诊断继续保存在看板。

准备通知和原生领取待发通知共用同一判定，升级前已 prepared 的中间消息原生置 superseded，已发送或未知发送仍只回读，不重发、不抹除账本。无需迁移或关键词屏蔽。

定向测试覆盖正常与恢复阶段、各等待种类、旧队列抑制、未知发送回读、完成与主动查询、真实私聊审批回归。按普通无备份部署流程安装 Assistant，独立回读运行包/PID/健康和本次删除需求；SQL业务测试结果与通知修复结果分别报告。
