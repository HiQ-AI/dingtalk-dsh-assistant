# 统筹正常结束但未提交决定的自动恢复

## 现状与根因

真实任务 task-c74a355e5506fd9b2ed6af998a14263d 的执行已提交 completed，统筹最后一轮却产生空 assistant/message 和正常 turn/end，没有调用 task_session_submit。task-session 返回 no_submission 后，service 将其保存为 blocked 并 ack 原 wake，导致没有后续事件可推动，必须人工补充输入。

反例：已提交的 wait、complete、人工申请都是有效决定；真实工具错误、认证配置错误、取消和租约失效不应因本修复自动重试。不能把执行完成直接当成整体任务完成。

## 修复范围

- 原生回合确实正常完成但没有提交决定时，产生 TASK_SESSION_NO_SUBMISSION 技术错误（phase=decision），复用现有持久恢复预算和调度器，保留原 wake 不确认消费。
- 原 session、任务与执行结果、操作账保持；恢复时明确要求核对已有结果后提交决定，不重放动作。
- 复用 5/10/20 秒及 10/30/60 分钟退避，连续七次失败后暂停自动重试；重启不清预算。有效决定优先，不额外调用模型。
- 不自动改写历史 blocked、不以猜测恢复真实错误；不修改执行模型协议、业务权限、数据库 schema。

## 验证

使用真实原生 Host、会话持久化及 SQLite，仅模型输出受控：验证一次空返回自然定时恢复、重启后同会话恢复、连续空返回预算上限、已经提交的决定不重试、真实错误及工具拒绝不误重试、已有执行结果和未知效果账不被自动重放。同步 README 和部署核验说明。
