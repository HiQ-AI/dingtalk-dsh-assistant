# 调查证据提交纠错与原任务恢复

现场：新删除列需求的查询返回 tasks/<taskId>/sha256-…，模型提交去掉任务前缀；校验器先读文件，ENOENT逃逸为致命execution_submission_rejected。原Task保留成功结构查询，但负责人只见通用失败，误判没有调查。

排除：正式文件确实存在Task工件目录；查询返回完整引用；部署及原生派发已恢复，故不是磁盘写入丢失或仍维护。目标列数据查询另有授权范围拒绝，不能混作证据文件故障或自动扩权。

方案：在证据读取前核对模型引用与Host已记录的成功查询身份，模型拼造/截短的引用属于输出纠正，反馈完整引用使用要求；真实已知引用文件损坏/消失、任务或权限变化继续拒绝。复用当前分类及同轮纠正，不猜路径、不补前缀、不搜任意目录、不吞ENOENT。只修改必要校验与反馈，保持冻结历史合同及原生恢复路径。

按既有runbook部署并通过原生节点/Owner恢复继续原Task。实际执行会话负责修正业务输出；不得手工把原输出置成功。必要预检后以新删除工单送插件真人审批，不复用旧加列审批。精确SQL批准前不执行；批准后独立查执行/生产及最终验收。所有中间群进度保持静默。

定向验证：真实原生会话先错引用后正确引用、跨任务/伪造/缺文件反例、覆盖排除/分页、已失败节点安全恢复；部署独立包/PID/健康；新工单和私聊送审/批准/执行分别回读。

同因范围：普通问答也从原生成功回执传入已签发引用集合，只核对模型实际引用，不启用调查的全部查询覆盖要求。前置材料引用仍按原合同接纳。
