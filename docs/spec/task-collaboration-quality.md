# 统筹拆分、交接与独立核验

## 目标与现状

用户要求优化任务统筹与执行协作，解决大多数任务初始只委派一个执行会话的现象。本轮基线为 origin/main 的 192e808，保留主检出未提交内容，在独立 worktree 实现。

现场只读样本中 18 个任务的首次委派轮均为一次 task_delegate 后 wait；这证明当前行为倾向，不能证明单一提示语是唯一原因。当前 task-session.js 只允许而未要求评估并行，且“派发后用 wait”缺少完成本轮可独立工作分派的条件。Host 已允许同任务多个执行，运行中反馈、资源互斥、阶段进度与巡检纠偏均已存在。

可验证目标：可独立推进的工作在同轮分派；串行依赖保留原执行身份；委派明确目标、已知事实、工作边界与交付证据；有风险的完成判断获得独立反证核验；运行成果和待验证声明不混淆。

## 候选方案与取舍

1. 强制每任务至少两个执行或固定实施→审查→验收流程：拒绝。简单任务及强依赖步骤会平添开销，并不能证明独立验收。
2. 新建 DAG、委派对象 schema、审查角色或资源锁：拒绝。当前动态执行、objective/context、resourceKeys 与证据字段可承载需求，重复机制会扩大恢复边界。
3. 改进现有统筹和执行指引，配合真实 SDK 合同与隔离真实模型场景：采用。先评估独立性、依赖、共享写入和验收风险；只对收益明确的工作拆分。提示无法保证模型每次正确，保留反例与模型样本边界。

## 实施范围

- 统筹首次与后续事件均评估尚未覆盖的独立小目标；在本轮完成所有已具备条件的委派后才 wait。存在依赖、相同写入资源或不可拆目标时串行，避免无意义会话数量指标。
- 复用 objective/context/skillNames/resourceKeys 描述可独立理解的交接，不假定执行会话共享聊天上下文。同一请求重试、同会话续办、运行中反馈继续沿原合同。
- 风险较高的变更或业务完成声明，优先安排独立会话审查具体产物/版本、验收与反例，统筹自行核查原始证据；简单任务可直接核验。独立核验是待产物就绪后的小目标，不与改写同一产物并发。
- 审计现有阶段报告、任务摘要和看板。已有能力以回归验证覆盖；只有确认信息丢失或误导时才改实现，不添加第二份状态账本。
- 不更换执行引擎，不接入 Claude Code CLI；该方案借鉴其任务拆分、上下文隔离和文件所有权经验。

## 验证与交付

使用原生宿主测试证明多委派、延迟完成、反馈防重、串行资源和会话身份不回归。隔离真实模型场景覆盖独立双目标、单目标反例、依赖阻塞、共享写入、复杂完成需核验及简单证据充分可完成；所有外部业务工具禁用，记录模型原始调用与源文件摘要，人工审阅语义。模型样本不能替代长期效果统计。

同步 README 和相关运维核验说明；定向测试与发行 smoke 通过后提交 PR，独立回读。普通开发不触发 CI。本轮不修改现场任务或部署运行实例，部署状态单独报告。
