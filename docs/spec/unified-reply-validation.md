# 统一引用回复与验收纠偏修复

## 问题与目标

用户要求把单位分组入口任务复盘中的三类问题与附件回复缺陷一并修复。当前部署证据、文件字节送达成立，但调查优先级失当、正常登录路径误用、验收假设造成返工，正文和两张截图又被拆开。修复范围是现有个人 skill、通用任务统筹和真实消息交付链，不能重新执行原业务发布或重发旧图。

## 已读事实

- `D:/project/dingtalk-dsh-assistant/docs/acceptance/unit-group-buttons-retrospective/` 保留原日志索引、45 条决定及 11 次巡检。巡检确有读取和判断，但首轮继续追网关，后续关键纠偏由另一个修复会话注入。
- 原登录脚本错误要求 login 响应 Authorization；真实浏览器 current 请求的认证头及用户 Cookie 才是本应用已核实来源。当前成功脚本已验证同身份 current → logout → current 拒绝，需抽取可复用能力与失败诊断，不能复制凭据。
- 真实截图曾因账号权限、Element UI 定位器、只读 POST 拦截失败；JSON PASS 与截图 Network Error 曾不一致。
- 当前 `group-file-delivery` 已改规范，要求正文和所有附件组成原生引用回复，但插件 schema、通知 payload 和 DWS adapter 尚未承载该组合。安装 DWS v1.0.63 的引用为纯文本；上游源码也固定 replyMsgType=text。不能猜测未公开的消息协议或宣称 mock 等于真实发送。

## 方案与责任

1. 核实 DWS 真实消息 Schema/原生平台支持范围，先确定可实现的引用正文与多资源表示。传输能力未证明前，不补造类型、不拆发降级。形成具体外部依赖边界。
2. 插件统一回复承载受信产物、正文、引用身份和发送身份；准备与发送分离，发件箱持久化、恢复沿原效果，不自动重放未知发送。复用现有任务文件与通知实现，读完当前结构后实施最小改动。
3. 现有 UAT 账号 skill 和验证辅助资源补正常登录/失败清理、当前权限预期、只读请求精确分类、脱敏的断言阶段/expected/actual；现有业务开发指引补调查依赖排序及实际视觉检查。不得添加不适用的全局授权门槛。
4. 统筹在第一次证据明确的偏离时主动反馈，关注外围取证、已有账号误判资源不足、JSON PASS 与原始截图冲突。保存每次决定/解释/证据；正常等待与维护不判错。用场景验证实际判断，不能只测提示词包含某句话。

## 验证与交付

定向测试覆盖成功及反例、路径/资源/账号/引用身份、重启恢复、未知效果不重复；技能结构与独立情境审查分开记录。只有获得真实传输支持且存在已授权测试目标时才进行真实发送，不用原群旧图试探。无真实发送证据时明确限制。普通分支推送/PR 不触发 CI，不擅自部署、合并或发消息。
