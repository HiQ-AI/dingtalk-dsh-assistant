# 执行会话真实进度巡检

## 整体进展与非终结阶段成果

详情页以统筹已有 `lastDecision.summary`、`at` 及需求/控制修订展示整体最新进展；新回合中保留最近已确认说明并标注非实时，旧版本说明不冒充当前工作。不新增整体进展存储或固定业务阶段。

动态执行可调用 `execution_report_progress({summary,evidence})` 报告可公开的事实阶段摘要及必要证据（最多2000字、4条引用，每条512字）。该工具不结束回合、不写最终结果、不发送消息，报告后继续原执行；同名继承工具不能绕过内部报告边界。

Host 使用原生调用ID去重，校验当前任务/执行、输入版本、需求/控制修订和租约，保存有序 `stageProgress` 并产生 `execution.stage.progress` wake。报告仅携带有界业务说明和证据，不注入工具参数或完整历史；原调度尊重取消、暂停和真实人工等待。统筹核对阶段成果后经原 `task_session_submit(wait/blocked)` 更新整体摘要，阶段成果不代表业务完成。

内容索引投影保留阶段摘要及证据、执行输入版本/digest/租约和当前 Provider 恢复决定；完整结果诊断仍经 `resultRef` 或执行目录读取。整体进展保留原 `lastDecision.at`，不因投影改变记录身份或恢复准入。

活跃原生回合的JSONL事件可能仍在缓冲中；巡检读取前通过公共 `sessions.flush` 刷新已有原生writer，再打开只读handle。没有第二writer、日志发现、动作重放或新增计时器。原身份/输入/租约验证保持不变。

用户要求：统筹与执行沟通上下文不能过大；每10分钟检查正在执行的会话真实进度、方向，不能把running状态当作执行证据。

已有修复：传递执行当前目标、身份/版本与当前结果，去掉完整input/previousExecutions递归；旧Host快照只留当前可见正文。进一步把已成功操作逐条记录改为状态计数，未决/失败证据保留。需实测双向字段大小而不以局部JSON代表整个模型请求。

新增方案：当前Host五秒恢复tick负责十分钟到期判断，使用execution当前输入/租约及持久progressReview时间，不另建OS计划任务。到期经原生持久会话只读handle读取真实文件、核验任务/执行身份与当前输入，保存轻量检查元数据并持久wake原Owner。无新记录只陈述未观察到日志进展，不断言停止或成功；缺日志明确标不可读。

Owner获得progress wake后必须调用task_execution_progress读取该execution当前原生记录的限量实际摘录，比较目标、真实动作/结果/错误及方向后才能提交本轮决定。原始摘要/digest和seq允许追溯，工具输出限制最新8条、每条640字符，完整日志不反复注入。是否继续、续原执行小目标、纠偏或申请人工，由Owner按内容和原授权判断，Host不以超时自动取消、重放或更换执行身份。

已排队进度wake不绕过人工等待/暂停；执行结果及未知效果仍按现有持久账。重启不重置十分钟时钟，同一检查幂等且不重复叫醒。新增持久元数据不增加表/schema。

巡检纠偏职责：统筹对照整体目标与受托小目标，只凭实际记录识别已验证且未变化的重复工作、不必要步骤或方向偏离；必要的新验证不算绕路。正常推进或证据不足则 wait，不按日志沉默或耗时认定卡死。有确证且目标/授权不变时，用已有 task_delegate 的原 executionId、feedback=true 和稳定 key 给一条包含证据、省略步骤与下一必要动作的简短建议。先用 task_execution_read 核对已有反馈；同一意见未消费或无新证据时不重复发送，不另派任务、不取消重建。沿既有 #208 持久接收及安全模型步骤准入机制传递；received 不表示已消费或业务完成。

本次只增强模型指令，不新增计时器、监督会话、日志结果复用或 Host 审计/判别规则。确定性模型适配器可验证等待、反馈、身份和去重链路，但不能证明生产模型实际识别绕路的准确性。

待消费反馈回读中，consumedAt、modelStepEnteredAt 和 sequence 尚无值时显式返回 null，保持原生工具的合法 JSON 输出；null 不表示已消费。该表示修复不改变持久投递或步骤准入语义。

验证：真实原生日志身份/版本/方向片段读取、无新事件/未结束调用/缺文件/限量；store持久时钟、唤醒幂等与旧输入拒绝；Owner必须读真实日志、重复查看不复制全历史；人工等待不被巡检绕过。部署须在原真实业务自然排空后通过双包Check。
