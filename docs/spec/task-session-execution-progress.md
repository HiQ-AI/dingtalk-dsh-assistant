# 执行会话真实进度巡检

用户要求：统筹与执行沟通上下文不能过大；每10分钟检查正在执行的会话真实进度、方向，不能把running状态当作执行证据。

已有修复：传递执行当前目标、身份/版本与当前结果，去掉完整input/previousExecutions递归；旧Host快照只留当前可见正文。进一步把已成功操作逐条记录改为状态计数，未决/失败证据保留。需实测双向字段大小而不以局部JSON代表整个模型请求。

新增方案：当前Host五秒恢复tick负责十分钟到期判断，使用execution当前输入/租约及持久progressReview时间，不另建OS计划任务。到期经原生持久会话只读handle读取真实文件、核验任务/执行身份与当前输入，保存轻量检查元数据并持久wake原Owner。无新记录只陈述未观察到日志进展，不断言停止或成功；缺日志明确标不可读。

Owner获得progress wake后必须调用task_execution_progress读取该execution当前原生记录的限量实际摘录，比较目标、真实动作/结果/错误及方向后才能提交本轮决定。原始摘要/digest和seq允许追溯，工具输出限制最新8条、每条640字符，完整日志不反复注入。是否继续、续原执行小目标、纠偏或申请人工，由Owner按内容和原授权判断，Host不以超时自动取消、重放或更换执行身份。

已排队进度wake不绕过人工等待/暂停；执行结果及未知效果仍按现有持久账。重启不重置十分钟时钟，同一检查幂等且不重复叫醒。新增持久元数据不增加表/schema。

验证：真实原生日志身份/版本/方向片段读取、无新事件/未结束调用/缺文件/限量；store持久时钟、唤醒幂等与旧输入拒绝；Owner必须读真实日志、重复查看不复制全历史；人工等待不被巡检绕过。部署须在原真实业务自然排空后通过双包Check。
