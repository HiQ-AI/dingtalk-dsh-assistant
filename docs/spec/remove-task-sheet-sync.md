# 移除任务表格同步

## 目标与当前实现

按 2026-10-13 的要求移除“任务表格同步”。当前设置卡片由 `client.js` 定义，经 `scripts/build-web-client.mjs` 生成发布 bundle；首次加载会请求同步状态。Resident 创建 `task-sheet-sync.js` 服务，注册状态、检查连接、保存配置、手动运行四个接口，并在启动及每 180 秒全量覆盖所选工作表。

完成标准：设置页不再显示同步卡片、不再请求同步状态；四个旧接口返回 404；Resident 不创建同步服务或定时器；已有 enabled 配置不能恢复同步。任务看板、常驻群、Agent 配置和 DWS 消息能力继续正常工作。

## 移除范围与数据边界

- 删除独立同步服务和专属单元测试、直接调用该服务的历史 live-sync 验收脚本。
- 删除 `resident.js` 的服务初始化、runtime 方法、启动调度和关闭钩子，以及 `http.js` 的四条路由。
- 删除 `store.js` 的同步 get/set 方法。保留 scheduler schema 中两个历史字段，并明确其仅用于旧数据读取；`check-resident-storage.mjs` 会拒绝字段被剥离，删除字段会阻断已有实例预检。保持 domain v9，不增加迁移或运行时清理路径。
- 保持 `storage-v8-schema.js` 迁移源快照不变。共享 DWS runner、任务进度投影和工作流不作改动。
- 删除前端卡片、草稿/反馈状态、连接检查和请求，重新生成发布 bundle；不调整其他视觉或交互。
- 更新 README、安装手册和部署说明，去除启用说明及同步验收步骤。历史 spec、验收记录保留为历史证据。
- 不清空或修改远端表格，也不修改当前运行实例的持久化数据。此轮交付到 PR，不包含合并、发布或本机部署。

## 验证与证据

1. HTTP 定向测试实际请求四个已移除接口，均为 404；相邻状态和配置接口仍正常。
2. 旧 enabled 配置 fixture 通过存储预检，更新其他设置后旧字段仍保留，无同步 get/set 方法；相关迁移回归通过。
3. 实跑 Resident 启动/关闭、Store、HTTP 和客户端定向测试。
4. 客户端 overview 测试证明不依赖已删除端点；独立 headless 浏览器加载真实 React 和发布 bundle，核对入口消失、初始加载/刷新及相邻配置保存、错误恢复、窄屏与键盘。API 使用隔离 fixture，不接触线上任务。
5. 搜索生效源码/脚本，确认无残留执行引用；构建 bundle，核对最终 diff。
