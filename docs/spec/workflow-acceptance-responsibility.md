# 逐项验收责任与领域合同

本轮基于 `retrospective.md`，实施起点 abe58e1。保留 Owner/Stage/Run、效果账和既有修复预算，不增加沙箱、网关、通用规则引擎或新的全案总审模型。

## 问题与目标

调查不足可被后续无关写入引用补齐，同时通用合同在混合流程跳过业务验收。生产身份/版本正确、文件真实和业务满足必须分别成立。消费者尚未声明支持的结果合同版本，requiredOutputs 仅是手工目录。

## 实施路径

1. 完成门禁按 Owner assessment 引用划分待验证的验收项，将当前权威 itemId/criterion 与证据交给负责领域验证。引用是责任提案，不能自身证明满足；每一项必须得到实际被引用领域的验证。
2. 调查只证明其明确 satisfied 的逐项结论；后续领域补齐不足时独立验证同一项。通用能力先验证实际效果，再仅针对其承担的验收项执行业务检查，不能因混合计划跳过，也不要求每个写入阶段证明全任务。
3. 验收结果绑定 task/requirement/plan、冻结定义、运行和产物引用；复用既有完成决定与清单持久化，不另建平行状态机。模型候选、代码接纳与投递回执各守边界。
4. 阶段消费者声明受支持的生产合同类型/版本；入口统一拒绝不支持交接。目录从实际 workflow owner/result contract 派生，删除手工 requiredOutputs 事实源。
5. 领域规范明确调查、工程、发布、通用操作的受理承诺、权威规则、合法结局和恢复责任。当前完成仍要求全部验收项满足；调查可以报告不足，但不得伪装整体完成。不凭本次改造新增泛化的部分成功终态。

## 证据计划

- 先保留原始混合误通过反例，再验证拒绝、有效后续领域补齐、不同阶段承担不同验收项、错项/陈旧证据拒绝。
- 服务入口验证 Owner 完成状态和清单持久化；类型/版本拒绝以及目录与实际定义一致。
- 运行受影响的定向测试、恢复测试及独立审阅；记录 matrix/round，文档和 PR 与本轮结果一致。
- 不将夹具模型的集成测试声称为真实模型语义质量或真实钉钉交付。
