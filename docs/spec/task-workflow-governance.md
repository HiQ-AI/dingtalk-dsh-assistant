# 任务流程一致性门禁

## 问题

任务流程提示词目前只注入叶子会话。叶子虽然能加载正确流程，但常驻主会话生成的 objective、acceptanceCriteria 和 stageTasks 可能自行扩大原始要求；计划与完成审阅又看不到已选流程正文和固定 Topic 原文，因此可能批准与流程冲突的计划。

## 目标

- 任务流程继续由插件配置维护，Runtime 不固化开发、UAT、生产等业务规则。
- 叶子计划声明当前流程组合、证据复用、不适用步骤和例外依据。
- 常驻主会话按需读取同一份已选流程，结合固定 Topic 原文审阅计划与完成结果。
- 只有原始消息明确支持的例外可以覆盖流程；主会话自行扩写的目标不能成为例外依据。
- 已选流程修订后只影响引用该流程的活动任务；保留历史检查点，但重新规划前不能推进或完成。

## 方案

`plan-confirmed` 增加 `workflowAssessment`，包含精确的流程引用、复用证据、不适用步骤和带 `basisMessageIds` 的例外。Host 校验流程引用等于 Task 当前组合，例外消息属于 Task 固定 Topic 原文。

常驻审阅请求只携带流程索引和有界原始消息，不直接注入全部流程正文。主会话通过 `group_task_prompt_get` 按 requestId 读取当前 Task 已选流程；未读完不能提交审阅。计划冲突使用结构化 `reject`，叶子收到纠偏后重新提交计划。

阶段推进和完成提交都要求最近一次已接受计划的流程引用仍等于 Task 当前组合。流程配置更新后，仅通知引用了已变化流程的活动叶子；叶子加载新修订后，旧计划自然失效，重新规划会保留此前已落盘的历史证据。

## 验证

- 已选流程但计划缺少 assessment、引用不一致或例外依据不属于固定 Topic 时拒绝。
- 主会话未读取所有已选流程时不能确认计划或完成结果。
- 审阅可拒绝冲突计划，拒绝后不能推进阶段，重新规划后可继续。
- 已选流程修订并重新加载后，旧计划不能推进或完成；未引用流程的任务不受影响。
- 用户原始消息明确要求额外 UAT 业务复验时，可由带来源消息的例外继续执行。
