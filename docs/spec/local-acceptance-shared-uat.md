# 本地业务验收与共享 UAT 数据

## 已确认要求

开发修改完成后，在本地启动当前候选代码，连接共享 UAT 数据库，按任务验收条件执行实际业务操作；取得预期与实际对比证据后，才允许提交对应 UAT 分支的 PR。

uat1～uat9 共用一套 UAT 数据库。任务必须明确选择一个 UAT 环境，该编号决定 feature/uatN-base 代码分支及后续部署目标，不决定数据库实例。不推导 uat1_db 等不存在的库，也不从共享数据库反推出应选分支。

## 流程与产物

1. 编写修改方案时列明任务验收条件、操作步骤、预期结果和关联需求；这些是待执行计划，不能标为已通过。
2. 构建检查候选代码，保存构建报告及候选身份。
3. 准备本地验收：使用当前候选的独立目录、空闲本地端口和受信共享 UAT 数据连接；记录候选、服务、环境与测试数据归属，凭据不进入工件。
4. 启动本地服务并确认本次进程、监听地址及就绪状态；后续业务请求必须命中本地候选服务，不能用已部署 UAT 服务的结果替代。
5. 逐条执行任务验收步骤；记录操作、预期、实际、通过情况和证据。就绪探针或构建成功不能替代业务验收。
6. 清理本次测试数据和服务进程，保存验收报告。只处理属于本任务的测试资源；不能清空共享库、改动无关业务数据或根据部署环境编号建库。
7. 核对报告完整且每个验收条件均通过、候选未改变、清理已确认，才允许提交代码并创建目标为 feature/uatN-base 的 PR。

## 生命周期约束

共享 UAT 数据不得被隐式视为隔离副本。验收用例优先使用本任务新建且可追踪的测试数据；跨进程或外部系统的副作用不能声称由数据库事务统一回滚。失败、取消及重启需要回读已产生的验收效果；不能盲目重发业务请求。缺连接、启动方式或可执行验收步骤时展示具体缺项，不能生成形式上的通过报告。

## 当前实现差距

当前 v10 仅执行预配置 acceptanceChecks 命令，没有本地服务生命周期编排、任务级业务操作计划、共享测试数据归属与清理回执。本文件为实施前方案；尚未新增上述能力或变更本地运行配置。历史已完成任务不自动补跑验收。

## 本轮实施切分

- SG14.1：冻结任务验收条件与 UAT 选择；v11 增加条件核对、验收计划、环境准备、本地执行与报告校验，历史 v1–v10 定义保持原样。
- SG14.2：新增有界本地执行器，固定 Host 命令及共享 UAT 凭据配置，运行过程使用现有外部效果账；领取/结果不明时只回读，不自动重放业务写入。独立测试数据命名与清理回读为提交必要条件。
- SG14.3：节点产出展示计划、目录、服务、业务预期/实际、清理结果；文档说明配置与未接入边界。服务启动、业务执行、清理在同一个受管执行节点中完成，避免跨节点遗留进程；阶段分别留耗时与回执。

新建 execution-local-acceptance.js 的理由：现有 execution-check-job.js 仅执行一次性构建命令，无法容纳长驻服务生命周期、共享数据清理与持久操作对账；旧文件的函数身份被历史工作流冻结，不能就地改写旧执行语义。
