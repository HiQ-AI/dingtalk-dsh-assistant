# 以模型原生结束状态为准

## 目标与依据

用户追加“这类判断是否可以去掉，优先保证流程正常”。本方案取代上一份 `message-model-capacity-contract.md` 中的容量配置覆盖提案；该提案未执行。相同真实 R 输入已经得到原生 stop 和完整 JSON，却因 usage 超出本地静态模型目录而被适配器改判容量错误。不能用扩大另一项静态数字解决这个判断错误。

## 实施

1. 在已安装 DSH 适配器对应发布源码中修复结束状态映射：正常 stop 保持成功，仅原生 error 路径识别真实容量错误；保留 length、abort、工具调用和空结果合同。独立 worktree 构建精确包，不热改已安装文件，不改模型和 settings。
2. 消息 Host 调用窗口统一为 180 秒，领取租约继续由同一窗口加提交余量计算。保存真实结束原因、错误码及 usage；明确容量失败不反复提交同一输入，旧租约失败不得改写新来源状态。
3. 看板复用现有 traceReason 展示系统责任说明，不新建状态模型、布局或设计系统。现有颜色、组件和交互保持一致。
4. 用同一真实输入及正式配置验证候选适配器，无容量 override。真实完整 IB 由正式重放后的 R 绑定产生，不用旧的小输入证明大输入可用。

## 验收与边界

先完成适配器原生 stop/error 回归及消息调用合同回归，再走受控停机、备份、精确安装和独立回读。以原七条消息的材料读取、关联、原命令承接、Task 发起、阶段条件和通知送达验收。测试或服务健康均不能替代业务完成；不执行生产 SQL。上游源码不向外部远程推送，除非另获授权。
