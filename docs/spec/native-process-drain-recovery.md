# 原生进程排空失败重试

原生工具排空失败时，保留该执行持有的进程 scope 和 handle，封闭新进程启动；失败的 `close()` Promise 不再永久缓存。错误记录保留失败阶段及有界 cause，动态执行账记录 `drainFailure` 并进入既有 recovery 流程。

同一 Host 的恢复先核对执行身份、输入版本及租约、原生会话归属、已结束轮次、收件箱和后台作业。在原生会话 maintenance 排他区内，只重试原 handle 的终止与排空核验；非终端进程必须由 `waitForExit()` 明确返回 `true` 证明管理范围已空。缺失能力、观察失败、返回 `false`、租约变化或仍有活动会话时继续阻塞。进程核验成功后仍需关闭文件 scope、flush 原会话并释放原生句柄。

恢复不调用业务工具或模型，不重写原工具回执、执行结果及 unknown 操作。物理排空证明按原租约保留至 `execution.drained` 成功入账，历史读取或账本提交短暂失败可重试。效果对账与业务续办继续沿用原有机制。

此修复不追溯补造旧进程证据。跨 Host 重启后若已记录排空失败但原 scope 不再可用，保持失败；不能凭 PID 消失、退出码或服务重启判定已排空。旧版本现场失败的底层 cause 未记录，仍需核对原生会话、作业与既有审计证据，不能保证维护重启后自动解除。

验证覆盖原 handle 重试、缺失能力、租约变化、并发恢复、读回/提交失败后重试及结果/unknown 记录保留。云端使用 Linux 原生 DSH `0.2.1-alpha.2` 的进程、会话和持久化服务，模型响应由测试脚本提供；不替代 Windows、现场 `0.2.1-rc.2` 或实际模型验证。
