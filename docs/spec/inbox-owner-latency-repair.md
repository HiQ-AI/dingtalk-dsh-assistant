# 消息接纳与归档任务诊断修复

## 目标与边界

2026-10-29，修复 #408/#409 分析暴露的 Host 接纳等待新 Owner、归档任务不可解释和协调工具无效纠正；基线为 origin/main `9dd585f0a5c6567f78313c4662c516f9c40c2964`。本文是实施前快照；唯一持续目标文件位于主检出 `docs/acceptance/inbox-latency-408-409/goal.md`，验收证据位于本分支同名 acceptance 桶，不建立第二份 goal。

不重放历史消息、不写正式数据库、不发送业务通知、不默认部署、不合并 main、不自动运行 CI。实验只使用隔离临时数据、原生 Node 测试和受控会话夹具。保留原任务/会话、来源授权、幂等、已成功效果及未知效果禁止重放的边界。

## 方案比较与单一路径

1. **只提前保存 inflight promise**：不足。它只约束等待对象，仍可能取消到新 entry，也不能保证新轮在材料准备前不启动，排除为单独修复。
2. **修改提交前先取消原任务**：不足。来源/版本/动作可能被后续提交拒绝，不能因此中止合法原任务；还存在取消后其他调度重新进入，排除。
3. **单任务接纳屏障并固定旧轮边界**：推荐。屏障在任务修改前建立，覆盖提交、旧轮取消排空、材料发布，所有 Owner/执行的准入均需尊重屏障，包括已越过同步入口的异步 claim。最后释放并显式调度，不等待新 Owner 业务整轮。
4. **仅固定旧 lease 的取消 API**：可避免误取消，但单独不能保证发布材料先于新轮入场；不作为另一套并行兼容机制。若既有机制已提供同等屏障，优先复用，避免新增通用调度框架。

推荐方案须由平台实验与独立审查核定。实现要使用最小的同任务排序，不能持有与旧轮排空互相等待的锁；失败不永久阻塞，不允许失败后未经准备就自动执行。重启恢复从持久任务、来源与收据重建材料，不依赖仅存于内存的屏障证明输入就绪。不同任务保持独立，普通 preserve 补充仍保留旧轮与反馈语义。

## 对外合同

### 任务查询与错误

- 目录默认只列本群未归档任务，不把全量归档注入提示词或活动缓存。
- 已有明确 taskId 引用允许按 ID 只读查询归档身份；先验证群归属，再返回本群归档任务的必要身份/状态与允许动作，不泄露跨群正文。
- 归档不是不存在；不得自动恢复归档任务或按用户未授权动作新建替代任务。明确标注归档不可原任务执行，可由模型依真实新目标选择动作或解释限制。
- 错误分类互斥：不存在 -> 跨群 -> 归档 -> 当前状态/版本；不因不存在额外报 not_completed，不放宽授权/来源/话题版本校验。

### 协调工具

- 参数按 JSON schema 和运行时同一合同严格验证；缺失/类型/空数组/重复/数量越界返回可修正的结构化 issues，不产生原生类型异常。
- 严格拒绝无定义的顶层字段；示例与真实 schema 一致，不以允许 reason 等方式掩盖协议错误。
- 来源覆盖失败返回精确 UTF-16 范围及原文片段，便于修正引用；继续拒绝遗漏、错配、越界及未授权来源。
- 优先复用现有 linkedTasks 和绑定引用候选，禁止用模糊关键词命中替代任务身份核验。空结果分页不得凭空重试 offset，提示需保留真实 hasMore/nextCall。

### 可观测性

- 在真实异步边界记录 Host 提交、旧轮排空、来源物化等子阶段；startedAt/completedAt 来自执行时钟，不用测试假时间冒充延迟改善。
- 子阶段与整体 Host 可能嵌套，展示/文档不直接相加。计时失败不变成业务操作重放，保持既有故障可见性。
- 不在缺底层信号时虚构 TTFT 或将全部墙钟标成模型推理。

## 实施边界

- implement：`packages/` 内直接相关源码；只走上述明确合同，不顺带改无关调度/提示词。
- tests：`test/` 独占写入，优先扩充现有相关测试；基线实验须先见失败/交错，再在修复后通过。
- platform：确定性交错脚本及专项实验记录；独立检查正在启动的 claim、旧轮慢取消、慢新轮和恢复边界。
- docs：README/相关运维说明及 `matrix.csv/round-N.md`；只据真实结果记录，失败保留、修复重跑新增轮次。
- lead：合同取舍、唯一 goal、证据独立核验和 PR；review 独立只读审查反例。

## 验收要求

1. 慢新 Owner 保持未完成时接纳已返回；确需旧轮排空时仍等待旧轮，旧效果不可并发重放。
2. 预先进入启动链的 claim、并发同任务输入、取消/重开、preserve 补充均按正确边界执行；其他任务不被屏障阻塞。
3. 重复请求、材料发布失败及关闭/重启恢复不丢输入、不重复业务效果、不依赖易失 hold。
4. 明确归档ID、本群正常任务、真正跨群和不存在分别准确反馈，不泄露跨群详情；无授权不产生动作。
5. taskIds 缺失/错误类型/空/重复/过量及路由额外字段、原文遗漏/多事项/引用错配均有直接断言。
6. 真实子阶段顺序与持续时间有证据；单次本地 gate 实验只证明消除等待依赖，不宣称等价线上148秒收益。
7. 仅运行相关当前测试和受影响的历史合同；不默认全量或CI，不将本地验证写成已部署。
