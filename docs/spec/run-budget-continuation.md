# Run 预算显式续行

## 问题与范围

Run 的领取预算跨 generation 累计。历史重复领取可能耗尽预算，即使当前候选及业务验收已成功，剩余提交和部署节点仍无法领取。本方案单独记录预算续行合同，因为阶段确认不应承担增额职责。

## 最小方案

新增受信本机 Web 命令 `POST /tasks/{taskId}/continue-budget`。调用者提交唯一 requestId、明确 continuationText 及当前任务投影中的 budgetContinuation 作为 budgetBinding；actor 由受信 Host 提供。请求不接受追加额度。

绑定 Task 控制状态及版本、要求版本、计划版本、阶段，以及 Run revision、generation、workflowDigest、预算等待节点、leaseEpoch 和原始预算计数。接纳及应用时检查当前身份，拒绝过期状态、未排空执行、待处理输入、未知效果和非唯一预算等待节点。

Host 按当前剩余节点数 × 3 计算有限追加额度，同 Run 最多一次。保留 claimCount、generation、已成功节点、候选树与验收凭证，不重新执行已完成业务验收。下一次领取使用未使用的 lease 身份，避免重放已缓存的预算失败回执。再次耗尽明确停止，不允许模型自动续费或以换代清零。

重复同一请求返回原回执；同 requestId 不同内容冲突。审计保留用户正文、受信 actor、绑定、前后预算与原因。预算许可不替代候选、构建、合并和部署原有门禁。

## 验证要求

覆盖严格 HTTP 字段、受信来源、绑定身份与版本、幂等、重复批准拒绝、未知效果拒绝、失效领取避重，以及已成功节点与业务验收不重复。只有实跑后才能报告通过；本方案不代表已经续行或部署。
