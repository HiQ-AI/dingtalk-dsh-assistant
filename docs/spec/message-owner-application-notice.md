# Owner 应用阻塞的告知责任

已接纳决定连续应用失败达到现有预算后，报告仍为 application_status=blocked。现有通知仅处理 applied 报告，用户只能看到过期结果。

复用报告账与现有 owner 通知路径，增加 owner:application_wait:<reportId> 阶段。正文仅告知系统问题导致尚未继续，无需重复提交已有材料，不转发尚未应用的决定摘要。事件身份固定在报告，不含失败次数或技术原因。

发送领取核验最新已接纳 turn、应用仍 blocked、Owner 仍 blocked、当前需求与控制版本一致及原有消息来源守卫。恢复 discard/applied 或版本变化使 prepared 失效；已发送未知效果只回读，不重发。普通已应用报告合同保持不变。

验证同一阻塞重复扫描唯一告知，未执行摘要不泄漏，恢复后未发失效，未知发送恢复后仍只对账。


## 群聊受话者与输入等待

S/R 必须先确认当前话语向助手提出请求或补充约束；群内第二人称不能自动指助手。S误拆后R可用既有no_action语义结束该事项，附当前事项原文sourceQuote。Host仅接受已持久成功R输出、无绑定/无命令的当前事项，保留审计并消除其未归属影响；其他仍未解析事项继续阻挡。明确交办、原需求方更正、停止执行等真实约束不能静默忽略。群聊人际追问不主动澄清。

Owner领取前原子核验消息输入屏障，有待处理输入时不启动模型。领取后到达新输入造成MESSAGE_INPUT_PENDING时释放为pending但不增加失败次数。沿现有恢复调度继续，不跳过新约束。

明确指向助手的Host事实必须贯穿S到R/I：投影replyObligation、完整agentNames和群职责。R不得覆盖required=true判为人际闲聊；协议验证在节点成功前有限纠正，账本再次拒绝静默消费。真实审核SQL案例用于回归，不能只验证闲聊安静。
