# 历史消息材料到执行合同闭环

## 已验证问题与反证

第22轮真实重放中，#114的S成功后调用附件读取器，因xlsx不受支持进入needs_attention；其相关输入继续阻挡111/113答复及115承接。历史文件消息文本不等于表格正文，R临时material也未保证进入IB。当前连续归属仍可沿115已建话题恢复，暂不引入另一套任务或关联模型；contextRevision守卫保留。

## 本轮整体方案

1. 复用现有DWS附件读取入口，增加xlsx结构化只读解析，保留工作表、行列位置、值、公式及缓存结果，不执行公式/宏/外链。原文件身份、同群来源、路径与完整性校验保留；不把不支持格式当文件缺失。
2. 统一材料含义：引用文件消息时沿其已证明附件读取真实正文，消息原文和附件正文都保留；失败返回可恢复系统材料等待。提供给answer的只读材料能力补齐参数合同，保证实际被注册。
3. 用已持久unit.contextNeeds及已解决材料请求贯穿R→IB→执行，规范化hN后引用同一材料账；模型不能静默丢弃已有必需材料。解析未完成时保留明确系统等待并通知，不伪造ready。
4. 正常恢复并发发起各run，沿现有FIFO模型slot背压和同run flight去重，避免等待一条完整R分页才推进下一条；不放宽版本、相关输入或生产阶段权限守卫。

## 整体验收

脱敏组合用例同时覆盖xlsx多sheet和Y列、文件消息引用、R→IB→真实派发材料、读取失败通知与恢复、连续114/115约束、旧policy与长队列。真实只读验证两份原工作簿可读取后再部署；部署后原消息恢复回读同Task/阶段合同/状态通知，不执行生产SQL或代替审批及发送人验证。
