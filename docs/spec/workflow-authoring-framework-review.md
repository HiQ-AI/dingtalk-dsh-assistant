1. 核对消息接纳、Task Owner / Plan / Stage、Run / Node、工件、效果账本和平台适配器的职责及真实扩展接口。
2. 审查定义冻结、输入映射、产出校验、授权、失败恢复、暂停取消、展示和升级边界；确认问题给出触发条件、代码依据、影响及修改方案。
3. 在 `packages/dingtalk-dsh-assistant/README.md` 编写框架级新流程建设手册，根 README 提供入口。现有 API 契约偏接口，运维文档偏具体平台，均不能代替面向流程建设者的完整步骤；使用包级 README 符合仓库开发者指南归档约定。

## 审查与验证

- 主审查负责接入路径、具体流程与手册，独立审查负责执行控制及恢复边界。
- 以当前源码为准；对问题主动寻找正常路径或既有检查作为反证。隔离反例只使用临时目录及一次性数据。
- 手册包含可执行的最小定义示例、接入清单、产物契约、验证清单和明确未提供的能力；核验代码位置和 Markdown 链接。
- 不把历史定向测试、PR 合并或本地部署推断为当前生产流程及钉钉入站已经验收。

## 完成判据

手册可指导建设者从需求与验收定义走到源码接入、隔离验收和发布回读；每项框架能力有源码依据，审查问题与未验证边界单独列明，文档经过独立审閱及本地校验。
