# Resident 别名与群职责一致性修复

## 问题与范围

配置别名包含当前登录人的姓名，群职责也明确要求处理，但内置协议的任务准入与回复节制两处仍要求因登录人姓名保持静默。现场 Topic 决策采用了该理由；这支持提示词冲突的判断，不等于完成真实模型因果对照。

## 方案

- 删除两处针对 DWS 登录人的特殊否定规则及只为提示词服务的状态和 setter。DWS bridge 的本人消息投递对账仍使用登录人信息。
- 群职责保留身份、负责范围和介入要求；配置别名供 Host 校验，职责正文不会自动注册新别名。不新增个人身份声明或新的配置项。
- 验证完整 Resident 提示词、动态别名更新、明确别名任务创建和图片补充续接同一任务；无别名和指向他人的反例继续拒绝。
- 现有现场职责已经包含正确的任务准入要求，无需修改。历史已接受决策不批量重放。

## 验收边界

本地测试与源码包部署分别验证。合成工具提交不能证明真实模型已自动选择相同动作；真实群聊消息收发未验证时明确说明。
