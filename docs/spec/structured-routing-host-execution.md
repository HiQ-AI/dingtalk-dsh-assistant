## 不明消息的路由处置（2026-11-05）

当前 Route 提示允许仅含理由的 deferred，持久化后 Host 没有问句可发，来源可能持续阻挡其他话题。比较：仅改提示不能阻止无问句提交；对所有待判加问句但不区分可发送身份和影响范围，仍会出现不能发送或阻挡无关话题；采用闭合分流，具备真实同群来源与作者、可发送问句及明确范围的来源可依据管理员分诊策略进入既有澄清链，新来源的其他不确定输入记录 Host 缺省策略并静默归职责外。策略准许发问不表示已确认业务交办，也不授予 Task 副作用权限；既有明确业务事项及已发生效果不得丢失，不能由程序猜交办、猜目标或编造问句。已有活跃单元且无法形成可发送问句时，结构化拒绝不完整提交，要求模型提供合法范围和问句或按原合同完整重分类及继承效果；不通过修改状态冒充完成。

新行为保留历史决定、成功回执和未分诊 pending 围栏；澄清范围仅可由模型显式选择本请求已曝光的 Topic 及版本，Host 在群锁内核对并持久化。陈旧版本、未读上下文、资源或持久化错误不能降级为职责外。已发送澄清的真实答复须按同群精确送达 ID 关联原来源及版本、epoch，保留原始引用事实。澄清须校验真实来源与作者、分诊策略或既有交办依据、候选审阅、版本及发送许可，不以接受发送代替送达。测试须覆盖分流、范围和安全围栏、引用回复回链、职责外静默及旧收据恢复，不调用真实消息或改正式账。

## 结构输出方案取舍

1. 当前框架 `@deepseek-ai/dsh-llm@0.2.1-alpha.2` 的已核GenerateOptions及AgentLoop组装没有原生responseFormat/JSON-schema入口；不自行绕框架调用网关或跨项目改SDK。
2. 同版也未发现toolChoice入口；仅留下一个工具不等于保证模型必调用、只调用一次，还可能切断必要补读。
3. 本轮复用现有Route/Decision JSON Schema提交作为结构化意图载体。业务动作与通知始终由Host规范校验、接纳、执行及恢复；模型不编排创建/唤醒/取消/发送/回读等底层步骤。未提交或不合法结果按程序错误处理，不冒充成功。

按真实请求用途核对工具清单：普通路由不应因共用role就暴露title/summary提交；必要来源、附件、话题和任务检索保留。Task Owner正常执行工具不在本轮退役范围。已选择请求内显式新Topic定义消除共同排除审计的机械重复；精确报错单独实施只能减少修错位置，不能消除此重复；仅加强提示仍保留已证失败模式，不采用。

## 请求内新Topic定义合同

- 顶部显式 `newTopics=[{newTopicKey,title,candidateComparisons:[{topicId,revision,reason}]}]`；每个Unit的target显式引用key并保留自己的归属reason和relationship。定义只共用新Topic标题及相对候选的排除审计，不共用来源、授权、关系或effectOwner。
- 引用表示模型明确断言该共同比较也适用于此Unit；排除依据不同应给不同定义，或走原完整显式结构，Host不能从首条推断。不同key即使同标题也不合并。
- Host校验key唯一、定义非空且被使用、引用存在、冲突/混用无歧义、候选已曝光且版本匹配；有候选时比较不能为空。只按显式引用展开title/comparisons，继续原逐target审计、来源覆盖、未汇总读取、锁内版本校验及原子持久化。
- 模型指引提供一条清晰的推荐结构；原完整提交兼容限于明确旧合同路径，不能把历史冻结函数改成新逻辑。已成功receipt重试保持原账，不重判、不重放。
- 必验反例为相似但不同事项、同key冲突、未声明/未用key、候选漂移/未见候选、跨请求短引用、每Unit缺reason、并发变化与幂等恢复；不能只验证Host复制结果等于fixture。

## 两级模型配置合同

- 复用现有原生模型选择器及配置保存/预检，不新增provider、凭据或另一套选择器。
