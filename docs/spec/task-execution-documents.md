# 每轮执行文档

用户要求每个执行会话具有执行文档，统筹查看文档即可；后续补充每轮文档必须保留，不能被新一轮覆盖。R4 样本中已有团队等待前置用了 12 次模型调用/108 秒，多层读取成员职责和结果是可观察成本。本扩展用明确文档入口改善交接，不承诺普遍耗时降低。

## 唯一路径

每个 Task 工作区的 `outputs/<executionId>/round-<inputVersion>.md` 为该成员该轮执行文档。Host 从现有委派输入、版本/状态、阶段报告和结果账生成，执行成员通过原阶段报告维护计划、进展、证据和阻塞；不让模型同时维护与账本冲突的第二套状态。阶段报告增加可选简短 plan，首次执行形成计划，必要变化再更新；同一 inputVersion 的后续报告未带 plan 时保留原计划，续办新版本不继承旧计划为当前计划。

文档包含任务/成员身份、需求与控制版本、输入版本、本轮职责与交接、计划、当前状态及报告时活动、阶段成果/证据、最终结果/产物/限制；摘要标明自述和验证边界。文档不新增授权。

当前轮可更新，轮次变化前完成旧轮快照，此后新轮写新路径；旧文档保持字节不变。恢复时只更新当前版本文档，既有历史不能从新输入重建覆盖。受信身份决定路径，拒绝目录/文件链接，原子替换当前轮文档；失败如实暴露，不用陈旧文件冒充最新。完整原账仍是恢复依据。

统筹输入给出各成员当前文档路径与版本；日常进度检查和结果交接优先读取文档。原始日志不是日常必读门槛；文档缺证据、版本矛盾、技术失败或未知效果才按需要读取原始产物/日志。历史文档按旧 inputVersion 定位，不在每轮完整回灌。

## 验证

用实际文件读回证明职责/计划/进展/结果一致；阶段更新只修改当前轮，续办和恢复后旧轮 SHA256 不变；新轮不沿用旧成果当当前事实；路径越界/链接拒绝、并发文档刷新和当前版本一致性均验证。原生执行实际报告计划与进度，统筹实际读取文档后完成判断。真实模型隔离评估使用同一生产文档生成器，保留旧 R4 轨迹并重新验证文档路径及分工成本。
