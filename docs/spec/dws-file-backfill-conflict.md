# 文件消息回补冲突修复方案

目标：恢复正式实例 DWS 回补和健康状态，避免同一文件卡片的展示差异被误判为编辑；不改业务账、不跳过消息、不伪造来源版本。

只读核验：2026-09-30 正式首群当天五条历史消息中一条冲突；同 ID、sourceVersion=1、发送者相同，已保存正文119字符、历史正文87字符，差异仅为 DWS 事件附加的32字符下载提示。历史 resourceRefs 独立给出一个 fileId 及同名文件。原始证据在本次 docs/tmp/dws-backfill-conflict，不提交业务内容。

排除：发送者映射相同；不是正文任意编辑（只差工具提示）；不是缺失来源版本（双方均版本1）。真实编辑继续拒绝，不能以这些排除结论概括其他消息。

复用 coordination-resources.js 的 sameDwsFileProjection 严格校验；在工作流同版本重复分支只接受发送者相同且同名同fileId的单个资源展示差异，保留原持久正文和版本。双向重叠均须通过校验。DWS bridge 保留显式 fileId，并从完整文件卡片文本恢复事件的fileId/name；其余文本不补假资源。

验证：桥接归一化、同版本双向文件卡片重复、换发送者/文件名/ID/提示正文拒绝、已有协调资源边界回归。正式部署按 resident-review-local-deployment runbook，先Check，维护/排空/封存/备份/安装/历史回读/恢复派发后独立检查双端口、健康、回补及延迟存活。无schema或运行库手工修复。
