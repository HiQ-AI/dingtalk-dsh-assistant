# 任务卡片状态与归档展示

## 目标与边界

任务卡片应先让用户看清任务结果、通知状态和等待原因，再按需查看技术详情与归档文件。只修改 Observer 的展示，不改变 Task、Outbox 或归档契约。

## 现状与设计

- 完成结果和通知状态原为两行，信息重复且缺少关系；改为同一行，分别保留业务结果和通知投递状态。多个通知意图按状态计数，避免遗漏。
- `topic_request_retry_exhausted` 等内部错误码原样露出；改为“协调请求重试耗尽，等待系统恢复”，原始错误码保留在可展开的“查看技术原因”中。其他等待原因仍原样展示。
- 工作目录和每份文档原样展开，长路径撑高卡片；改为默认收起的“清理状态 · 目录数 · 文档数”。展开后按目录展示登记/借用/分支、完整目录路径和文档文件名；完整来源路径保留在 title，归档目的地仍显示。
- 同一路径的重复登记合并展示，文档按 source 去重。仅影响视图，不修改持久数据。

## 视觉与组件归属

沿用 Observer 的 DSH 主题色、状态语义、卡片边界和紧凑排版。业务结果用较强字重，通知状态次级，等待原因用现有警示色。归档明细使用原生 `details/summary`，依赖现有 `:focus-visible` 规则，避免新建平行交互组件。桌面保持四列看板，窄屏单列；连续路径允许折行。

## 验证

用完整 Observer 源码和真实 React 在 Edge Chromium 浏览器中渲染隔离数据，覆盖重复工作目录、8 份文档、长路径、重试耗尽等待、四种结果与通知状态、键盘和 390px 窄屏。隔离夹具阻止所有写请求；不代表真实 DSH profile 集成或群通知验收。
