# M2 候选与受控交付实施快照

2026-09-23。在 M1 独立入口上继续实现，旧 resident 不接入。本轮先落实工程链的候选身份和交付适配器，完整群消息替换属于 M4。

## 契约

- 候选是完整 Git tree 与基线 commit 的固定身份。仅处理显式受管仓库；生成 tree 不生成临时 commit，原工作区/用户索引保持不动。拒绝子模块、符号链接、未声明外部依赖和执行型 Git 过滤器等不能证明的场景。
- 验证器读取固定 tree 的字节，不读取正在变化的工作目录。受信代码验证函数与版本绑定；不支持任意 shell 测试，不能据此宣称操作系统隔离或项目完整测试完成。
- 验证回执绑定候选、检查 ID/版本、结果与日志引用。只有精确候选全部要求的验证成功，交付适配器才可准备动作。
- 写动作经 M1 效果账取得一次发送资格，重复/未知只回读。提交使用已验证 tree；更新 ref 使用 Git 原生旧值条件；push 绑定精确新旧远端 SHA 和精确 ref，独立读回。
- 真实 Git hook 或远端能力不能满足语义时拒绝准入，不能绕过 hook 后称正常项目交付。首批验证使用无 hook、无凭据的临时受管仓库与本地 bare remote。
- 同步工程工作流、真实 PR 平台适配器、隔离 shell、渠道通知和业务耗时仍按后续验收推进；不得以本批局部验证宣布 M2 全部完成。

## 验证

覆盖冻结后原目录改变、删除/未跟踪内容、验证失败不创建 commit、候选身份不符、过期代际/取消/输入屏障、真实 ref 条件冲突、push 前远端变化和效果结果丢失。所有测试只写临时合成仓库；产物与日志留在既有 docs 归档范围，现场材料不公开。
