# 群消息协调延迟与任务发起修复

## 目标与基线

2026-09-22 的现场只读排查发现：消息 #1336 已保存正文和图片并完成话题归类，约 13 分钟后仍无已接受决策或 Task。前一个无关话题在约四分钟内连续九次提交 `actions: []`、`reply`、`reason`，全部因严格联合类型不接受混合字段而失败；错误输出仅有 `decision: Invalid input`。同群完整轮次串行等待和全群未路由门禁共同放大延迟。

可验证目标：消除 schema 误导；错误定位到具体字段；有竞争时请求在原生工具结果落稳后的步骤边界公平让出；已路由事项能及时准备决策；Task 创建保留输入版本、撤销、重复提交和效果归属校验。修复不保证真实模型/网络固定秒级响应。

## 实施与取舍

1. 保留持久决策数据形状，将等价 Zod 分支收敛为可由原生工具 oneOf 表达的回复/不回复分支。真实运行仍严格校验，不删除调用者的多余字段。
2. 展开联合类型的叶子问题，返回字段路径及分支信息，使一次反馈足以修正，不只输出 Invalid input。
3. 复用协调队列与原生 pre-step gate，在竞争时限定执行量子，等待工具结果落稳再调度下一请求。让出不等于失败，不能消耗协议重试预算；不取消正在执行的副作用。
4. 将决策准备与路由完整性门禁分离。提交处仍必须证明输入和版本有效；未归类消息不能按关键词猜成无关。进一步门禁调整须以原子提交反例为准，禁止简单删除全群保护来换取速度。
5. 复用现有流程验收目录及目标记录，追加本轮证据；更新 README、流程契约及运维说明。

## 验证与交付

- 原生工具 validator 与 Zod：三条合法决策路径、混合 reply/reason、所有动作分支。
- 工具错误反馈：嵌套字段、联合分支、无效参数零副作用。
- 原生 AgentLoop：长轮次竞争公平性、工具 post-execute 未完成不切换、同群峰值并发为一、让出不消耗协议重试。
- #1336 等价输入：图片与事项已归类，有无关新输入时能够推进；同话题撤销/编辑、旧版本及重复提交仍拒绝或幂等。
- 运行针对性测试、全量测试、构建；PR 独立回查。真实群消息、合并部署与本地隔离验证分别记录，不用本地结果声称现场已恢复。

## 风险

公平切片会增加少量续行消息；必须复用原 Session 和工具结果。调度和监控生命周期不同步可能导致重复唤醒、错误耗尽、关闭挂起，需原生生命周期验收。未归类消息的相关性未知，不能以性能为由提前执行潜在已撤销任务。
