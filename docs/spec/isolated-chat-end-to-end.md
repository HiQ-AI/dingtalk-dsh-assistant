# 独立群真实消息验收

用户明确要求新建独立测试群，完成真实消息端到端验证并修复期间发现的问题。只邀请当前授权账号；不增加其他同事、不改业务群职责、不发送业务动作。

现状：DWS 原账号重新授权后 health=ok、监听ready、补读ok。既有真实测试消息被正确解析为 answer，但 Host 要求 arguments.objective，拒绝“仅回复已收到”的对话请求。需先读 answer 全链合同，避免只删除校验而在后续流程仍失败或误建业务任务。

实施：主代理建群、核对工作流群封存/激活与受控部署；子任务梳理并修复普通回复合同及定向正反例。复用原通知效果账、来源引用、去重与回读；不增加第二套发送路径或伪造输入。独立群以原生受信入口/离线维护流程接入，保留既有群和任务。

验收：真实发送→渠道回读输入→正式入站→拆分/关联/判断→受信接纳→真实回复→渠道独立回读；普通回复无误建任务，补读/重启不重复。自发输入若由历史补读接收，明确记录路径，不当作外部成员实时推送。失败轮保留，修复重跑使用新编号。

部署预检新增范围：自身通知的入站回声在通知回读前已启动 S，随后 quarantine 仅封存消息未终结模型节点，导致维护永远不能排空。修复封存的节点收尾及迟到提交保护；旧数据仅在真实已回读通知、同群同消息、无业务命令等证明下经原生命令收尾。恢复旧实例需复用正式维护与完整 Resident dispose 见证，取得 owner 锁、备份后执行；不放宽一般部署排空门禁。
