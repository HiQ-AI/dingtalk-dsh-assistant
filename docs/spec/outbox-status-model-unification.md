# 发信箱状态模型统一

现行通知账的 prepared/starting/unknown/delivered/failed 是发送状态依据；旧 status、preflight/postflight 和撤回字段只用于无 notificationState 的历史适配或独立事实展示。当前 UI 混合这几类信息，存在重复 delivered 分支、撤回结果覆盖送达及历史自动重试承诺。

方案：保留既有 outboxDelivery 纯函数作为唯一界面映射，内部将现行判定和只读历史适配分开。输出发送状态、原因、替代指针和撤回结果。现行 failed 的退休原因映射已停止，具体待核验放原因；不认识的状态保持待核对，不回退待发送。历史仅 status=sent 且无回读证据的记录显示已发送未核验。真实撤回不抹除原送达事实，群历史撤回不承诺执行或重试。

界面复用表格与 SelectMenu：发送状态、原因、替代关系和撤回结果分别展示和筛选，多个筛选按交集工作。不写业务账、不触发消息发送/撤回、不改调度或私聊撤回。保留发送时间列及提示关闭行为。更新 DESIGN、README、当前部署 runbook 和既有验收目录。

测试覆盖现行各状态与冲突旧字段、legacy 各原因、未知结果保留、送达+替代+撤回并存、原因/关系/撤回组合筛选、历史不承诺重试。按现有原生静止实例脚本 Check 后部署，只变 Observer，Assistant 复用当前受信包；读回摘要、新 PID、健康及64条通知事实一致性。Chrome 检查原样本、未知记录、四维筛选及刷新/窄屏，更新现有 PR204。
