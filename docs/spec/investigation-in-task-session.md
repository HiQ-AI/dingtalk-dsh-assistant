# 调查并入任务执行会话

## 结论与范围

普通调查与分析不应继续作为独立 `task-investigation` 工作流。由同一个任务执行会话直接读资料、查询、形成候选、纠正工具错误并推进任务。保留 Host 的资源权限、插件真人审批、外部操作记录和最终验收。这里是分析方案，本轮没有实施架构改造。

## 当前实现证据

- `packages/dingtalk-dsh-assistant/task-owner-session.js:125-127` 的工具 guard 仅允许提交决定、读事件和读工件。Owner 虽然被提示承担持续执行责任，却不能直接使用查询能力。
- `packages/dingtalk-dsh-assistant/workflow-service.js:585` 构建查询工具；`:672` 将工具提供给阶段执行会话；`:1421` 创建 Owner。工具与持续负责人分离，是独立调查阶段仍存在的实际原因。
- `packages/dingtalk-dsh-assistant/agent-work.js:157-181` 将调查拆成 agent 的 investigate 和 code 的 accept-result；前者 validateOutput、admitOutput，以及后者 execute 都调用结果验证。
- 同文件 `createInvestigationCompletionPolicy` 与领域合同、Task 最终验收进一步判断证据是否足以满足目标。这些入口有不同职责，不能直接断言所有检查都完全相同，但结构上产生了多次交接、版本绑定和结果提交机会。
- `agent-work.js:351` 当前定义已经限制调查只核对影响下一步候选的事实。这缓解了过度调查，但没有消除会话与交接结构。

当前最主要的问题不是调查不能自主执行，而是负责人只能读别人提交的结果；要继续查证或纠错，仍需安排/修复阶段并通过阶段合同。把责任写进提示词，不能补足实际工具能力。

## 三种选择

| 选择 | 判断 | 原因 |
|---|---|---|
| 保持独立调查工作流，继续优化提示和合同 | 不推荐 | 改措辞仍保留交接、重复提交和冻结版本的负担；适合真正需要独立交付的专项报告，不适合每个任务的普通读取 |
| 删除全部编排和 Host 限制，仅让一个会话自由执行 | 不推荐 | 模型的自主性不能代替真人批准、目标绑定和未知外部效果对账；SQL 超时后重做可能重复执行 |
| 一个任务执行会话自主调查，Host 提供薄的受管操作 | 推荐 | 常规读取与推理不中断；只有审批、外部写入、恢复对账和最终完成需要确定的持久化边界 |

## 推荐的唯一执行路径

群协调会话归并需求 → 一个任务执行会话读资料/只读查询/形成候选 → 调用需要的受管操作 → 同会话读回结果并验收 → 一次最终群回复。

任务会话直接获得现有登记查询工具。Host 按 taskId、当前需求版本和资源授权生成 scope，保存原始工具结果及身份，不让模型构造成功回执。查询失败返回原始原因和可纠正信息，会话可缩小查询、分页或换已授权资源，普通失败不升级为人工阻塞。

不把每次搜索、读文件或查询编成阶段，也不强制为过程输出 findings/criterionReviews 或调查阶段完成声明。需要对外交付报告时，报告是任务成果，而不是所有任务都必须经过的通用调查流。

任务会话可以维护和调整简短计划；计划不是可执行的硬性流水线。Host 保留一个任务目标与执行日志，不再同时维护调查完成、领域完成与任务完成三个业务判定。

数据库写入沿插件真人审批：生成精确 SQL 与目标 → 提交 Bytebase 工单 → 插件私聊审批 → 批准绑定本次 SQL/目标 → 执行并对账 → 生产只读回查。Bytebase 平台 SKIPPED 不作为插件批准失败。SQL 改动重新审批，未知执行结果先查既有工单，不重建或重执行。

最终验收只有一个业务判断入口；证据身份、权限、批准先于执行和实际完成状态属于 Host 的客观检查，不重复做多轮语义验收。过程不发群进度；保留必要业务提问、插件私聊审批和最终结果。

## 实施与验证边界

直接替换当前任务执行路径，而非为同类任务增加开关或兼容分支。增加任务会话的实际查询能力，移除通用调查工作流的调度、交接与重复语义完成校验；复用当前查询工具、工件存储、插件审批及外部操作账。实现变更前列出各现有检查的责任，保留客观安全检查，删除重复业务判断。

验证至少覆盖：纯调查任务不生成 investigation Run；SQL 只查询必要事实；查询权限错误由会话纠正；插件批准与 SQL 绑定；审批拒绝后的修改重审；执行超时对账不重做；会话/进程恢复接续原任务；证据不足不能假完成；最终群回复唯一且无中间进度。

反证与盲点：分离会话可以给专项调查隔离上下文，并方便独立报告复用；当前证据不足以证明所有领域工作流都应删除。因此本建议只合并通用调查与分析，不把开发发布、生产 SQL 等外部操作降为无约束工具。性能和错误率改善需要上述实际测试，不能仅据结构简化宣称已经验证。
