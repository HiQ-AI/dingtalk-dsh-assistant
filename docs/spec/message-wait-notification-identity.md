# 等待通知的逻辑来源身份

问题：同一来源的技术错误原因变化和受控重放版本变化，会创建不同通知身份并发送相同业务等待正文。已送达历史必须保留，不能全群按正文去重。

复用现有通知账：查询增加 sourceKey 精确过滤；通知准备前读取该来源全部版本中已送达或结果未知的通知，比较最近一次公开事实。相同等待 phase、公开正文及必要材料资源集合且期间无新的承接、结果或其他公开进展，不再准备通知。已有未发送或已失效通知不作为跨版本送达证据；既有本版本通知身份和领取时版本守卫不变。新的公开事实形成新的等待周期。不同来源永远独立，用户澄清、承接和业务结果不参与等待抑制。

验证：同版本内部原因变化、跨版本重放、未知发送均不重发；未发送旧通知失效后新版本仍发；不同来源不互相遮蔽；新进展之后再次等待应告知。无运行库变更，无真实消息发送。

真正修改来源正文视为新请求；仅重放保持原文不产生新等待。新等待周期将最近公开通知身份追加到既有eventKey，避免先前同状态身份阻止新的合理告知。
