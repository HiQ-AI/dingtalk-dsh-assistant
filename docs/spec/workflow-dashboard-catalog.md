# 运行看板工作流目录

日期：2026-10-13。基于 origin/main 44646d2；用户确认在运行看板新增「工作流」入口，集中查看流程及维护问题。

## 现状与边界

运行看板已有群消息、话题、任务看板、人工介入、归档任务和告警；任务详情呈现一次执行。插件设置页的 WorkflowCatalog 消费 GET /state/workflows/catalog，展示由代码注册的只读流程目录。工程流程随任务与仓库冻结定义，目录不具备统一静态节点。当前没有通用定义编辑/启停/发布 API。

独立 Tab 比继续藏在设置页更适合日常查看；任务看板二级入口不便发现从未运行的流程。新增入口承载定义目录，实例重试和恢复保留原上下文。本轮不改变定义、运行数据、权限或部署实例。

## 实现约定

- 在任务看板后增加「工作流」，沿现有导航与宿主主题；列表 → 详情，桌面左右、窄屏上下，内容自然增长。
- 复用目录 API，进入页面后读取；保留选中项，刷新失败保留已读目录并标注未刷新，初始失败/空态/未启用有独立说明和重试。请求在页面退出时失效，慢响应不得覆盖新页面；请求去重防止自动刷新饥饿。
- 列表显示名称、用途、版本与可用状态；详情显示用途、按顺序的节点及执行职责、准入仓库、不可用原因。未知版本不猜测；无节点不冒充零步骤已就绪。
- 配置与维护区域给出按模式区分的维护说明和仓库现有文档入口，不提供没有后端语义的按钮。工程流程明确具体步骤在任务详情查看。
- 相关任务依据 workflowId 或 plan.stages 的真实流程绑定筛选，支持当前与归档任务；跳到原任务详情，返回工作流目录时恢复选中项及焦点。
- 设置页移除重复目录展示，保留文字指路；仍读取目录元数据中的群归属以保持旧版叶子任务配置的显隐与保存合同，不改用更重的完整运行状态接口，构建同步生成客户端。
- 复用 nodeTitle、tableStatusTag、Button、emptyState、请求函数及任务详情；不新增生产模块、依赖、接口。新建特性验收脚本因为目录与跨页面异步行为没有现成覆盖。

## UI 所有权

设计/行为约定继续维护在 docs/manual/observer-design.md。导航由 pages/navigationTabStyle 管理；目录选择沿 TopicBrowser 的语义 button 和 aria-pressed；详情沿共享字号、状态与空态；外部文档用原生链接且新窗口明确标注；页面滚动沿 ObserverContent，窄屏布局用现有 observerCss。无表单、选择器、弹窗或写操作。
