# 话题复用与失败响应恢复

现场六个话题对应两个业务任务；每个任务的两个额外话题均为Web任务补充，由submitWebTaskInput仅在new-task时启用reuseTopics产生，群消息路由本次没有重复建题。修复须沿任务现有有效topicRefs复用主话题，版本、幂等、待处理决策和多话题效果归属保持明确。禁止用标题相似自动合并。

原生MCP get_schema的两次DATABASE_NOT_FOUND真实响应已写入日志且原回合结束，绑定只读调查也结束。但工具桥接没有effectClass，Host按unknown永久门禁。现有网页失败和旧停止恢复各有专用路径；新增操作人显式确认“原生错误已结束且绑定调查已完成”的人工答复路径，复用精确摘要、身份、正常turn/end及排空校验，保留failed/partialEffectsPossible及完整原账。调查结论不是无效果证明，禁止标noEffect或自动重放。模型自动对账不能使用此路径；必须由受信Web人工回复提供原操作摘要，全部操作及人工答复在一个事务中提交，失败整批回滚。成功响应、取消、缺响应、活跃执行、未绑定/未完成调查均拒绝。

先交付Host修复解除当前技术阻塞，再验证Web续办复用、独立事项拆分、多事项路由、旧来源及版本漂移；历史收口只能通过正式原子受控命令，不直接编辑运行数据库，不再次执行原业务动作。部署沿task-session-clean-start runbook，精确双包校验及原会话读回。
