# 任务卡片执行会话时长

仅在任务卡片的执行会话列表展示最新一轮执行耗时，左图标、中间名称、右时间值保持单行；名称超长以 ellipsis 省略并提供完整 tooltip，320px 也不换行；原状态文字位置仅显示时间数值，不显示状态文字或“时长”前缀；状态含义由原图标的 tooltip/无障碍标签保留。复用 observer 的 fmtDuration，不增加明细请求，不修改其他页面或执行机制。

## 最新一轮口径

一轮从 Host 的 `execution.claim` 开始，以当前 `leaseEpoch` 标识；首次 `execution.result`（成功或失败）或 `execution.drained` 关闭本轮。取消请求尚未排空仍属于本轮。结果后的排空等待不计入。续办和 provider 重试只有下一次 claim 才开始新一轮；排队期间保留最近已执行轮次的固定耗时，首次尚未 claim 显示“—”。

`executionSessions.latestRoundTiming` 是只读投影 `{ startedAt, endedAt, active }`，缺失时为 null。从既有 `timeline.segments` 中取当前 `leaseEpoch` 的第一段开始与最后一段结束。阶段活动切换可以切分连续区段，但不开始新轮次；普通日志、反馈、`updatedAt`、进度检查时间不作为计时边界。运行中显示当前时间减该轮开始；关闭后显示真实结束减开始，固定不再增长。不叠加旧轮次或跨轮排队间隔。

当前轮区段必须连续、时间有效且顺序正常；未知区段、重启中断未记录终点、缺少开始/结束等情况返回 null，显示“—”，tooltip/无障碍标签解释“最新一轮耗时未记录：该轮尚未开始或缺少可靠的起止时间。”不以恢复、刷新或新反馈时间补造终点。旧历史缺失不妨碍之后新 claim 的完整轮次独立展示。不回填、不新增持久化字段。

浏览器只在有效活动区间时每秒刷新，结束、缺失或卸载时清理计时器。验证使用隔离 SQLite、组件合成环境及本地 HTTP，不代表真实宿主或钉钉部署验证。

## 原累计数据保持不变

动态账本的 runTiming 为 Host 管理的元数据：recorded 表示累计记录完整，elapsedMs 为已结束运行区间之和，startedAt 为当前领取执行的起点或 null。新分派初始化为已记录的 0；execution.claim 开始区间，首次 execution.result 或 execution.drained 关闭区间。结果后的排空等待不计；无结果排空后重新排队不计。取消请求尚未排空的时间仍属于运行区间。

execution.continue 和 provider 重试复用原执行/会话，保留累计值；下一次 claim 才恢复计时。终态固定，重复结果/排空不会重复累计。既有 JSON 记录保持不变，无数据库 schema 迁移或历史回填。

历史无 runTiming 不补造累计值，即使后续续办也不假装拥有完整累计值。Host 重启时，存在未结束计时区间则将 recorded 置 false 并清除 startedAt；恢复确认排空时不以恢复时间冒充实际终点。已收到结果且区间已关闭的记录保持固定。时钟倒退导致负区间也标为未记录。

该累计字段与其他总耗时指标不改动，任务卡片不再使用它显示耗时。
