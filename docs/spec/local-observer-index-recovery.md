# 本地看板分页索引恢复

## 目标与根因
用户明确本地看板报OBSERVER_PAGINATION_MIGRATION_REQUIRED，要求恢复真实本地可用性。进程、端口、入站正常不等于看板可用；前次部署最新main漏做其显式索引迁移。本轮必须真实分页API与浏览器任务列表/详情均可用，原任务和外部效果保持。

## 范围与实现
复用现有migrate-observer-pagination.mjs及原生索引安装函数，增加明确indexes-only维护模式，默认只读Check零写；Apply仅SQLite单事务补观察索引、索引回填和触发器，不物理归档历史、不改任务/执行/来源/效果正文、不升归档schema、不做整库快检/哈希/备份复制。用户本地部署不需历史副本；索引可重建且失败事务回滚，因此该模式不沿用物理归档的历史备份前提，原默认迁移模式保持原合同。

必须在当前Host/执行自然排空并经原生生命周期停机后执行。动态库校验已初始化身份及精确owner CAS，owner进程必须不存在（允许已证明死亡的stale owner，不清理该字段）；resident消息库保留其owner-lock独占校验。Check只读schema/owner元数据；Apply按现有installer回填所需元数据，多项索引可能分别读取同一源表，不声称单遍，不把这些扫描塞回正常启动或GET。明确报告目标表、持续时间与状态，保留失败与正式阶段记录。

先核实所有看板调用涉及的动态库、消息/trace库及旧执行页索引，不只补一个错误后停在下一个错误。实际查询缺哪个正式索引，使用对应现有安装函数，不新造UI fallback或缓存成功状态。原c5发布已排空、原bc只读核验/Owner尚未排空，等待自然结束，不暂停、不重放。

## 验证
独立临时已初始化库Check零写、Apply索引完整、源正文及版本不变、幂等、活owner/错误owner/不合格schema拒绝、失败回滚。现场迁移前后记录原任务/执行/通知关键身份；正式停机→仅索引迁移→同包/配置启动，核对双端口及入站。独立HTTP任务分页/详情及浏览器实际看板无连接错误，核对原任务可见；不以health成功代替页面验收。
