# 调查阶段完成职责修正

## 现象与证据

真实渠道文档用例的调查节点已经读取配置并形成结论，却提交 blocked：它把后续保存 Markdown 的整体交付条件当成本节点必须完成的条件。原生会话工具记录与失败工件留在本地验收目录。现有受信文档写入能力存在，不能将缺少调查会话写工具解释为系统缺少保存能力。

## 根因与修改

共享执行底座应共用工具、身份及证据校验，但消息问答与任务阶段的完成职责不同。当前共用提示要求完成整个用户目标，调查节点因此无法向后续交付阶段交接。

- 保持共同的调查方法、证据规则及错误分类。
- 消息执行按本次问答目标判断完成；调查节点按调查取证及结论交付判断完成。原始目标和约束继续完整提供，不删掉保存、修复或提测要求。
- 调查产物明确后续工作尚未执行；实际缺少调查所需资料、权限或工具时仍等待或受阻。禁止无证据地将失败改为成功。
- Owner 负责按整体目标安排已授权文档、工程及交付阶段；最终仍须独立核验全部验收项。
- 调查定义升级至 v5，禁止把新提示套到旧运行定义。部署前处置本次失败的 v4 测试任务并核对活动引用，保留失败产物；新一轮真实输入重验。不添加无限期双轨执行。

## 验收

1. 消息问答和调查节点具有不同的完成合同；工具与证据校验保持一致。
2. 调查资料缺失/越权仍拒绝，未完成文档时整体任务不能完成。
3. 真实文档用例先完成调查，再通过受信写入阶段保存文件；独立读回内容、摘要及回复路径。不得仅以节点成功或回复文字判定落盘。
4. 后续工程交接仍携带原目标、结论及未执行项；真实工程/UAT全链继续单独验收。

## 同链路材料引用边界

隔离真实输入暴露第二处边界错误：意图模型把项目、仓库、状态的逻辑查询资源 ID 填入启动材料字段，接纳器据此等待永远不会出现的消息材料。修复在 Host 意图输入提供 executionMaterialRefs，枚举本事项来源、附件、已解析材料及有来源的话题引用；I/IB 提交前逐事项校验 requiredExecutionMaterials 为其子集。错误引用通过既有节点失败与预算重试反馈模型，不静默删除，不伪造材料就绪，也不触发新的材料等待。后续查询目标仍保留在 objective/acceptanceCriteria，由执行 Agent 取得证据。

额外验证：无效资源引用可纠正后只执行一次；真实附件未就绪仍等待；同批事项不能借用另一事项引用；补取长材料及约束保持原样。
