# 执行会话停止依据核验

## 目标与当前证据

原Owner有全部43工具与danger-full-access，但恢复后仅探测连通性及账号字段，随后把隔离验证准备交维护，capability block被正常接纳（Owner revision30/lease12、lastFailure=null）。任务仅要求核验，不授权修复部署；此约束不等于禁止原会话准备局部隔离核验。当前只有完成验收，wait/block仅结构校验。

## 候选与反证

1. 再次恢复并加入一次性提示：前轮已做但仍回到相同等待，排除作为完整修复。
2. 一律禁止等待或放宽业务授权：真实凭据/用户决策/未知效果仍可能需要等待，排除。
3. 复用现有无工具语义核验机制审查停止依据，原会话自己执行和修正：采用。不以有shell推断一切可做，不以缺现成夹具推断无能力。

## 最小实施

在普通Owner的等待条件（含确实缺少业务信息）接纳前核验，暂停成果评估不增加执行义务。输入当前需求来源、当前阶段、真实模型工具目录与权限、Host验证的引用证据及最近原生调用。判定器只判断停止理由，不执行、不授业务权限、不成为任务责任人。外部阻碍真实则接纳；可继续或依据不足则保存诊断并同轮反馈给Owner。结构、证据身份、版本CAS和有限纠错仍保留。

原执行指令明确：验证方案、隔离夹具和运行环境准备属于自己的任务；不能把已有账号清单或某专用工具输出当能力全集。若真实环境不可修改，应自行寻找授权范围内隔离验证，报告其对当前运行版本证明的边界；不可伪称UAT实测。

## 验证及交付

测试正常外部拒绝、待对账、无根据外包、伪造引用、取消及同会话纠正；部署按既有runbook，恢复原Task后核验实际原生调用及新的停止/完成依据。维护侧不准备该业务夹具、不提供业务成功回执。

用户补充：确实无法自行取得的信息由原Owner提出，经常驻系统唯一群通知通道转达；常驻会话将回复关联回原Task。公开正文只写正在做的具体业务动作和具体缺项，不暴露责任方/恢复条件等内部模板。账号应说明系统环境与审核角色等必要识别信息，不索取公开凭据。
