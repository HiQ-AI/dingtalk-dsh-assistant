# 旧任务流程目录迁入代码编排

日期：2026-09-24。本文是本轮修改前的实现方案快照，以当前 v9 配置和 PR #121 源码为准。

## 现状与目标

现场 `taskPrompts` 有 10 条启用记录，仍由旧叶子读取文字、自行选用和报告阶段。新入口只注册 `task-analysis` 与 `task-engineering`，消息准入也只允许这两种。因而“已部署工作流 v2”不能解释为十类业务流程均已迁移。历史 Task 留在原引擎只读或按原精确包恢复；本轮只改变新任务准入，不迁移旧 checkpoint，不重放任何外部动作。

目标是让每个新流程有固定 ID/版本/定义摘要、有限节点、明确输入和输出、节点恢复与授权边界。消息只选择已注册流程；Host 复核来源、权限、目标资源和所需材料。需求补充使用同 Task 新 generation，失效节点停止并重新核算外部效果。

## 现场流程与准入映射

| 原配置 | 新代码流程 | 必须独立核验的结果 | 外部效果边界 |
| --- | --- | --- | --- |
| 排查 | investigation | 现状、原因、反证、证据与未知项 | 只读 |
| 方案 | planning | 范围、选择、风险、验收清单 | 只读 |
| PR 评审 | pr-review | 精确 PR/head、问题定位、既有与新增区分 | 只读；合并是另一个受控动作 |
| 开发 | engineering | 候选、实跑、提交/推送/PR 回读 | 仅已配置仓库和 Git/PR 适配器 |
| UAT 交付 | uat-delivery | 提交→构建→制品→运行版本→可访问 | 需 UAT 目标和平台适配器 |
| 生产发布 | production-release | 审批范围→精确版本→构建→运行版本→访问 | 需生产审批及发布适配器 |
| 数据查询导出 | data-query | 查询来源、字段/精度、导出文件回读 | 纯材料答疑只读；真实 DB/导出需专门连接器 |
| 数据变更 | data-change | SQL/目标冻结→演练→工单→精确审批→执行→独立回查 | 需 Bytebase/DB 适配器；不得直接放行 SQL |
| 复盘 | retrospective | 事实、原因、教训、未验证项 | 只读 |
| UAT 同提交重构建 | uat-rebuild | 精确 SHA、等价构建查重、制品及运行版本 | 需构建/部署适配器和版本保护 |

10 类是可组合的处理方式，不能把一次消息强行压成单一类型。首版组合由代码显式拆成有依赖的任务/节点；消息模型不得凭文字自行跳过前置节点。当前通用工程流没有已有开放 PR 续作语义，不能把旧开发流程全部宣称覆盖。

## 实施顺序与节点合同

1. 先把 5 类只读流程做成发布版定义。统一 `prepare-materials → 领域判断 → validate-result`，各类输出 schema、证据 ID、长度和风险字段独立。PR/数据库事实必须由材料提供；缺来源时产出缺口，不可编造已回读。
2. 消息 schema、模型可见目录、准入和创建使用同一流程注册表。未注册 ID 与缺目标资源均在派发前拒绝。定义摘要与历史版本在启动时严格比对。
3. 开发保留工程既有受管 Git 链，但补任务范围与既有分支/PR 续作适配器后才能覆盖旧流程完整语义；当前只准入已登记仓库的首次交付。
4. UAT、生产、数据变更和重构建分别注册受控连接器。每个副作用都要准备对象（目标环境、精确 SHA/SQL hash、资源版本、幂等键）、权限依据、`execute`、独立 `reconcile`。unknown 保留占用，不自动重发。平台读取失败不能解释为无冲突。
5. 生产动作采用同一请求的 Web/IM 平级审批，首次终态有效；批准绑定精确效果身份。工单自动 DONE 不代表生产 Task 已执行。只读发布状态核验不得触发发布。

## 本轮验证判据

- 对十类逐项记录：定义是否注册、是否可被消息选中、输入输出合同、恢复/修订、外部效果回读以及已知缺口；`NOT_RUN` 不填 `PASS`。
- 五类只读用每类正例、缺证据和注入材料反例验证，真实模型测试与替身测试分开。
- 工程流跑固定候选真实检查及 Git/PR 回读，不以原有通用分析证明。
- UAT/生产/数据分别在隔离目标跑已授权操作与 unknown/重复/变更反例；未配置真实适配器时明确拒绝，不能在入口宣传为可执行。
- 全仓测试、本地原生启动和消息→任务链验证；真实群发送、生产 SQL、正式发布各需独立授权和回读。
