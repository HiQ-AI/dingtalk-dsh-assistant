# 群消息受控重处理

今天的旧消息在澄清或取上下文节点等待，原消息 ID 再次入站只会返回幂等回执。为逐条重处理，新增本机 Web 操作入口；每次只接受一个旧 `runId`。

入口仅允许工作流群、已认证的本机 Web 操作者和尚无业务命令的 `pending`、`waiting` 或 `needs_attention` 消息。账本事务将旧运行和待答请求标为被重处理取代，保留旧节点、通知及发送回执，再为同一来源创建递增版本的新运行。已有业务命令时直接拒绝，避免重复建任务、补充或取消。

新运行重新构建上下文，读取当前群消息与任务历史。批量补处理由调用方按原消息时间串行发起，每条回读状态、命令与发信箱后再进入下一条。旧通知若已送达，仍以原渠道回执和撤回记录为准；新运行是否需要发信由节点决定。

验证包括：无命令等待消息可重处理、旧请求被封存、新版本成为唯一当前来源、已有业务命令拒绝、跨身份拒绝、按时间串行处理及本地渠道回读。
