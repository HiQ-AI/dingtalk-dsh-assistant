# 执行资源互斥及公共验证合同

## 目标与范围

修复 2026-10-20 六任务复盘发现的资源键只接收未执行问题，完成当前运行插件的验证；同步修复个人公共健康检查脚本及现有开发/UAT skill。保留所有现存任务、通知、未知效果及工作区改动，不重放历史业务任务或发布 Dataset。

## 当前事实

基于 origin/main f2191f2。execution.dispatch 保存 resourceKeys，continue 不更新；claim 不取得锁；native operation 使用空资源键。现有 dynamic_resource_locks 只保护显式 operation。资源冲突目前不能阻止六个原执行同时进入 UAT。健康脚本成功正常返回 JSON、失败 exit 1，同进程调用残留 LASTEXITCODE。

## 插件设计

- 资源键约束整段受委派 execution；共享 UAT 的集成至部署读回应由同一次持锁执行覆盖。无需新增锁服务或 schema。
- 新派发归一化资源键；续办省略时保留，显式提供时更新，但只有原执行和原效果真正排空才允许改变资源集合。等待状态不是失败，也不申请人工。
- 在 SQLite 同一原子事务中一次获得全部资源，再 claim 执行。资源由 execution 独立身份持有；不同资源允许并行，避免部分持锁等待形成环。
- execution.result 不释放；只有 execution 已 drained 且没有未结原生操作才释放。后台 job、unknown、取消和宿主重启不能绕过此条件。资源占有可跨恢复保留；正常失败且效果排空后释放。
- 使用既有 operation 生命周期保留在途效果。执行声明资源时不允许操作再扩大资源集合；声明内的 operation 与执行共享持有者，不与自己冲突。未声明资源的旧 operation 模式保持。
- 续办只读对账必须能够在原持锁执行中处理未知效果；保持原键，不允许借只读恢复解除或扩大锁。未知效果不能自动改为成功。
- execution.get/list 和任务上下文暴露真实资源状态、阻塞持有者；queued/received 不能当作持锁。调度跳过资源等待者，不占执行槽、不忙轮询，释放后推动原排队执行。
- 运行态接入使用当前任务恢复和正式部署 runbook；不直接改真实 SQLite。安装前必须排空旧活动，避免给没有锁记录的旧执行伪造互斥承诺。

## 公共脚本与 skill

- 健康脚本提供一致进程退出状态，明确调用示例；成功/失败均保留结构化 JSON，模拟脏退出码、失败以及独立进程调用验证。
- 现有 business-development 增加验证期间候选固定与目标夹具适配；uat-pr 将 UNKNOWN 有界复读和明确拒绝落实到可调用检查入口；uat-deployment 说明资源状态及健康合同。不新增宽泛 skill。
- 公共脚本/技能在当前实际安装路径修改，记录哈希与语法/行为验证；Git 代码在本 worktree 提交并开 PR。真实消息与业务发布不属于验证范围。

## 验证

资源互斥覆盖：同键不并行、异键并行、多键原子获取、续办保留/更新、重复键去重、冲突不忙循环、等待者释放后提升、取消排空、后台 job/unknown 保留、对账释放、重启持锁恢复、范围扩大拒绝、资源可观察性。运行相关定向 ledger/service 测试，不无条件全仓测试。

公共工具覆盖 HTTP UP/失败/非 JSON/重定向，以及遗留非零 LASTEXITCODE。skill 验证包含结构、引用以及针对候选变化、未知合并状态、资源等待与已有上传四类行为场景，不只检查词语出现。
