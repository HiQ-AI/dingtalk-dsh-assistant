## 合同

1. 静默与归类分开。此类消息不调用模型、不回复、不创建任务；Host 只读解析本群引用消息 ID，沿本群已送达通知的来源消息 ID 找到已持久绑定的话题。
2. 只接受唯一话题。直接引用、新工作流通知和旧 Outbox 来源都须以渠道消息 ID、群 ID、来源键核对；多条有效路径出现不同话题时不绑定。未经回读的通知或跨群记录不参与。
3. 绑定是同库幂等命令：原运行必须为该进展格式、引用 ID 必须属于原入站快照、证据来源必须在同群已绑定目标话题。只给现有话题添加来源关联，不新增话题或业务事实；重复绑定同一身份无副作用，冲突拒绝。
4. 新消息在静默结案时原子绑定；修复前已静默结案的消息仅作一次有界确定性对账。未解析出唯一话题时保持静默，收信箱显示待归类，不能显示已路由。话题详情读取绑定来源，因此进展消息可在对应话题中回看。
5. 验证：现场引用链、重复入站/重启、两话题冲突、跨群/伪造证据、无引用、无模型/通知/任务副作用，且状态与话题详情一致。部署后只对可证明的旧消息回填，独立回读当前消息和话题。

## 同轮补充：旧排查事项再次报告问题

现场消息 `msglrqv1gZoH6YJAWCMyjda8w==` 已关联已完成的旧排查任务“排查评审意见草稿再次进入未回显问题”，I 节点却只产出 `fact`；旧任务只读门禁拒绝该命令，运行仍以 `settled` 结束，未提问也未发起任务。对此类明确指向常驻助手、同一现象再次出现、旧任务目标明确“仅授权排查分析”且本条未明确交办修复的消息，须发一次“是否继续实施修复”的澄清。肯定答复解除该消息的新任务准入，但必须以新工作流任务身份派发，不复活或改写旧任务；否定答复不授权创建。普通话题事实仍可记录在本地话题，旧任务依旧只读。

历史上已被拒绝的纯 `fact` 命令没有业务效果；只有其全部通知仍为 `prepared`、从未尝试发送时，才允许重处理并在同一事务封存旧通知。已领取、发送未知或已送达的通知禁止走这条例外。通知领取还须检查来源运行未被新版本取代，防止旧准备记录在重启时迟到发出。
